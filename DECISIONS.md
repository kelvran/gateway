# Decisions

Lightweight, continuous, one-line-per-decision log. Read before starting new work; append a new line after work is implemented, not during planning. **Never edit past entries** — supersede with a new dated line that says what changed and why.

This is **not** a replacement for `docs/decisions/` (ADRs). ADRs are for the rare, foundational, hard-to-reverse calls, written in full MADR format with context/drivers/alternatives/consequences. This file is the terse, continuous layer for everything smaller — if a decision here recurs or turns out to matter more than expected, promote it to a full ADR rather than letting it grow in place.

Format: `[YYYY-MM-DD] decision — one-sentence why (see docs/decisions/000N-*.md if promoted to a full ADR)`

- `[2026-09-02]` One monorepo, two deployables (`gateway` Go binary with embedded Cache; `evals` separate Python service) — forced by the Go/Python runtime boundary, repo stays unified to keep the shared `api/` contract from drifting. See `docs/decisions/0001-monorepo-two-deployables.md`.
- `[2026-09-02]` Cache is an internal Go package inside `gateway`, not a standalone service — its natural architecture duplicates 60-70% of Gateway, and every comparable product surveyed embeds it. Extraction stays possible via a pre-designed interface + dormant gRPC adapters if a real trigger fires. See `docs/decisions/0002-cache-embedded-in-gateway.md`.
- `[2026-09-02]` Go for Gateway/Cache, Python for Evals, connected only by a versioned `api/` contract — never a shared library across the language boundary. See `docs/decisions/0003-go-python-split.md`.
- `[2026-09-02]` Project named **Kelvran** — confirmed clean across GitHub/npm/PyPI/crates.io and no domain conflict found across two independent naming research rounds, the second seeded explicitly with the system's differentiators (agent-run-level governance, risk-gated caching, adversarial skeptic-panel evals). Manual USPTO TESS/WHOIS clearance still required before public registration — tracked as an open action, not yet done.
- `[2026-09-02]` Changelog structure is one `.md` file per released version, in a `changelog/` folder per deployable (`gateway/changelog/`, `evals/changelog/`) — an explicit override of the more common single-running-file convention, chosen deliberately over the research's default recommendation.
- `[2026-09-02]` Branch strategy is `main`-only (no `develop`/`release` integration branch) — reversible with zero migration cost at solo-maintainer stage, so it doesn't clear the ADR bar; deliberately does not adopt the `develop→release→main` model used elsewhere in the builder's own toolchain, since that would contradict `CONTRIBUTING.md`'s existing "branch from main" convention. See `docs/development/BRANCHES.md`.
- `[2026-09-02]` Contract testing for the `api/` boundary is `buf breaking` in CI plus a golden-fixture round-trip test, not a full Pact Broker — an additive, reversible tooling choice, not architecture. Chaos-fault-injection tooling is Toxiproxy, revisited only if the production target becomes Kubernetes. See `docs/testing/TESTING.md`.
- `[2026-09-02]` Initial code scaffolding landed for both deployables (real, tested, non-stubbed pieces: OpenAI/Anthropic adapters, `cache.Cache` L1 exact-match, in-memory rate limiting, single static-key auth, non-streaming dataplane pipeline for `gateway`; `EvalCase` model, Wilson CI, deterministic + LLM-judge scorers, Docker-sandboxed rollout wrapper, CLI for `evals`) — resolves the RFC's version-pin open question: `gateway/go.mod` targets Go 1.25 language level (1.26.5 toolchain verified locally; Docker build uses `golang:1.25-alpine`); `evals/pyproject.toml` targets `>=3.12` (uv resolved a 3.13.12 venv locally against the 3.14.7 system interpreter — both satisfy the constraint, no forcing needed). Full scope boundary (what's real vs. intentionally stubbed): `docs/rfcs/2026-09-02-initial-code-scaffolding.md`. Streaming, distributed rate limiting, Decimal cost accounting, MCP/A2A, and guardrails remain explicitly deferred, not silently dropped.
- `[2026-09-02]` Branch strategy reopened at the founder's request (against a suggested `main`(release)+`develop`(integration)+feature-via-`develop` model) and reaffirmed as trunk-based (`main`-only) after a dedicated end-to-end research pass — six of seven real OSS infra projects surveyed (Kubernetes, Envoy, PostgreSQL, Redis, Kong, LiteLLM) run zero permanent `develop` branches, and the one partial counter-example (LiteLLM) showed live branch drift matching the theoretical critique of that model. Two refinements added on top of the prior `[2026-09-02]` branch-strategy line above: the `release/<deployable>-vX.Y` escape valve now follows an explicit Release-Flow/Branch-for-Release discipline (cherry-pick forward only, never merged back), and the single revisit trigger is split into an organizational trigger (unchanged from ADR-0001) and a new support-policy trigger (concurrently supporting multiple live major versions in production). See `docs/development/BRANCHES.md`.
- `[2026-09-02]` Test suite deepened for both deployables before moving to the next feature (streaming): real end-to-end HTTP integration tests, wire-format regression/golden fixtures for both real adapters, `go test -fuzz` on the cache-key fabricator and the YAML config parser (both clean, no crashing input found), `go test -bench` baselines for cache/rate-limiter, CLI integration tests, Hypothesis property-based regression tests on the Wilson-interval math, and a golden fixture pinning the LLM-judge prompt. Lint tooling wired for real: `golangci-lint` v2 (`gateway/.golangci.yml`) and `ruff` (`evals/pyproject.toml`'s `[tool.ruff]`) — an additive, reversible tooling choice, not architecture. `Makefile` targets (`setup`/`lint`/`test`/`verify`) are now real, matching a new `.github/workflows/ci.yml`. No production behavior changed — only lint-driven explicit-error-discard idiom fixes; no functional bugs found in either deployable.
- `[2026-09-02]` Real SSE streaming shipped for `gateway`'s OpenAI and Anthropic adapters (`docs/rfcs/2026-09-02-streaming-support.md`), with two design choices beyond the RFC's own type definitions: (1) a provider unable to stream (Gemini/Bedrock/openaicompat) fails with a typed `ErrStreamingNotSupported` rather than silently degrading to a buffered response — a streaming request either streams or fails visibly, never a surprise shape-change; (2) the fallback-to-next-deployment rule that already existed for the buffered path now applies identically to streaming, gated on a `firstChunkSent` flag — no fallback is attempted once any byte has reached the client, to avoid duplicated/corrupted content. Found and fixed one real bug during this pass (not a design decision, but load-bearing enough to record): the Anthropic decoder was reading `message_delta` only for `usage`, silently discarding `stop_reason`, which would have made every streamed Anthropic response's cached/reconstructed `FinishReason` come back empty.
