1"""Data model for evaluation cases. 

2 

3Matches evals/ARCHITECTURE.md's Data Model sketch: 

4 

5 EvalCase { id, revision, task_spec, reference | null, 

6 tier: golden|regression|drift_sample, tags } 

7 

8`EvalCase` instances are immutable once created — a stable `id` at a given 

9`revision` never changes shape out from under a dataset. Advancing a case to 

10a new revision is done via `with_revision()`, which returns a brand-new 

11instance rather than mutating the original in place, per the org-wide 

12immutability convention. 

13"""

26class EvalCase(BaseModel): 

27 """A single, versioned evaluation case. 

28 

29 `tier` is set at dataset-registration time (see THREAT_MODEL.md's Evals 

30 "Spoofing" row: a rollout must never be able to claim its own tier). 

31 

32 `flaky` (added 2026-09-07, per docs/rfcs/2026-09-07-evals-cigate- 

33 refinements.md) is a durable, case-level declaration — set once by a 

34 human curator, exactly like `tier`/`tags` — that this case is known to 

35 be non-deterministic/environmentally noisy. It lives here, not on 

36 `Run`, because *why* a case is flaky doesn't change trial-to-trial; a 

37 `Run`-level flag would mean re-declaring it on every single execution 

38 for no real benefit. Mirrors DeepEval's own `LLMTestCase(flaky=True)` 

39 precedent: a dedicated, type-checked field, deliberately not encoded 

40 as a magic string inside `tags` (which stays an open-ended, 

41 operator-chosen label — overloading it with one reserved value that 

42 silently changes gate behavior would be a real footgun). Denormalized 

43 onto every `Score` this case produces (see `Score.flaky`'s own 

44 docstring) so `evals.cli.report_cmd` can exclude it from a 

45 `--fail-under`/`--category-fail-under` gate computation while still 

46 printing its real result — it still runs, it's still visible, it just 

47 never trips a gate on a known-noisy signal. 

48 """ 

49 

50 model_config = ConfigDict(frozen=True) 

51 

52 id: str 

53 revision: int 

54 task_spec: dict[str, Any] 

55 reference: str | None = None 

56 tier: EvalTier 

57 tags: list[str] = Field(default_factory=list) 

58 flaky: bool = False

60 def with_revision(self, revision: int) -> EvalCase: 

61 """Return a new `EvalCase` at `revision`, leaving `self` untouched. 

62 

63 Never mutates `self` — revisions are immutable once created. 

64 """ 

65 return self.model_copy(update={"revision": revision})

71class Run(BaseModel): 

72 """The result of executing one `EvalCase` through the Rollout Scheduler. 

73 

74 A deliberately narrowed v1 slice of ARCHITECTURE.md's full `Run` sketch, 

75 per docs/rfcs/2026-09-04-evals-rollout-scheduler.md — every field below 

76 is either real today or an honest "not measured" `None`, never a 

77 fabricated placeholder: 

78 

79 - `cost_usd` defaults to `None`, not `0.0`: `run_in_sandbox()` runs a 

80 Docker command, not a billed LLM call, so "measured as zero" would be 

81 false. `None` means "not applicable to this harness yet." 

82 - `harness_config` carries only `{image, command, timeout_s}` — the 

83 literal sandbox invocation — not the full `scaffold_version`/ 

84 `tool_budget`/`retry_policy`/`step_budget`/`sandbox_tier` set the 

85 architecture sketch describes for a future pluggable multi-step agent 

86 harness that doesn't exist yet. 

87 - There is no `Trace`/`Span` field, not even an empty placeholder — 

88 `api/otel`'s transport is still undecided, so a stub field here would 

89 be dead code with no consumer. 

90 - `status="skipped"` (per docs/rfcs/2026-09-04-evals-rollout-cost- 

91 mitigation.md) means this trial was never attempted at all — a group 

92 of repeated trials already reached an early-stopping decision. Never 

93 read a `"skipped"` `Run` as "verified healthy"; it carries no signal 

94 either way, the same "None means not applicable, never a stand-in 

95 for a real measurement" convention `cost_usd` already establishes. 

96 - `cache_key`/`from_cache`/`cache_source_run_id` are also additive, per 

97 the same RFC: `cache_key` is computed for every `Run` regardless of 

98 whether caching is active (cheap, and lets a *later* `--use-cache` 

99 invocation hit against `Run`s produced by an invocation that didn't 

100 ask for caching); `from_cache=True` only on a genuine cache hit 

101 (`status` is always `"completed"` in that case — an `error`/ 

102 `timed_out` prior `Run` can never source a hit); `cache_source_run_id` 

103 points at the real, originally-executed `Run` a hit reused — never a 

104 chain of reuse-of-reuse. 

105 """

167class Score(BaseModel): 

168 """The result of one scorer's judgment on one `EvalCase`'s output. 

169 

170 A deliberately narrowed v1 slice of ARCHITECTURE.md's `Score` sketch, 

171 per docs/rfcs/2026-09-04-evals-score-model.md: 

172 

173 - `run_id` is `None`, not a fabricated `EvalCase.id`, when no real 

174 `Run` exists behind the scored output (`evals run`'s fixture-baked 

175 `task_spec.output` case never touches the Rollout Scheduler) — 

176 mirrors `Run.cost_usd`'s own "`None` means not applicable, never a 

177 fabricated stand-in" convention. `eval_case_id`/`eval_case_revision` 

178 are the universal join key both `evals run` and `evals rollout` can 

179 always honestly supply, regardless of whether a `Run` exists. 

180 - `scorer_type` is narrowed to `deterministic`/`llm_judge`/ 

181 `llm_judge_panel` — the `Literal` was widened interface-only on 

182 2026-09-07 (per docs/rfcs/2026-09-07-evals-judge-panel-interface.md, 

183 before any scorer constructed a `Score` with the panel value) and 

184 the panel itself became real on 2026-09-08 (per docs/rfcs/2026-09- 

185 08-evals-judge-panel-reducer.md — `evals.cli`'s `--llm-judge-panel` 

186 flag now constructs real `llm_judge_panel` Scores via 

187 `evals.judge.llm_judge.judge()` called with more than one 

188 `call_model`). Deliberately named to match Inspect AI's 

189 `multi_scorer()` naming, not ARCHITECTURE.md's original sketch 

190 spelling (`skeptic_panel`) — see the interface RFC's Design section 

191 for why. `human` (also in the original sketch) stays dropped, still 

192 `v2`-scoped per `PRD.md`. 

193 - `rubric_axis` is `None` for a holistic verdict (the default), or the 

194 configured axis name (e.g. `"correctness"`, `"safety"`) when 

195 `evals.cli`'s `--judge-axes` requested one real `judge()` call per 

196 axis instead of one call covering all of them — per docs/rfcs/2026- 

197 09-05-evals-multi-axis-judging.md. Always `None` for a 

198 `deterministic` score, which has no concept of a rubric axis. 

199 - `cost_usd` is `Decimal("0")` (not `None`) for a `deterministic` score 

200 — that scorer makes categorically zero external calls, by 

201 construction (`exact_match`/`regex_match` are pure string/regex 

202 comparisons), so zero is an exact, certain fact, not an estimate. 

203 This is a deliberate divergence from `Run.cost_usd`'s "`None` = not 

204 measured, possibly non-zero" convention: the two situations aren't 

205 analogous. For `llm_judge`, `cost_usd` is the real, computed cost of 

206 that one Anthropic call (`evals.judge.providers.JudgeCallCost`), or 

207 `None` if the pinned judge model has no price-table entry — 

208 genuinely unmeasured, unlike the deterministic case. 

209 - `cost_usd` is `Decimal`, not `float` — report --scores sums it 

210 across every `Score` in a group (per docs/rfcs/2026-09-04-evals- 

211 score-model.md's own named revisit trigger: "the moment evals gets a 

212 suite-level cost aggregation... Decimal should be adopted 

213 immediately"). Price-table constants in `providers.py` are built 

214 from strings (`Decimal("1.00")`), never float literals, to avoid 

215 reintroducing the exact imprecision Decimal exists to prevent. 

216 - `score_cache_key`/`from_cache` are additive, per docs/rfcs/2026-09-05 

217 -evals-score-cache.md, mirroring `Run.cache_key`/`Run.from_cache`'s 

218 own exact precedent: `score_cache_key` is computed for every real 

219 `llm_judge` score regardless of whether `--use-score-cache` is 

220 active (cheap, and lets a *later* cached invocation hit against 

221 `Score`s an earlier, non-caching invocation produced) — always 

222 `None` for a `deterministic` score, since that scorer is already 

223 free and instant, with nothing worth caching. `from_cache=True` only 

224 on a genuine cache hit, in which case `cost_usd` is the exact, 

225 certain `Decimal("0")` (no new API call was made) — the same 

226 "exact fact, not an estimate" reasoning already applied to a 

227 `deterministic` score's `cost_usd` above, not a new convention. 

228 Unlike `Run`, there is no `cache_source_score_id` — `Score` has no 

229 `id` field of its own for a hit to point back at. 

230 - `tier`/`tags`/`flaky` (added 2026-09-07, per docs/rfcs/2026-09-07- 

231 evals-cigate-refinements.md) are denormalized, verbatim copies of 

232 the originating `EvalCase`'s own fields of the same name, captured 

233 at the exact moment `run_cmd`/`rollout_cmd` construct this `Score` 

234 — the same "compute once, at write time, regardless of whether a 

235 later feature needs it yet" convention `Run.cache_key`/`Score. 

236 score_cache_key` already established, chosen over having 

237 `evals.cli.report_cmd` join back to a `--suite` file at report 

238 time (which would let a `--scores` file outlive or diverge from 

239 the suite it was scored against, a real staleness risk this 

240 convention avoids). `tier` is `EvalTier | None`, not a bare 

241 `EvalTier` — `None` for a `Score` built before this field existed 

242 (an old JSONL line still validates, resolving to `None` via this 

243 declared default) or, in principle, any future scoring path with 

244 no real `EvalCase` behind it; never a guessed tier. `tags` defaults 

245 to `[]`, `flaky` to `False` — both `EvalCase`'s own defaults, 

246 reproduced exactly. `evals.cli.report_cmd`'s `--tier` and 

247 `--category-fail-under` read `tier`/`tags` here; its flaky- 

248 exclusion logic reads `flaky` here — never the originating 

249 `EvalCase` directly, which `report_cmd` never loads. 

250 - `panel_votes`/`quorum_reached` (added 2026-09-08, per docs/rfcs/2026- 

251 09-08-evals-judge-panel-reducer.md) are real, populated fields only 

252 for `scorer_type="llm_judge_panel"` — `None` for every other 

253 scorer_type, the same "`None` = not applicable" convention already 

254 used throughout this class (see `tier` above). `panel_votes` is the 

255 full per-judge audit trail (never collapsed away once computed); 

256 `quorum_reached` is `True` iff a strict majority (`count * 2 > 

257 panel_size`) agreed — `False` on a tie means `value` was set 

258 fail-closed, not that no verdict exists. `cost_usd` for a panel 

259 score is the `Decimal` SUM of every panelist's real per-call cost 

260 (or `None` if any one panelist's cost is unmeasured), never just 

261 the first judge's — a real divergence from a single-judge 

262 `llm_judge` score's `cost_usd`, which is exactly one call's cost. 

263 """

293 # evals-optimization-beyond-settled-2026-09-14.md Finding 1) tags a

295 # evals.judge.llm_judge's own prompt-generation logic produced it -- 

296 # evals.judge.llm_judge.JUDGE_PROMPT_VERSION at construction time on

308class Span(BaseModel): 

309 """One real OTel-SDK-generated span wrapping a single sandbox execution 

310 attempt in the Rollout Scheduler, per docs/rfcs/2026-09-04-evals-trace- 

311 span-model.md. 

312 

313 Deliberately no `Trace` wrapper: today's harness makes exactly one 

314 `run_in_sandbox()` call per `Run`, so `Span` joins directly to `Run.id` 

315 via `run_id` — the same "don't build the diagram-only box" discipline 

316 already applied to `Run`/`Score` in `evals/ARCHITECTURE.md`'s Data 

317 Model section. A future multi-step harness making several spans per 

318 `Run` is the real trigger for introducing `Trace{spans: [Span]}`. 

319 

320 `span_id`/`trace_id` are real, spec-compliant OTel IDs (16/32 lowercase 

321 hex chars) generated by the OTel Python SDK's own `RandomIdGenerator`, 

322 via a locally-held `TracerProvider` in `evals.tracing` — never the 

323 process-wide `trace.set_tracer_provider()` singleton. No OTLP exporter 

324 is wired: the SDK is used purely as a correct ID/timestamp/status 

325 generator, for possible future correlation with gateway's own real 

326 OTel spans (per `api/otel`'s still-undecided transport), never as a 

327 live export pipeline. 

328 

329 `container_id` (added 2026-09-04, alongside a real bug fix in 

330 `sandbox.py`: killing the local `docker run` CLI process on timeout 

331 did not stop the container itself — confirmed empirically against a 

332 real Docker daemon) is the real Docker container ID, captured via 

333 `--cidfile`, matching the stable `container.id` semantic convention. 

334 `process_pid` remains deliberately excluded — even now that a real 

335 PID is technically obtainable from the local `docker run` CLI 

336 process, that PID identifies the CLI *client* process, not the 

337 containerized command's own process, and OTel's `process.pid` 

338 convention means the latter — attaching the former would be a real, 

339 honest-sounding-but-wrong value, worse than omitting the field. 

340 `gen_ai.operation.name` is deliberately never used — confirmed, via 

341 direct inspection of the OTel semantic-conventions registry, to be a 

342 namespace for LLM/model-inference operations only, not applicable to 

343 a container-sandbox execution. 

344 """

372class TrendSnapshot(BaseModel): 

373 """One persisted history point for one named quality-trend series. 

374 

375 Per this repo's own already-documented principle (`evals.cli`'s 

376 module docstring: "never blended across `deterministic` and 

377 `llm_judge`") and every 2026 eval platform surveyed while designing 

378 this feature (Langfuse/Braintrust/Arize all trend named score series 

379 side by side, never fused into one composite) -- a `TrendSnapshot` 

380 always names exactly one `series`. There is no combined "eval 

381 quality score" anywhere in this model or in `evals trend show`, 

382 which reads it. 

383 

384 Exactly one of `rate_value`/`cost_usd_value` is the "active" field 

385 for a given `series` -- `series == "cost_usd"` uses `cost_usd_value` 

386 (a real `Decimal`, per `Score.cost_usd`'s own established Decimal- 

387 not-float cost-accounting convention -- never cast to `float`, which 

388 would reintroduce the exact imprecision `Decimal` exists to 

389 prevent); every other `series` uses `rate_value`. The field that is 

390 NOT active for a given `series` is always `None` -- enforced below. 

391 `rate_value` being `None` for its own active series is still a 

392 legitimate, meaningful value, distinct from "not applicable": a 

393 `judge_accuracy_kappa` snapshot records `None` when Cohen's kappa is 

394 genuinely undefined (zero-variance verdicts -- the same 

395 `kappa_str == "undefined"` case `evals.cli.report_cmd` already 

396 handles), and a `quote_grounding_rate` snapshot records `None` when 

397 no `Score` in that report run had a known `quote_grounded` value yet 

398 (`n=0`) -- both are honest "measured, but no real number exists" 

399 facts, mirroring `Run.cost_usd`/`Score.cost_usd`'s own "`None` means 

400 not applicable, never a fabricated stand-in" convention used 

401 throughout this file. `cost_usd_value` has no such "measured but 

402 undefined" case in any real call site today -- a real total cost is 

403 always computable -- so the validator below treats it more strictly. 

404 

405 `category_tag` is reserved for a future per-category trend 

406 (mirroring `Score.tags`/`report_cmd --category-fail-under`'s own 

407 tag-scoping) -- no real call site in `evals.cli` populates it yet; 

408 always `None` today. 

409 

410 `scorer_id` mirrors `Score.scorer_id` (the judge/panel identity, 

411 e.g. a model id string or a panel's `"panel:" + "+".join(ids)` 

412 composition) -- per PRD.md's Success Metrics line ("every judged 

413 result carries a disclosed harness configuration... never a bare 

414 percentage"), a trend series is otherwise silent about WHICH judge 

415 produced it. Populated only when uniform across the group of 

416 `Score`s a snapshot was computed from; `None` when the group is 

417 mixed (a real possibility once scores from different runs are 

418 combined) rather than fabricate a value, or for series that have no 

419 scorer_id concept at all (`audit_corpus_defect_rate`). 

420 

421 `scorer_type` is `None` for `audit_corpus_defect_rate` (audited per 

422 suite file, not per scorer) and real (`"deterministic"`/ 

423 `"llm_judge"`/`"llm_judge_panel"`) for the other series, all 

424 computed inside `report_cmd`'s own per-`scorer_type` grouping loop -- 

425 never blended across scorer types, the same discipline `report_cmd`'s 

426 own pass_rate/CI lines already enforce. `judge_panel_tie_rate` is 

427 additionally scoped to `scorer_type == "llm_judge_panel"` only -- a 

428 single-judge score has no quorum/tie concept at all. 

429 """

443 @model_validator(mode="after") 

444 def _check_value_field_matches_series(self) -> TrendSnapshot: 

445 """Enforce the one-field-per-series rule described in this 

446 class's own docstring. 

447 

448 Deliberately NOT a bare "exactly one of the two is not-None" 

449 check -- that would reject the legitimate `rate_value=None` 

450 cases described above. The real invariant enforced here is 

451 narrower and more useful: the field that does NOT belong to 

452 `series` must never carry a value -- `cost_usd_value` must be 

453 `None` for any non-`cost_usd` series, and `rate_value` must be 

454 `None` for `series == "cost_usd"` (cost is always a real, 

455 computed `Decimal` in every real `evals.cli` call site, never 

456 legitimately unmeasured the way kappa/quote-grounding can be). 

457 """ 

458 if self.series == "cost_usd": 

459 if self.cost_usd_value is None: 

460 raise ValueError( 

461 "TrendSnapshot(series='cost_usd') requires cost_usd_value " 

462 "to be set." 

463 ) 

464 if self.rate_value is not None: 

465 raise ValueError( 

466 "TrendSnapshot(series='cost_usd') must not set rate_value " 

467 "-- cost_usd_value is the only field this series ever " 

468 "populates." 

469 ) 

470 elif self.cost_usd_value is not None:
