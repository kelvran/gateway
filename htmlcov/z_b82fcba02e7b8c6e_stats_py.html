1"""Statistical helpers for eval scoring. 

2 

3`PRD.md`'s success metric is explicit: never report a bare pass rate without 

4a confidence interval alongside it. The Wilson score interval (not a normal 

5approximation) is the right tool here because it stays well-behaved exactly 

6where a golden-tier eval set tends to live: small `n` and/or a proportion 

7near 0 or 1, both regimes where the normal approximation breaks down. 

8""" 

9

18# A closed interval's edge exactly touching 0.0 or 1.0 reads, to a human or 

19# a CI/CD gate, as "impossible" / "certain" — a claim no finite sample can 

20# actually support. The literal Wilson formula *does* produce an exact 1.0 

21# at successes == total (and an exact 0.0 at successes == 0): this clamp is 

22# a deliberate, documented engineering choice on top of the real formula, 

23# not a substitute for it, so the reported interval never overstates 

24# certainty a finite `n` can't back up. 

25_EPSILON = 1e-9

28def wilson_interval( 

29 successes: int, total: int, confidence: float = 0.95 

30) -> tuple[float, float]: 

31 """Return the Wilson score confidence interval for a binomial proportion. 

32 

33 Args: 

34 successes: number of successful trials (0 <= successes <= total). 

35 total: number of trials. Must be > 0. 

36 confidence: confidence level in (0, 1), e.g. 0.95 for a 95% CI. 

37 

38 Returns: 

39 (lower, upper) bound tuple, each strictly within (0.0, 1.0). 

40 

41 Raises: 

42 ValueError: if `total` is not positive, `successes` is out of 

43 [0, total], or `confidence` is not in (0, 1). 

44 """ 

45 if total <= 0: 

46 raise ValueError("total must be > 0") 

47 if not 0 <= successes <= total: 

48 raise ValueError("successes must satisfy 0 <= successes <= total") 

49 if not 0 < confidence < 1: 

50 raise ValueError("confidence must be in the open interval (0, 1)") 

51 

52 z = NormalDist().inv_cdf(1 - (1 - confidence) / 2) 

53 n = float(total) 

54 p_hat = successes / n 

55 

56 denom = 1 + (z**2) / n 

57 centre = (p_hat + (z**2) / (2 * n)) / denom 

58 adjustment = (z / denom) * math.sqrt( 

59 (p_hat * (1 - p_hat)) / n + (z**2) / (4 * n**2) 

60 ) 

61 

62 lower = centre - adjustment 

63 upper = centre + adjustment 

64 

65 lower = min(max(lower, _EPSILON), 1 - _EPSILON) 

66 upper = min(max(upper, _EPSILON), 1 - _EPSILON) 

67 

68 return lower, upper

71def mixture_sprt_early_stop( 

72 successes: int, 

73 trials_run: int, 

74 baseline_pass_rate: float, 

75 confidence: float = 0.95, 

76 relative_mixing_variance: float = 1.0, 

77) -> bool: 

78 """Decide whether a group of repeated trials should stop now, via a 

79 real mixture sequential probability ratio test (mSPRT) — Robbins 

80 (1970), popularized for production A/B testing by Johari, Koomen, 

81 Pekelis & Walsh (KDD 2017), the same paper this project's own prior 

82 two-checkpoint design already cited as the authoritative source for 

83 why naively rechecking `wilson_interval` after every trial inflates 

84 the true false-positive rate (the classical optional-stopping / 

85 peeking failure mode). 

86 

87 Unlike that prior design, this is checked after *every single trial*, 

88 with no pre-declared checkpoints and no Bonferroni correction: by 

89 Ville's inequality, the mSPRT likelihood ratio is a nonnegative 

90 martingale under the null, so `P(exists n: stop) <= 1 - confidence` 

91 holds *simultaneously at every trial count* — the actual anytime-valid 

92 property the old design's checkpoint restriction was a conservative 

93 workaround for, not a full substitute. 

94 

95 The null-hypothesis variance `baseline_pass_rate * (1 - 

96 baseline_pass_rate)` is used FIXED, never re-estimated from this 

97 group's own running data — see docs/rfcs/2026-09-05-evals-mixture- 

98 sprt-early-stopping.md's "A deliberate choice" section: an 

99 online-estimated variance only gives an asymptotically-valid test, 

100 with real, measurable false-positive inflation at low trial counts 

101 unless a substantial warmup is spent first — a cost this early- 

102 stopping mechanism exists specifically to avoid paying. 

103 

104 Args: 

105 successes: successful trials so far in this group. 

106 trials_run: total trials so far in this group (>= successes). 0 

107 never stops (no data yet). 

108 baseline_pass_rate: the pass rate this group's running rate is 

109 tested against. Must be in the open interval (0, 1) — a 

110 baseline of exactly 0 or 1 gives zero null variance, a 

111 degenerate test this project has no reason to support. No 

112 default: this project has no production traffic yet to 

113 calibrate one — the operator must always supply it 

114 explicitly. 

115 confidence: confidence level in (0, 1). The false-positive rate is 

116 bounded by `1 - confidence`, at every trial count. 

117 relative_mixing_variance: the mSPRT's mixing-distribution 

118 variance, as a multiple of the null variance (Johari et al.'s 

119 own stated rule of thumb: "on the order of" it, hence a 

120 default of 1.0). Tunes detection speed/power only — provably 

121 never affects the false-positive-rate guarantee above, for 

122 any positive value. 

123 

124 Returns: 

125 True if the mSPRT likelihood ratio at this trial count has 

126 crossed `1 / (1 - confidence)` — a real, valid stop decision. 

127 False otherwise, including `trials_run == 0`. 

128 

129 Raises: 

130 ValueError: if `baseline_pass_rate`/`confidence` is not in the 

131 open interval (0, 1), `relative_mixing_variance` is not 

132 positive, or `successes` is out of `[0, trials_run]`. 

133 """ 

134 if not 0 < baseline_pass_rate < 1: 

135 raise ValueError("baseline_pass_rate must be in the open interval (0, 1)") 

136 if not 0 < confidence < 1: 

137 raise ValueError("confidence must be in the open interval (0, 1)") 

138 if relative_mixing_variance <= 0: 

139 raise ValueError("relative_mixing_variance must be > 0") 

140 if not 0 <= successes <= trials_run: 

141 raise ValueError("successes must satisfy 0 <= successes <= trials_run") 

142 

143 if trials_run == 0: 

144 return False 

145 

146 null_variance = baseline_pass_rate * (1 - baseline_pass_rate) 

147 mixing_variance = relative_mixing_variance * null_variance 

148 n = trials_run 

149 observed_effect = successes / n - baseline_pass_rate 

150 

151 n_times_mixing_variance = n * mixing_variance 

152 denominator = null_variance + n_times_mixing_variance 

153 # Computed in log-space, not as a raw likelihood ratio compared 

154 # against 1/alpha directly: an extreme deviation with enough trials 

155 # drives the real (non-log) ratio's exponent well past what 

156 # math.exp can represent (a real OverflowError, caught by this 

157 # module's own property-based test suite, not a hypothetical), while 

158 # the log-likelihood-ratio itself stays a perfectly ordinary, 

159 # representable float at every input this function accepts. 

160 log_likelihood_ratio = 0.5 * math.log(null_variance / denominator) + ( 

161 (n * n_times_mixing_variance * observed_effect**2) 

162 / (2 * null_variance * denominator) 

163 ) 

164 

165 alpha = 1 - confidence 

166 return log_likelihood_ratio >= -math.log(alpha)

169class ConfusionMatrix(NamedTuple): 

170 """A 2x2 confusion matrix for a binary judge verdict vs. a binary 

171 human/ground-truth label. `true_positive`/`false_positive` treat the 

172 judge's `True` (PASS) verdict as the positive class.""" 

173 

174 true_positive: int 

175 false_positive: int 

176 true_negative: int 

177 false_negative: int 

178

180def confusion_matrix( 

181 judge_verdicts: list[bool], human_verdicts: list[bool] 

182) -> ConfusionMatrix: 

183 """Return the 2x2 confusion matrix for paired judge/human verdicts. 

184 

185 Args: 

186 judge_verdicts: one bool per case, the judge's own PASS/FAIL 

187 verdict. 

188 human_verdicts: one bool per case, the ground-truth label for 

189 the same case, in the same order. Must be the same length 

190 as `judge_verdicts` and non-empty. 

191 

192 Returns: 

193 A `ConfusionMatrix` whose four counts sum to `len(judge_verdicts)`. 

194 

195 Raises: 

196 ValueError: if the two lists have different lengths, or both 

197 are empty. 

198 """ 

199 if len(judge_verdicts) != len(human_verdicts): 

200 raise ValueError( 

201 "judge_verdicts and human_verdicts must be the same length, " 

202 f"got {len(judge_verdicts)} and {len(human_verdicts)}" 

203 ) 

204 if len(judge_verdicts) == 0: 

205 raise ValueError("judge_verdicts/human_verdicts must be non-empty") 

206 

207 tp = fp = tn = fn = 0 

208 for judge, human in zip(judge_verdicts, human_verdicts, strict=True): 

209 if judge and human: 

210 tp += 1 

211 elif judge and not human: 

212 fp += 1 

213 elif not judge and not human: 

214 tn += 1 

215 else: 

216 fn += 1 

217 return ConfusionMatrix( 

218 true_positive=tp, false_positive=fp, true_negative=tn, false_negative=fn 

219 )

222def cohens_kappa(judge_verdicts: list[bool], human_verdicts: list[bool]) -> float: 

223 """Return Cohen's kappa — chance-corrected agreement between a 

224 judge's verdicts and human/ground-truth labels for the same cases. 

225 

226 Raw exact-match agreement systematically overstates how good a 

227 judge actually is: a real 2026 study found exact-match exceeds 

228 kappa by a ~38.6 percentage-point mean across 21 judges on MT-Bench 

229 — any judge-accuracy metric built only on raw exact-match will look 

230 far better than it actually is. Kappa corrects for this by 

231 subtracting out the agreement rate two independent, chance-only 

232 raters would produce given each one's own marginal PASS rate: 

233 

234 kappa = (p_o - p_e) / (1 - p_e) 

235 

236 where `p_o` is the observed agreement rate ((TP + TN) / N) and 

237 `p_e` is the chance-expected agreement rate derived from the 

238 judge's and human's own independent PASS rates. This is 

239 deliberately NOT the same as Pearson/Spearman/Kendall-tau_b/phi/ 

240 Matthews correlation coefficient — those five are mathematically 

241 identical to each other for binary verdicts, but kappa is a 

242 genuinely different, chance-discounted statistic, most different 

243 from them exactly when the judge's and human's marginal PASS rates 

244 diverge. 

245 

246 Args: 

247 judge_verdicts: one bool per case, the judge's own PASS/FAIL 

248 verdict. 

249 human_verdicts: one bool per case, the ground-truth label for 

250 the same case, in the same order. 

251 

252 Returns: 

253 Cohen's kappa, typically in [-1, 1] (1.0 = perfect agreement, 

254 0.0 = chance-level agreement, negative = worse than chance). 

255 

256 Raises: 

257 ValueError: on the same length-mismatch/empty conditions as 

258 `confusion_matrix`, or if `p_e == 1.0` — both raters have 

259 zero marginal variance in the identical direction (e.g. 

260 every verdict on both sides is `True`), making kappa 

261 undefined (a literal 0/0), not silently `NaN` or `1.0`. 

262 """ 

263 matrix = confusion_matrix(judge_verdicts, human_verdicts) 

264 n = float(len(judge_verdicts)) 

265 

266 p_observed = (matrix.true_positive + matrix.true_negative) / n 

267 judge_positive_rate = (matrix.true_positive + matrix.false_positive) / n 

268 human_positive_rate = (matrix.true_positive + matrix.false_negative) / n 

269 p_expected = judge_positive_rate * human_positive_rate + ( 

270 1 - judge_positive_rate 

271 ) * (1 - human_positive_rate) 

272 

273 if p_expected >= 1 - _EPSILON: 

274 raise ValueError( 

275 "cohens_kappa is undefined when p_expected == 1.0 " 

276 "(both raters have zero marginal variance in the same direction)" 

277 ) 

278 

279 return (p_observed - p_expected) / (1 - p_expected)

282def pass_at_k(n: int, c: int, k: int) -> float: 

283 """Return the unbiased pass@k estimate (Chen et al. 2021, the 

284 Codex/HumanEval paper) for one task: given `n` total samples with `c` 

285 of them correct, the probability that at least one of a random 

286 k-sized subset (drawn without replacement from the n samples) is 

287 correct. 

288 

289 Computed via the numerically-stable running-product form the paper's 

290 own reference implementation uses — `1 - prod_{i=n-c+1}^{n} (1 - 

291 k/i)` — never the raw binomial-coefficient ratio `C(n-c,k)/C(n,k)` 

292 directly, which overflows/underflows for large `n`. To report the 

293 real pass@k metric across a suite, call this once per task and 

294 average the results — this function is deliberately single-task, 

295 mirroring `wilson_interval`'s own single-proportion scope. 

296 

297 Args: 

298 n: total number of samples generated for this task. Must be > 0. 

299 c: number of those samples that passed (0 <= c <= n). 

300 k: the k in pass@k. Must satisfy 1 <= k <= n. 

301 

302 Returns: 

303 The unbiased pass@k estimate for this task, in [0, 1]. Returns 

304 exactly 1.0 when there are fewer than `k` failing samples (`n - 

305 c < k`) — at least one of any k-sized subset must then be 

306 correct, by pigeonhole, without needing the product formula at 

307 all. 

308 

309 Raises: 

310 ValueError: if `n` is not positive, `c` is out of `[0, n]`, or 

311 `k` is out of `[1, n]`. 

312 """ 

313 if n <= 0: 

314 raise ValueError("n must be > 0") 

315 if not 0 <= c <= n: 

316 raise ValueError("c must satisfy 0 <= c <= n") 

317 if not 1 <= k <= n: 

318 raise ValueError("k must satisfy 1 <= k <= n") 

319 

320 if n - c < k: 

321 return 1.0 

322 return 1.0 - math.prod(1.0 - k / i for i in range(n - c + 1, n + 1))

325def bootstrap_paired_pvalue( 

326 baseline: Sequence[float], 

327 candidate: Sequence[float], 

328 *, 

329 n_resamples: int = 10_000, 

330 rng: random.Random | None = None, 

331) -> float: 

332 """One-sided paired-bootstrap significance test (Berg-Kirkpatrick, 

333 Burkett & Klein, EMNLP 2012) for whether `candidate` is genuinely 

334 better than `baseline` on the SAME set of paired cases (e.g. per-case 

335 pass/fail scores from two judge providers, or two rounds, on 

336 identical cases). 

337 

338 A naive test that just counts how many resampled deltas fall below 

339 zero is subtly wrong for a paired comparison: the bootstrap resample 

340 distribution of delta is centered on the OBSERVED delta, not zero, so 

341 a plain "count below zero" test is only valid under conditions (a 

342 linear-decomposing metric and a symmetric bootstrap distribution, 

343 which the central limit theorem only guarantees for large samples) a 

344 small eval corpus won't reliably satisfy. This test instead 

345 re-centers correctly: it counts how often a resampled delta exceeds 

346 TWICE the observed delta — exactly as extreme, in the null 

347 (delta=0) frame, as falling below zero would be. 

348 

349 Args: 

350 baseline: per-case scores for the baseline arm (e.g. 1.0/0.0 per 

351 case, or any real-valued per-case score). 

352 candidate: per-case scores for the candidate arm — SAME length 

353 and SAME case order as `baseline`; this is a PAIRED test. 

354 n_resamples: number of bootstrap resamples to draw. 

355 rng: injectable for deterministic tests; defaults to a fresh 

356 `random.Random()`. 

357 

358 Returns: 

359 A one-sided p-value: the probability, under the null hypothesis 

360 that baseline and candidate are equivalent, of observing a delta 

361 at least as extreme as the one actually observed. Small values 

362 (e.g. < 0.05) support "candidate is genuinely better than 

363 baseline." If the observed delta itself favors baseline (is <= 

364 0), this correctly returns a p-value near 1.0 — there is no 

365 evidence for the "candidate is better" direction this test 

366 checks. 

367 

368 Raises: 

369 ValueError: if `baseline`/`candidate` have different lengths or 

370 are empty, or `n_resamples` is not positive. 

371 """ 

372 if len(baseline) != len(candidate): 

373 raise ValueError( 

374 "baseline and candidate must be the same length (paired), " 

375 f"got {len(baseline)} and {len(candidate)}" 

376 ) 

377 if len(baseline) == 0: 

378 raise ValueError("baseline/candidate must be non-empty") 

379 if n_resamples <= 0: 

380 raise ValueError("n_resamples must be > 0") 

381 

382 if rng is None: 

383 rng = random.Random() # noqa: S311 -- Monte Carlo simulation, never cryptographic material 

384 

385 n = len(baseline) 

386 observed_delta = (sum(candidate) - sum(baseline)) / n 

387 indices = range(n) 

388 

389 exceed_count = 0 

390 for _ in range(n_resamples): 

391 sample = rng.choices(indices, k=n) 

392 resampled_delta = sum(candidate[i] - baseline[i] for i in sample) / n 

393 if resampled_delta > 2 * observed_delta: 

394 exceed_count += 1 

395 

396 return exceed_count / n_resamples

399def beta_binomial_prob_a_beats_b( 

400 successes_a: int, 

401 trials_a: int, 

402 successes_b: int, 

403 trials_b: int, 

404 *, 

405 prior_alpha: float = 1.0, 

406 prior_beta: float = 1.0, 

407 n_samples: int = 100_000, 

408 rng: random.Random | None = None, 

409) -> float: 

410 """Monte Carlo estimate of P(A's true pass rate > B's true pass rate) 

411 under a Beta-Binomial Bayesian model — for comparing two eval pass 

412 rates (e.g. two judge providers, or two rounds' corpus results). 

413 

414 Each arm's posterior is `Beta(prior_alpha + successes, prior_beta + 

415 trials - successes)` — the standard Beta-Binomial conjugate update. 

416 `random.betavariate` samples this posterior directly; no 

417 `scipy.stats.beta` is needed. P(A beats B) is estimated as the 

418 fraction of paired posterior-sample draws where A's draw exceeds B's. 

419 

420 Args: 

421 successes_a: A's observed successes (0 <= successes_a <= 

422 trials_a). 

423 trials_a: A's observed trial count. Must be > 0. 

424 successes_b: B's observed successes (0 <= successes_b <= 

425 trials_b). 

426 trials_b: B's observed trial count. Must be > 0. 

427 prior_alpha: the shared Beta prior's alpha shape parameter. 

428 Default 1.0 (paired with the default `prior_beta` below) 

429 gives the uniform prior over [0, 1] — a real, common, 

430 uninformative default, not an arbitrary placeholder. 

431 prior_beta: the shared Beta prior's beta shape parameter. 

432 Default 1.0. 

433 n_samples: number of Monte Carlo posterior-pair draws. 

434 rng: injectable for deterministic tests; defaults to a fresh 

435 `random.Random()`. 

436 

437 Returns: 

438 Estimated P(A beats B), in [0, 1]. 

439 

440 Raises: 

441 ValueError: if either trial count is non-positive, either 

442 successes count is out of range, or either prior parameter 

443 is <= 0. 

444 """ 

445 if trials_a <= 0 or trials_b <= 0: 

446 raise ValueError("trials_a and trials_b must both be > 0") 

447 if not 0 <= successes_a <= trials_a: 

448 raise ValueError("successes_a must satisfy 0 <= successes_a <= trials_a") 

449 if not 0 <= successes_b <= trials_b: 

450 raise ValueError("successes_b must satisfy 0 <= successes_b <= trials_b") 

451 if prior_alpha <= 0 or prior_beta <= 0: 

452 raise ValueError("prior_alpha and prior_beta must both be > 0") 

453 

454 if rng is None: 

455 rng = random.Random() # noqa: S311 -- Monte Carlo simulation, never cryptographic material 

456 

457 alpha_a = prior_alpha + successes_a 

458 beta_a = prior_beta + (trials_a - successes_a) 

459 alpha_b = prior_alpha + successes_b 

460 beta_b = prior_beta + (trials_b - successes_b) 

461 

462 a_wins = 0 

463 for _ in range(n_samples): 

464 if rng.betavariate(alpha_a, beta_a) > rng.betavariate(alpha_b, beta_b): 

465 a_wins += 1 

466 

467 return a_wins / n_samples
