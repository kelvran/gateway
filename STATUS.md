## Current Phase

`evals report --scores` cost aggregation — picked per the founder's "go ahead with the recommended next ideal steps" reply. No fresh research pass this time: the prior judge-call-cost-tracking entry had already fully argued the design in writing ("the moment `evals` gets a suite-level cost aggregation... Decimal should be adopted immediately"), so this pass executes a pre-written decision rather than making a new one. `evals report --scores` now sums each `scorer_type` group's `cost_usd` into a `total_cost_usd` line. `Score.cost_usd` (and `providers.py`'s price-table math) migrated from `float` to `Decimal` in the same pass, built from string literals only. Independently verified before writing any test: pydantic v2 safely converts a float *input* to a `Decimal` field (`Decimal(str(value))`), but comparing a computed `Decimal` *result* directly against a bare float literal is not reliably safe (`Decimal('0.0001234') == 0.0001234` → `False`, confirmed both directions) — every test touching a computed `Decimal` compares against a `Decimal(...)` literal now. A `None`-cost `Score` (currently unreachable) is excluded from the sum and counted explicitly, never folded in as zero.

Real judge-call cost tracking on `Score.cost_usd` (previous phase) — `evals/judge/providers.py`'s `make_anthropic_call_model()` returns a callable object (`_AnthropicCallModel`) exposing `last_call_cost`, read from the SDK's own `usage` field — a deliberate, narrow, explicitly-flagged exception to the org-wide immutability rule, the only channel available without touching `judge()`/`llm_judge.py` at all. Real Anthropic pricing for `claude-haiku-4-5-20251001` ($1.00/$5.00 per MTok input/output) was live-fetched and cross-checked, flagged for re-verification after 2026-10-15.

Full phase history lives in `docs/agents/LOGS.md` (one entry per feature) and `DECISIONS.md` (one line per decision) — not restated here beyond the current + immediately-previous phase, to keep this section from growing unbounded.
