# RFC: Anthropic/Bedrock cache-token cost-accounting fix

## Status

Accepted, implemented 2026-09-10.

## Context

A `docs/upgrade-research/gateway-next-upgrade-round2-2026-09-09.md` deep-research pass surfaced a real correctness/cost defect, verified directly against the current code: `gateway/internal/adapter/anthropic/anthropic.go`'s native `Usage{InputTokens, OutputTokens}` and `bedrock/bedrock.go`'s native `Usage{InputTokens, OutputTokens, TotalTokens}` have no fields for either provider's real cache-token usage — `encoding/json` silently drops `cache_creation_input_tokens`/`cache_read_input_tokens` (Anthropic) and `cacheReadInputTokens`/`cacheWriteInputTokens` (Bedrock) on unmarshal. Every downstream consumer of `adapter.Usage` inherits the gap: `costaccounting.Calculate` undercounts real dollar cost and per-key budget spend; the TPM rate-limit dimension (`ReconcileTPM`) undercounts real token usage; and the `gen_ai.usage.input_tokens` OTel attribute undercounts the real figure. This is the *default* path today, not an edge case, since `docs/rfcs/2026-09-07-gateway-cache-control-auto-populate.md` made Anthropic/Bedrock system-prompt caching default-ON.

Two live API-documentation fetches (Anthropic's Messages API, AWS Bedrock's Converse API reference) confirmed the exact field names before implementing, per this codebase's own established discipline of verifying against a live source rather than a plausible guess: Anthropic's own formula is `total_input_tokens = cache_read_input_tokens + cache_creation_input_tokens + input_tokens` — i.e. Anthropic's native `input_tokens` already excludes cache tokens, and its own concept of "total input" is cache-inclusive. Bedrock's Converse `TokenUsage.totalTokens` is documented as "the total of input tokens and tokens generated by the model" — i.e. `inputTokens+outputTokens` only; cache tokens are **not** already folded in there, despite the field's name suggesting otherwise.

## Design

Token-counting correctness (unconditional, zero config) is deliberately split from cost-pricing (opt-in, config-gated):

**Canonical `adapter.Usage`** (`gateway/internal/adapter/types.go`): `PromptTokens` becomes cache-inclusive by definition, matching each provider's own "total input tokens" semantics — this is the one design choice that makes the fix automatic at both consumer call sites that matter (`dataplane.go`'s `InputTokens: resp.Usage.PromptTokens` and the `TotalTokens`-driven TPM debit), neither of which needed a single line changed. Two new informational fields, `CacheReadTokens`/`CacheCreationTokens int` (JSON `omitempty`), are a documented subset of `PromptTokens` — used only by `costaccounting` to price that slice separately.

**4 producer sites** (Anthropic buffered `anthropic.go` + streaming `stream.go`; Bedrock buffered `bedrock.go` + streaming `stream.go`) add native cache-token fields with the verified wire names and compute `PromptTokens`/`TotalTokens` per each provider's own confirmed formula. Anthropic's cache fields live in the same `message_start.message.usage` event the existing `input_tokens` capture already reads; Bedrock's live in the single `metadata` event already used for all usage.

**`costaccounting`** (a pure leaf, zero allowed dependency edges) gets its own mirrored `Usage` struct (`CacheReadTokens`/`CacheCreationTokens int`). `ModelPrice` gains `CacheReadPerToken`/`CacheCreationPerToken *decimal.Decimal` — pointers, not bare `decimal.Decimal`: `nil` means "not configured for this model," distinguishable from an operator's explicit `decimal.Zero` (e.g. "cache reads are free"), which a bare-value field could never represent. `Calculate` prices `freshPromptTokens := PromptTokens - CacheReadTokens - CacheCreationTokens` at the base rate, then the two cache slices separately via a new `resolveCacheRate(rate *decimal.Decimal, fallback decimal.Decimal) decimal.Decimal` helper.

**The confirmed fallback decision** (raised to the user via `AskUserQuestion`, given the real cost/business tradeoff — computed $ figures visibly change the moment this ships): both `Calculate` call sites pass `price.PromptPerToken` as the fallback. An operator who hasn't configured an explicit cache rate for a model has that model's cache tokens priced as ordinary prompt tokens — closing the undercounting defect (cache tokens previously contributed $0) immediately, for every existing deployment, with zero config change required. The rejected alternative (default to $0, matching today's behavior, until an operator opts in) would have shipped the fix in code while leaving it inert until someone acted.

**Config** (`controlplane.ModelPriceConfig`): the same two `*decimal.Decimal` fields, parsed from new YAML keys `cache_read_per_token`/`cache_creation_per_token` under `price_table.<model>:`, reusing the existing `getDecimal` helper.

## Alternatives considered

**"Raw + `Calculate` sums separately"** (keep `PromptTokens` non-cache-inclusive, let `costaccounting.Calculate` do the summing) — rejected: this would require an explicit three-field sum inserted at both consumer call sites (`InputTokens`, the TPM debit) that currently read `PromptTokens`/`TotalTokens` verbatim — a second and third place the fix could be forgotten, versus the chosen design's zero required changes at either site.

**Widening `budget`/`ratelimit` to accept the raw `Usage` struct instead of a pre-computed dollar/token figure** — unnecessary: both packages are already downstream of `costaccounting.Calculate`'s/`adapter.Usage`'s output by construction; fixing the two upstream types fixes every consumer automatically, without touching either package.

## Verification

New tests per producer site: `TestFromProviderIncludesCacheTokensInPromptAndTotal` (both `anthropic_test.go`/`bedrock_test.go`), `TestStreamDecoder_UsageIncludesCacheTokens`/`TestDecodeMetadataUsageIncludesCacheTokens` (both `stream_test.go`), and a new golden-fixture pair per provider in `regression_test.go` (`response_{anthropic,bedrock}_native_cached.json` → `response_canonical_cached.golden.json`, via the existing `assertJSONEqual` tree-diff). `costaccounting_test.go`: `TestCalculateCacheTokensPricedAtCacheRate`, `TestCalculateUnsetCacheRateFallsBackToPromptRate`, `TestCalculateCacheReadPlusCreationNeverExceedsPromptTokensInvariant`. `config_test.go`: `TestLoadPriceTableParsesCacheTokenRates`. A new full-pipeline dataplane test, `TestCallDeploymentCacheTokensFoldIntoCostAndTPM`, proves both signals against the SAME cache-bearing response: `budget.Tracker.SpentUSD` reflects the cache-inclusive priced cost, and a TPM bucket sized to survive the pre-fix (6-token) debit but not the post-fix (2054-token) debit correctly rejects a second request. Sanity-checked-by-breaking: temporarily reverted Anthropic's `FromProvider` mapping to the pre-fix 2-field shape, confirmed both assertions in that new test failed for the exact predicted reason (`0.00015` instead of `0.03087`; the TPM rejection never fired), restored.
