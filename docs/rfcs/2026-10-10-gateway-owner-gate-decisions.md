# Owner gate decisions, 2026-10-10

- **Status**: decided by the owner on 2026-10-10 against `main` at `a512d59a` (the commit that completed RFC-3 Stage 1). This record resolves every owner gate the round-4 discoverability plan and its four RFCs left open; each RFC's own "Owner decisions" section points here. `DECISIONS.md` keeps its rule of one line per decision *after* the work ships, so the one-liners land there with each item.
- **How**: a brainstorm with the owner over the gates that are values, risk appetite or classification (G8, G14, G24, G33, G5/G6, G9, G15, G16, the release), interleaved with a five-agent read-only red-team of every recorded recommendation against the code at `a512d59a`, the RFC texts and the archived primary sources (`scratch-pad/research/round4-lanes/sources/`, gitignored). The red-team changed no owner decision; it added eight modifications, listed per gate below, and flagged the claims it could not verify (last section).

## Decisions

| Gate | Decision | Why |
|---|---|---|
| **G8** (RFC-1) | **Option C**, passthrough-first: native passthrough for `provider: anthropic` deployments, translation through the canonical schema for every other provider | The only live configuration is all Bedrock, so Option B would give the pilot no Claude Code path; Option A would re-encode the `system` array and preserved-thinking blocks on the Anthropic hop |
| **Q2** (RFC-1) | Inbound `x-api-key` alias on `/v1/messages`, `/v1/messages/count_tokens` and `/v1/models`; `Authorization` wins when both are present; one attempt per request; `identity.Verify` untouched; OpenAI routes stay bearer-only | Authentication is bearer-only in one place (`gateway/internal/identity/identity.go`, the `Bearer ` prefix check); the alias is a carrier change. Claude Code sends both headers with different values when a Console key sits in `ANTHROPIC_API_KEY`, so a deterministic precedence is required. **Additions:** the Claude Code how-to and `kelvran connect claude` say "set exactly one credential variable" (two conflicting variables are a 401 with no fallback, by design); `THREAT_MODEL.md` names `x-api-key` as a credential-bearing header so any future header sink denylists it beside `Authorization` |
| **Q3** (RFC-1) | `HEAD /api/hello` answers 204, unauthenticated, no body; `GET` is 405 | The protocol page calls it best-effort warming traffic a gateway may reject; today's `ServeMux` 404 is already correct, so this is hygiene. The test pins "no auth, no body, no status variation" |
| **Q4** (RFC-1) | `anthropic_beta_policy` default `strip` for Bedrock; `forward_known` only after a live 200 per value | Nothing in the tree or the archived sources shows an `anthropic_beta` key accepted through Converse `additionalModelRequestFields`, so the *transport* is unproven, not only the values. **Additions:** the live proof (pilot credentials, `max_tokens: 1`) covers the transport and each of the five captured betas, interleaved thinking first; the two AWS Converse pages are archived under `scratch-pad/research` before RFC-1 quotes them; `thinking: {"type":"adaptive"}` and `output_config.effort` move from "unverified, quiet drop" to "AWS-documented, live 200 pending, forward once proven" |
| **Q5** (RFC-1) | `accept_lossy_anthropic_ingress` default `false`; a pre-upstream 400 `invalid_request_error` | Fail closed is this gateway's convention. **Modification:** `error.message` is a fixed sentence naming the config key, the remedy (`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`) and only top-level unknown field names; the full JSON-pointer list goes in `error.param`; a test asserts the message never contains the strings Claude Code's recovery matches on (`thinking`, `cache_control`, `system`, `output_config.effort`, `Extra inputs are not permitted`, `Input tag`, `bound to a different conversation`, `capability_rejected:`) |
| **G16** (plan) | Resolved **together with item 11**, as a MINOR change in `v0.19.0`: `ErrStructuredOutputUnsupported` 502 → 400 `response_format_unsupported`, `ErrFingerprintMismatch` 502 → 422 `idempotency_key_reused` | One rule: a problem known from the request alone is a 4xx. Leaving the plan's default would put RFC-1's 400 beside two 502s for the same class of fault |
| **Q6 / G15** (RFC-1) | Go and Python compatibility legs block merges; a TypeScript leg runs nightly, non-blocking, in a CI container only, driving the real `claude -p` binary or `@anthropic-ai/sdk` against the gateway. **The one-line ADR 0003 note is accepted now**, scoped to CI test tooling: no TypeScript under `gateway/` or `evals/`, no Node or Bun in release images | `docs/decisions/0003-go-python-split.md` decides product languages and never mentions test clients; `AGENTS.md`'s "ask first" is the binding rule and this is the ask. Deferring would leave the merge gate never exercising the SDK the P0 client is built on |
| **G14** (RFC-2) | Identifier capture **ON** by default with `attribution.capture_ids: false` (global) and per-key `attribution_capture_ids: false`; the owner classifies Claude Code session, agent and prompt ids as **not personal data** for this deployment | Capture is already live on `main` in the pilot and its only sink is span attributes (never metrics, logs, the proto or the cache key). The plan's per-key spelling `attribution: off` is stale; the shipped key is `attribution_capture_ids` |
| **G27** (RFC-2) | As recommended: CostViewer may call `GET /admin/spend` only with `key=` naming one key, across every `group_by` (session included); cross-key aggregates need Admin or Viewer; violations are 401 per the admin convention | The red-team's `group_by=session` restriction existed only while session ids were unclassified; G14's classification settles it |
| **G28** (RFC-2) | `POST /admin/spend/erase` Admin-only; no propagation in v1 (one call per replica in bbolt and in-memory modes, shared store in Redis mode). **Modification:** the `admin_spend_erased` audit line carries `rows_erased` and a 16-hex SHA-256 prefix of the session id, never the raw id | The audit log is append-only and indefinite (`SECURITY.md`); writing the raw identifier there would create the longest-lived copy of the thing being erased. `docs/operations/DATA-SUBJECT-REQUESTS.md` gains the per-replica procedure and the note that the 168 h sweep closes a miss |
| **G29** (RFC-2) | `retention_hours: 168` (0 rejected), `max_sessions_per_key: 2000`, in-memory when neither `persist_path` nor Redis is configured. **Addition:** `ledger.max_rows_per_key` (default 50,000) folds overflow rows into one `other` session inside their hour bucket; totals stay exact, the session dimension is lost for that key | The session cap bounds sessions, not rows: rows scale with hours × models × tools per session. The in-memory default mirrors the pilot's in-memory budget and is documented in `docs/operations/FAILURE-MODES.md` |
| **G24** (RFC-4) | Unauthenticated third `/metrics` listener, loopback by default, operator-chosen bind, its own `http.Server` like the admin plane. **Additions:** `promhttp.HandlerOpts{MaxRequestsInFlight: 4, Timeout: 10s}`; a `SECURITY.md` operator bullet (the exposition names every virtual key and its spend, bind it to loopback or a private network); the Kubernetes and compose recipes state that scraping needs a non-loopback bind behind the existing NetworkPolicy (which admits 8080 only today) | The standard Prometheus shape; loopback-by-default does the security work. The two omissions were an unbounded gather on an unauthenticated port and no line in the file operators actually read |
| **G25** (RFC-4) | `go.opentelemetry.io/otel/exporters/prometheus v0.68.0`, `github.com/prometheus/client_golang v1.24.1`, `otlptranslator v1.0.0`, pinned; **do not pre-bump** (v0.69.0 requires OTel SDK v1.47.0 across the gateway) | `gateway/go.mod` pins OTel v1.46.0; v0.68.0 is the exporter release that matches it. Record the pin's reason so a reviewer or Dependabot does not "fix" it |
| **G26** (RFC-4) | Go runtime and process collectors on the dedicated registry by default, no config switch; `metric_relabel_configs` is the documented opt-out; `docs/operations/TELEMETRY.md` states these exist only on the pull path | Gives operators `go_gc_gomemlimit_bytes`, the only view of what automemlimit chose; the pull-versus-OTLP asymmetry must be written down or it reads as a bug |
| **G30–G32** (RFC-3) | Stay as shipped: second binary in the gateway's artifacts; whole-key `expires_at`; `connect claude` writes, the other three print until their documentation is archived | Shipped under RFC-3's defaults in slices (d) to (g); nothing in the red-team argues for a flip |
| **G33** (RFC-3) | The OAuth-credential check stays a **warning** until three conditions hold: (1) the subscription terms are archived together with a dated, redacted token-shape observation (no primary source documents the prefix); (2) **G9 is closed** (below); (3) in `init` the refusal applies only when `anthropic` is a selected provider, other providers keep the warning. `doctor` is already per-deployment | A refusal cannot block a working upstream credential (an OAuth bearer cannot satisfy the `x-api-key` outbound path), but as coded today `init` would refuse `--provider bedrock` in any shell holding a stray token |
| **G9** (plan) | **Closed: never in scope.** Kelvran is an API-key gateway; a claude.ai subscription token is not a credential it accepts, and `init`/`doctor` may say so plainly | Leaving it open would keep G33 a warning forever |
| **G5** (plan) | **Build** the OpenAPI document (item 14), sequenced immediately after item 11 core because both touch `gateway/cmd/gateway/main.go`'s route table; a Go-native validator inside the contract test rather than a Node lockfile; the static page and hosting stay with G7 | `docs/VERSIONING.md` needs the document frozen across two consecutive minors before 1.0, so holding it defers 1.0 by at least two minors. Under Option C the `/v1/messages` schema is permissive by construction and the document says so |
| **G6** (plan) | **Soften now, chart later**: rewrite the Kustomize-only sentence in `deploy/k8s/README.md` and write ADR 0004 as the policy (Kustomize is the source of truth; a generated chart is a distribution channel); register the container image on Artifact Hub (a manual step; the labels already ship); build item 15b's chart only after the `v0.18.0` assets exist, as a manually released `chart/v*` lane. The plan's drift-guard command must first stage `gateway/config.example.yaml` as `base/config.yaml`, because `kustomize build deploy/k8s/base` fails in a fresh checkout | The "third-party only" sentence overstated a 2-1 research vote; a chart today is a second release lane with no recorded user |
| **Release** | **`gateway/v0.18.0` now, before item 11**; item 11 and G16 ship as `v0.19.0`. MINOR is forced by new routes, config keys and a second binary (`docs/VERSIONING.md`). Preconditions, in order: (1) reword `gateway/changelog/unreleased.md` so the prose no longer contains the literal `**BREAKING**` marker that `scripts/release-preflight.sh` greps for; (2) classify the text/plain → JSON error-envelope change as a real `**BREAKING**` entry with an `UPGRADE.md` row; (3) update `docs/VERSIONING.md` §6 (latest 0.18.0, previous 0.17.0, support window); (4) add a `RELEASE.md` step that sweeps the "on `main` since 2026-10-10, not in `gateway/v0.17.0`" qualifiers (159 occurrences) to the tag's name | Two `## Security` entries and a Go toolchain CVE fix have sat unreleased since 2026-10-09; the release pipeline's first real run should not coincide with the ingress change. The tag freezes `connect claude`'s flags under the compatibility policy before a live Claude Code run proves them; the owner accepts that |
