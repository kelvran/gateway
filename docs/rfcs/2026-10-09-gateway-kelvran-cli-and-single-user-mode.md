## Summary

A second shipped binary, `kelvran` (`gateway/cmd/kelvran`, Go, stdlib `flag`, logic in a new leaf `gateway/internal/cli`), turns the by-hand first run — `openssl rand -hex 32`, `sha256sum`, paste the digest into a hand-written `config.yaml`, `-validate`, export the provider key, start (`README.md:45-52`, `docs/tutorials/quickstart.md:29-114`) — into `kelvran init`, and gives operators `doctor`, `keys create|list|rotate|delete`, `connect claude`, `status` and `spend --by key` (in the single-user shape `init --single-user` emits, `keys` and `status --config` work offline against the file, while `spend --by key` and `status`'s live columns need the admin plane — decision 10). It ships **inside** the existing `kelvran-gateway_*` archives, packages and container image, so the release pipeline's SBOM, checksum, signature, attestation and upload steps cover it with no glob changes (`.github/workflows/release.yml:257,265,281,295`). The server side gains exactly what those verbs need and nothing more: a whole-key expiry (`expires_at`, 401 `key_expired`), `GET /admin/virtual_keys?include=spend`, and a read-only `GET /admin/deployments`. Single-user mode is a config shape `init --single-user` emits — loopback data listener, one unbudgeted key, no `admin:` section so nothing listens on the admin port (`gateway/cmd/gateway/main.go:645-646`) — not a new runtime mode; no new runtime mode or flag is added to the gateway binary, and its Stage 1 changes are exactly the ones listed in the Status line.

## Motivation

The round-4 report's ground truth is that Kelvran has no `init` and no zero-config mode, so the first request requires authoring a config from the example file plus the secret/hash dance by hand, against LiteLLM's `curl | sh` and Bifrost's no-config start (`docs/upgrade-research/kelvran-deep-research-round4-discoverability-2026-10-08.md:27-29,72`); the one-command onboarding of coding agents (`lite claude`, `vercel ai-gateway setup`) is the 2026 personal-use norm (`:158`); and the only verified CLI key-lifecycle precedent, Vercel's `api-keys create --limit --refresh-period --alert-thresholds --expiration …` printing the plaintext once, shows the gap is "the CLI verb and one-shot composition, not the data model" (`:159`; the competing LiteLLM `lite keys generate` precedent is refuted 1-2 at `:159,168`). The report's item 12 specifies the verbs (`:233`); RFC-2 pre-committed two decisions to this RFC — `GET /admin/virtual_keys?include=spend` ships with item 12 Stage 1, and `spend --by model|tool|session` is the only CLI surface that waits for the 13d ledger (`docs/rfcs/2026-10-09-gateway-attribution-and-spend-ledger.md:91`, which still calls this RFC "not yet written"; see Unresolved Questions). The coding-agent how-to lists "No `kelvran` CLI (`init`, `doctor`, `keys`, `connect`)" under not available today (`docs/how-to/configure-from-a-coding-agent.md:220`).

## The facts that shape the design

1. **It would be the third main package, and `cmd/` is unconstrained.** `gateway/cmd` already holds `gateway` and `kelvran-bench` (`gateway/ARCHITECTURE.md:5-12`); go-arch-lint runs with `workdir: internal`, so `cmd/*` is outside its scope and only Go's `internal/` rule applies (`gateway/.go-arch-lint.yml:1-2`, `gateway/cmd/kelvran-bench/main.go:22-23`). The in-repo CLI precedent is kelvran-bench: `switch os.Args[1]`, one `flag.NewFlagSet(name, flag.ContinueOnError)` per subcommand, usage to stderr with exit 2, `kelvran-bench: <err>` to stderr with exit 1, data to stdout, the bearer read from `-key-file` and never from the command line (`gateway/cmd/kelvran-bench/main.go:26-53,67-68,72,91-101,238-239`). It has no `-version`, no cmd-level tests, and is not a release asset (`docs/reference/release-artifacts.md:51`).
2. **GoReleaser builds one binary; adding a build id puts the second binary into every existing artifact.** One `builds` entry (id `gateway`, `binary: kelvran-gateway`, five targets, ldflags `-X main.version/.commit/.date` declared inside that entry), one archive and one nfpm entry, neither with an `ids:` filter (`gateway/.goreleaser.yaml:24-52,65-74`). Two claims about GoReleaser v2 (the version `release.yml:151` pins with `~> v2`) are vendor behaviour, **not verified in this tree** (source-map rows D-05/D-06/D-08; the GoReleaser documentation is not archived here): an archive or nfpm entry with no `ids:` includes every build, so a second build lands in the same `kelvran-gateway_*` tar.gz/zip/deb/rpm/apk by default; and the archive pipe fails a release whose archives would hold a different number of binaries on some platforms ("archive has different count of binaries for each platform") unless `allow_different_binary_count: true` is set or the builds get separate archives via `ids` — so the new build id copies the `gateway` build's goos/goarch/ignore set verbatim (`gateway/.goreleaser.yaml:30-34`) and shares the filterless `default` archive (`.goreleaser.yaml:40-43`). The yaml's own documented local dry run (`.goreleaser.yaml:11`, `goreleaser release --snapshot --clean --skip=publish`) is how slice (d) turns both claims into observed behaviour. Everything downstream globs `kelvran-gateway_*`: the SBOM loop, the checksums rewrite, the attestation subject path and the Release upload array (`.github/workflows/release.yml:257,265,281,295`); a separately named archive would need all four edited and is silently dropped by the checksums rewrite while still passing acceptance's own `sha256sum -c` (`:228-230,262-266`). Acceptance executes only `kelvran-gateway` (`:185-191,223-230`). The Dockerfile builds and copies only `./cmd/gateway`; `COPY . .` already carries other `cmd/` sources (`gateway/Dockerfile:41,54-56,65`). `.gitignore` ignores `/gateway/gateway`, `/gateway/kelvran-gateway`, `/gateway/kelvran-bench` — not `/gateway/kelvran` (`.gitignore:66-69`; the 36 MB binary accident is recorded at `:66`).
3. **Build identity is per main package.** `version`, `commit`, `date` are unexported vars in `cmd/gateway`'s `package main`, and `buildInfoString` hardcodes the `kelvran-gateway` prefix (`gateway/cmd/gateway/version.go:9-31`), so `cmd/kelvran` declares its own three vars and its build entry's `-X main.version=` binds to them; acceptance's `-version` assertion is on the literal `kelvran-gateway ${VERSION} (` prefix (`release.yml:189`).
4. **Every admin body type is unexported, and nothing under `internal/` is public.** `admin.Handler` and `Credentials` are the only exports; `virtualKeyRequest`, `virtualKeyListEntry`, `virtualKeySpendResponse`, `rotateVirtualKeyRequest` and the rest are unexported (`gateway/internal/admin/admin.go:75-80,88-1331`), their JSON names deliberately mirror `config.yaml`'s `virtual_keys.<name>` keys (`:82-112`), and `docs/VERSIONING.md:28` declares nothing under `gateway/internal/` importable from outside the module. The admin plane returns plain-text errors via `http.Error`, never the data-plane JSON envelope (`admin.go:316-320,594-610`, `docs/reference/admin-api.md:16`); unknown body fields are silently ignored (`admin.go:603,791,907,956,1257,1361`); an upsert is a full replace, so a field absent from the request literal is zeroed — today that already ends a rotation grace period mid-flight and drops `MaxConcurrentRequests` and `BillingSubjectID` (`admin.go:715-728`, `dataplane.go:1313-1316`).
5. **The loader is parse-only over a hand-rolled YAML subset.** `controlplane.Load` is `os.ReadFile` + `parseYAMLMini`; there is no serializer (`gateway/internal/gateway/controlplane/config.go:1039-1049,1565-1570`). The subset: `key: value` scalars and `key:` block openers only — no lists, no flow style, no null, no anchors, no multi-line strings; `#` starts a comment anywhere, even inside a quoted value; a tab in leading whitespace is an error; duplicate keys at one level are an error; booleans are the six bare literals `true/True/TRUE/false/False/FALSE` (`config.go:1755-1759`) and any other spelling — `yes/no/on/off/1/0`, or a quoted `"true"` — stays a string and is a load error through `getBool`/`assignBool` (`:1909-1939`); numbers stay raw strings converted at the point of use (`getInt`/`getFloat`/`getDecimal` return `(0, false)` on a malformed value, `:1790-1793`, `:1857-1860`, `:1872-1883`), and most call sites discard that `false`, so a malformed value silently becomes its zero value — a malformed `budget_usd` means an unlimited key (`:1072`; zero-means-unlimited at `:341-342`), a malformed optional `cache_read_per_token`/`cache_creation_per_token` is silently dropped (`:1516,1522`) — except that a present-and-malformed `price_table.*.prompt_per_token`/`completion_per_token` (`:1498-1505`) or `rate_limit.tpm_accounting.output_token_multiplier` (`:2097-2104`) is a load error; a key containing `:` must be quoted; a line indented deeper than a preceding scalar is silently attached to that scalar's parent (`config.go:1589-1666,1668-1676,1701-1731,1733-1762,1764-1939,2097-2104`). List-shaped fields are mappings of name → `true` (`config.go:1095-1148`) or, for `fallback_chains.<class>`, a comma-separated string split at `:1983` (`:1978-1988`). Required: `listen_addr` (no default, no loopback default; the example binds all interfaces, `:1054-1057`, `gateway/config.example.yaml:11`), at least one `virtual_keys` entry with a non-empty `key_hash` whose 64-hex shape is checked only by `identity.NewVerifier` at real startup (`config.go:1058-1071`, `gateway/internal/identity/identity.go:299-306`), at least one deployment with `model/provider/upstream_model/base_url` and `api_key_env` or `api_key_file` (bedrock: `access_key_id_env|_file`, `secret_access_key_env|_file`, `region`; `config.go:1162-1219`); `base_url` must be `https` unless `allow_insecure_http: true` (`config.go:1191-1195`); the OpenAI-compatible provider key is exactly `openaicompat` (`gateway/cmd/gateway/main.go:1335`) and the example file has no such deployment to copy (`config.example.yaml:186`).
6. **An unpriced model silently costs $0.** `costaccounting.Calculator.Calculate` returns zero for a model absent from `price_table` with no log, warning or metric, and no load-time or `-validate` check covers price-table coverage of deployment models (`gateway/internal/costaccounting/costaccounting.go:59-63,96-100`, `config.go:1492-1545`, `docs/reference/config.md:218`) — so a generated config without prices would make every budget a no-op.
7. **`-validate` is narrower than startup, and its checks live in `package main`.** `-validate` runs `Load` + `validateConfig` (provider ∈ the adapter registry's fixed map, fallback-chain targets exist) and prints exactly `config is valid` (`main.go:390-402,1329-1371`); admin tokens, propagation signing secrets, the telemetry exporter name, key-hash shape and PEM paths are checked only in `run()`/`buildPipeline` (`main.go:574-580,647-670,1636-1647`, `docs/reference/config.md:462-480`). `validateConfig` is unexported, so a second binary cannot call it (`main.go:1351`). No test, script or workflow asserts the literal `config is valid`: `release.yml:190-191` and `scripts/bench-ci.sh:154` check only the exit code.
8. **Keys: SHA-256-hex secrets, no expiry, seven threading sites, JSON-persisted.** The hash is `hex(sha256(secret))`, lower-cased 64 hex (`identity.go:299-308,326-327`); the documented recipe is `openssl rand -hex 32` + `sha256sum` (`config.example.yaml:13-19`, `README.md:45-52`). `VirtualKey` has no whole-key expiry — only `PreviousKeyHashExpiresAt` bounds the old hash during rotation, and that expiry is folded into `ErrInvalidKey` (`identity.go:162-177,320-344`). A new key field must be threaded through: `VirtualKeyConfig` + its parse (`config.go:428-432,1153-1157`), `buildPipeline`'s copy (`main.go:984-999`), the admin request and list entry (`admin.go:107-111,715-727,1008,1036`), `configpropagation.VirtualKeyPayload` (`configpropagation.go:235-275`), both dataplane conversions (`dataplane.go:1430-1470`, which are on the persistence path for receiving replicas, `:1418-1420,1597-1606`), and `identity` itself — the five-site experience of 13a plus the check. Both stores persist `json.Marshal(VirtualKey)` and decode missing fields to zero, with no test for a legacy record (`boltstore.go:8-13,93-109`, `redisstore.go:74-87`). `errorStatus` maps the two identity sentinels to 401 and a new sentinel would otherwise fall to 502 (`main.go:2122-2129`); `errorTypeAndCode` gives `invalid_api_key` (`gateway/cmd/gateway/error_envelope.go:196-202`); `outcomeFor` buckets them as `OUTCOME_AUTH_FAILED` (`dataplane.go:4980-4986`); `error_envelope_test.go:56-82` (`TestWriteErrorResponseEnvelopeTable`; rows at `:65-81`, the two identity rows at `:65-66`) is the table that pins every sentinel. A persisted admin mutation beats `config.yaml` on restart (`main.go:1490-1515`, `docs/how-to/virtual-keys-and-budgets.md:176-179`); there is no offline primitive that edits a key — `backup.Restore` swaps a whole bbolt file against a stopped gateway (`gateway/internal/backup/backup.go:13-24,102-168`) — and key mutations are pushed live to already-running replicas through `configpropagation` events (`configpropagation.go:24-26`) — Redis pub/sub, fire-and-forget, no replay or catch-up (`configpropagation.go:12-14,352-357`; `dataplane.go:1849-1850`) — which an offline edit would bypass entirely, leaving running replicas stale until their own restart. `BudgetUSD` ≤ 0 means unlimited (`identity.go:54-57`, `budget.go:533-537`).
9. **Admin reads a CLI needs that do not exist.** The list route carries no spend, so `keys list --spend` is 1 + N today (`admin.go:1066-1076`); the per-key spend body is `{spent_usd, budget_usd, budget_reset_interval_seconds, percent_used}` with no next-reset timestamp, and the live window start has no in-process accessor (`admin.go:984-989`, `gateway/internal/budget/budget.go:57-62,337,999-1001`); the only deployment route is `POST .../weight`, and the router exposes `IsHealthy`/`SetWeight`/`SetLatencyFactor` but no getters (`admin.go:275`, `gateway/internal/router/health.go:234,357`, `router.go:187`). Tiers: list is Admin-or-Viewer; per-key spend is the only route CostViewer can call; Operator can read nothing (`admin.go:218-304`; Operator is accepted only by `requireAdminOrOperatorBearerToken`, `:415-420`, used on exactly three POSTs, `:225,275,280`). The admin listener defaults to `127.0.0.1:8081` when `token_env` is set and `listen_addr` is empty, and does not start at all without `token_env` (`main.go:186-191,645-692`); tokens are env-var names only, read once at startup (`config.go:777-817`, `main.go:647-671`).

## Detailed Design

### Decisions this RFC settles

1. **Second shipped binary `kelvran`, in the same module, shipped inside the gateway's artifacts (G30).** `gateway/cmd/kelvran/main.go` is a thin dispatcher in the kelvran-bench shape — `switch os.Args[1]` for the top level, a second `switch` inside `keys`, one `flag.NewFlagSet` per leaf command, usage to stderr with exit 2, `kelvran: <err>` to stderr with exit 1, results to stdout, `--json` on every read verb for scripting.    **Offline** (`--config <path>`, the single-user case where no admin listener exists) rewrites the `virtual_keys.<name>` block of the YAML file as a text operation that preserves every other byte, defined in the parser's own terms so the writer cannot diverge from `parseYAMLMini` (fact 5):
   - Line classes: each line is classified exactly as `config.go:1600-1603` does — `stripYAMLComment`, right-trim ` \t\r`, blank ⇒ comment/blank line; otherwise a content line whose indent is its count of leading spaces (a leading tab is rejected as `Load` rejects it, `:1620`).
   - Section: the unique content line at indent 0 whose key after `unquoteYAMLScalar` (as `config.go:1635` applies it) is `virtual_keys` and whose value is empty. A `virtual_keys` string inside a comment, at indent > 0, or with a value is never the section (`config.example.yaml:336` has one inside a comment); zero or more than one such line is an error. Entry indent E = the indent of the first content line after the opener with indent > 0 — read from the file, never assumed to be 2 or 4, because the parser accepts any deeper indent (`config.go:1627-1630`); an entry is the content line at exactly E whose unquoted key equals the name.
   - Extent: from the entry line through the last content line before the next content line with indent ≤ E (or EOF). Comment and blank lines strictly inside that span are removed with the block on `delete` (the parser never sees them, so they belong to the entry textually); comment lines immediately above the entry line and any blank/comment lines after the span are kept byte-for-byte. `rotate` replaces only the value token of the `key_hash:` content line inside the span — the first whitespace-delimited token after the colon — leaving colon spacing and any trailing `# …` comment bytes intact. `create` inserts the new entry immediately after the last content line of the whole block, before any trailing blank/comment lines (so column-0 commentary that introduces the next section, as at `config.example.yaml:130-167` before `deployments:` at `:168`, stays attached to it), at indent E (2 if the block is empty), writing `key_hash` and only the non-default ones of `budget_usd`, `budget_reset_interval_seconds`, `budget_warn_percent`, `allowed_models`, `billing_subject_id`, `expires_at` (`config.go:1068-1149`).
   - Names: refuse a name the subset cannot represent or silently re-spells — containing `#`, a newline or `\r`, leading/trailing whitespace, empty, or beginning and ending with the same quote character (`stripYAMLComment` runs before quote handling, `:1600,1671-1676`, so quoting does not rescue `#`; `unquoteYAMLScalar` has no escape handling, `:1723`) — pointing at the online path; double-quote a name containing `:` or whose first byte is `"`/`'` (the only spelling `findKeyColon` protects, `:1701-1731`); bare otherwise.
   - Safety check, semantic rather than syntactic: `Load` the ORIGINAL first — refuse if it fails (never edit a file the gateway cannot read) and, for `create`, refuse an existing name unless `--replace` (offline `--replace` = delete + append), so the duplicate-key `Load` error is never the user-facing message. After writing the candidate, `Load` it and require every `Config` field except `VirtualKeys` to be deep-equal to the original's, and `VirtualKeys` to equal the original's ± exactly the intended delta (create: plus `{name → intended key}`; rotate: identical except `[name].KeyHash`; delete: minus `name`); refuse on any mismatch. This fails closed on every parser quirk — including a name `Load` accepts but re-spells — without enumerating the grammar; "Load succeeds" alone is necessary but, because comments are stripped at `:1600`, not sufficient.
   - Atomic, mode- and owner-preserving write: resolve `--config` with `filepath.EvalSymlinks` and operate on the target (a symlinked `/etc/kelvran-gateway/config.yaml` keeps its symlink); `os.Stat` it for `Mode().Perm()`, uid and gid; `os.CreateTemp` in the target's directory (Go opens it `0600`, so the next step is mandatory), write, `Sync`, `Close`; `os.Chmod(tmp, original.Mode().Perm())`; when the original uid/gid differ from the process's, `os.Chown(tmp, uid, gid)` in a `_unix.go` file (no-op on Windows) and treat `EPERM` as a refusal; remove the temp on every error path as `backup.Restore` does (`backup.go:148`); only then `os.Rename`, then fsync the directory. **Never apply a fixed `0o600` to an existing config**: `backup.Restore`'s `os.Chmod(tmpPath, 0o600)` (`backup.go:163`) is right for a bbolt store and wrong for this file — the packaged unit runs as `DynamicUser=yes` and its `ExecStartPre … -validate` runs as that random uid (`deploy/systemd/kelvran-gateway.service:24,28`), so `config.yaml` must stay world-readable (`docs/how-to/deploy/systemd-package.md:77`, `docs/operations/DEPLOY.md:51`; the file holds hashes and variable names, never a secret). After writing, if the result is under `/etc/kelvran-gateway/` and lacks `o+r`, print the warning `doctor` emits for the same condition (decision 7).
   - Caveats printed: always, "takes effect on the next gateway start"; and only when the loaded config has `admin.persist_path` or `admin.redis_addr` set — the two-case condition at `main.go:1049-1077` (Redis wins and warns when both are set) and `docs/how-to/virtual-keys-and-budgets.md:176` — "if `<name>` was ever created, rotated or deleted through the admin API, the persisted store (`admin.redis_addr <addr>` / `admin.persist_path <path>`) overrides this file for it on restart (`main.go:1490-1515`)". Without either, `identityStore` is nil, `mergePersistedVirtualKeys` never runs and admin mutations are in-memory no-ops on persistence (`dataplane.go:1598-1600,1612-1614`), so the file is authoritative and an unconditional caveat would teach users to ignore it; in the `admin:`-present-but-no-store case print instead "this gateway has no admin.persist_path/redis_addr; keys changed through the admin API are in-memory only and this file wins on restart".
   - Offline `rotate` is a **hard cut** effective at the restart that picks up the file: `VirtualKeyConfig` has no `previous_key_hash` field (`grep previous_key_hash` over `config.go` finds none; `main.go:984-999` builds file keys with a single hash), so no grace period is expressible offline; `--grace` is rejected offline with that message and the fact is printed as a third caveat. Offline `rotate` of an entry whose parsed `expires_at` is in the past refuses unless `--expires` is given, rewriting both values in the same pass (decision 4).

   Editing bbolt/Redis offline is rejected: no primitive exists, the stopped-gateway requirement is a trap for a laptop user, and an offline store edit emits no `configpropagation` event, so running replicas would not learn of it until restart (`configpropagation.go:24-26,352-357`).

4. **Whole-key expiry: `expires_at`, absolute RFC 3339, 401 `key_expired` (G31).** `identity.VirtualKey.ExpiresAt time.Time` (zero = never). Wire spellings: YAML `expires_at: "2026-12-31T00:00:00Z"` (a new `getTime` helper in `controlplane`, RFC 3339 only, load error otherwise, so `-validate` catches it — the first timestamp the loader parses, `config.go:1764-1953`; a *past* value is accepted by `Load`, so a gateway restarts with an expired key rather than refusing to start); admin request field `ExpiresAt string` tagged `json:"expires_at"` (string-typed like every other `virtualKeyRequest` field, `admin.go:88-112`): absent, `""` and `null` all mean never expires (the full-replace rule, `admin-api.md:173`); a non-empty value is parsed with `time.Parse(time.RFC3339, …)` and a failure is 400 `expires_at %q is not a valid RFC 3339 timestamp: %v` — the exact shape `GET /admin/audit` already uses for `since`/`until` (`admin.go:518-528`, `admin-api.md:143`) — and a value not after the server's `time.Now()` is 400 `expires_at must be in the future` (a non-string JSON value is already 400 `invalid request body: …` through the decoder path, `admin.go:603-606`, `admin-api.md:220`); the list entry emits `expires_at` as RFC 3339, omitted when zero. The plan's `virtualKeyRequest.expires_at_unix` spelling (plan `:219`) is not used — see Alternatives. The past-value check lives **only** in the admin handler: `Load`, both stores and the propagation apply path (`dataplane.go:1430-1470`) accept past values unchanged, so replicas and persisted records never diverge from the leader; the consequence is that re-upserting an already-expired key with its stored value is a 400 — set a future `expires_at`, omit it (un-expiring the key), or `keys delete`. **Propagation payload**: `ExpiresAt *time.Time` tagged `json:"expires_at,omitempty"`, with `virtualKeyToPayload` ALWAYS setting a non-nil pointer (to the zero time when the key never expires), so the member is always on the wire from a new sender and `nil` after decode means "the sender predates the field"; `ApplyVirtualKeyUpsertFromEvent`/`payloadToVirtualKey` (`dataplane.go:1452-1470`) then carry forward the local verifier's current `ExpiresAt` for that id instead of writing zero. This is necessary because `MutationEvent` carries no schema or field-set version (`configpropagation.go:153-160`; adding one is rejected — outside `signingInput`, `:171-173`, it is unauthenticated, inside it every older replica's `verifyEvent` rejects every event for the rollout's duration) and the apply path persists what it receives (`persistVirtualKeyIfStoreConfigured` at `dataplane.go:1350`), so without the carry-forward an old replica's ordinary `RotateVirtualKey` would durably erase a key's expiry in the shared store. `omitzero` (available at `go 1.26.9`, `gateway/go.mod:3`; `omitempty` does not omit a zero `time.Time`, `configpropagation.go:265-266`) is kept only for the admin JSON, where "omitted when zero" is the intended public contract. The code-side hardening is partial: an older replica never *enforces* `expires_at` and, when it itself upserts or rotates such a key, re-persists it without the field. ## Drawbacks

- A second binary doubles the acceptance surface and every archive grows by one static binary. For scale: the gateway binary accidentally committed in abcc1a4e was 36 MB, an unstripped `go build` (`.gitignore:66`); a stripped `-trimpath -ldflags "-s -w"` build of `./cmd/gateway` (the flags `.goreleaser.yaml:36,38` ship) measured 26,043,762 bytes on darwin/arm64 on 2026-10-09, with 527 packages in `go list -deps`. The CLI binary's size is unmeasured — it does not exist yet — and will be smaller, since its `mayDependOn` set (`adminapi`, `controlplane`, `identity`, root `adapter`, `telemetry-exporterkind`) links neither `dataplane` nor the OTel, gRPC, AWS SDK, bbolt or redis trees; it is measured once `cmd/kelvran` exists. `docs/VERSIONING.md` gains a CLI public-surface row that then binds future changes to the verbs and flags.
- `init` embeds a price table that goes stale; the as-of comment and `doctor`'s coverage check make staleness visible but not self-healing. Refusing unknown models without `--price` trades convenience for not silently disabling budgets.
- Offline `keys` edits are text surgery on a file format with no serializer; the semantic re-`Load` check before write bounds the damage, but a hand-formatted file may be rewritten less prettily than its owner wrote it.
- `expires_at` is one more field threaded through the seven sites fact 8 lists (plus the rotate body), and the admin upsert's full-replace semantics now have one more field to forget; the `--replace`/`--force` guard on `keys create` and the rows in the admin reference are the mitigations, not a fix of the upsert model. Its rollout is order-sensitive: until every replica sharing an identity store runs a build with the field, an older replica neither enforces nor preserves an expiry it rewrites (decision 4); the mitigation is documentation plus the receive-side carry-forward, not a wire version.
- A sequence departure (Status): the plan puts RFC-3 + Stage 1 after 11 core and 13c and marks `connect claude` useless without 11; `connect claude` is honest about `/v1/messages` not existing, which is a worse first impression than not shipping it. The alternative (ship nothing until item 11) was judged worse because `init` + `connect` is the one-command story the report measured competitors by — G32 lets the owner defer it.
- `init` never persists a secret, so team mode has one manual step between `init` and the first gateway start — exporting the printed `KELVRAN_ADMIN_TOKEN`; the CLI reads the same variable (decision 3), so no second step exists. Single-user mode has none (no `admin:` section; `keys` is offline). The printed exports leave the secrets in shell history unless the user takes the file route `init` also names.
- `doctor`'s `*_env` findings are only as truthful as the environment it can see; without `--env-file`, a container or systemd deployment gets warnings, not errors, by design (decision 7).
- Moving `validateConfig` and the admin body types is churn in two files that have been stable; the moves are mechanical apart from the one-parameter retype in `Validate`, and pinned by existing tests.
- `connect claude --scope project` shells out to `git` for its ignore check — a soft runtime dependency no other verb has.

## Alternatives Considered

- **CLI subcommands inside the gateway binary** (round-4 report open question 6, `round4 report:255`; settled the same way by plan item 12, plan `:215`): rejected — `cmd/gateway` is flag-only (`main.go:358-365`); grafting a dispatcher onto it changes the public flag surface `docs/VERSIONING.md:30` protects, and a user who only wants the client would download the server.
- **Separately named `kelvran_*` archives and a `kelvran-cli` package**: rejected — four glob edits plus the checksums-scope mismatch (fact 2) for no user benefit; the gateway package is the natural home for its own admin client.
- **cobra/kong**: rejected — not in `go.mod`, a two-level tree does not need them, and kelvran-bench already set the stdlib shape.
- **Offline `keys` editing bbolt/Redis directly**: rejected (decision 3).
- **TTL seconds on the admin wire for expiry** (the `grace_period_seconds` precedent, `admin.go:120-123,800`) **and the plan's `virtualKeyRequest.expires_at_unix` epoch integer** (plan `:219`): both rejected for the stored field. A TTL re-sent on retry drifts; the CLI converts relative input client-side instead. An epoch integer does not drift, but every absolute instant the admin plane already emits or accepts is an RFC 3339 string (`time`, `admin.go:496`; `created_at`, `:1168`; `updated_at`, `:1335`; `since`/`until`, `:518-528`), every integer-seconds field on both planes is a duration (`budget_reset_interval_seconds`, `grace_period_seconds`), one `time.Time` then serves `getTime`, the admin JSON and the propagation payload with no int64 conversion at either end, `expires_at` as a string keeps the admin body mirroring the YAML field name (`admin.go:82-87`) and is readable in a hand-edited single-user `config.yaml`, where an epoch integer is not — and in YAML an integer would have been accepted by `getInt` with no shape check, whereas RFC 3339 fails `-validate` on a malformed value.
- **Folding expiry into `ErrInvalidKey`** as rotation grace does: rejected — a distinct code tells the key's owner what to do. Trade-off accepted and recorded: `key_expired` also tells anyone else presenting a leaked, expired secret that it was once a real Kelvran key — a small confirmation oracle; accepted because the secret is unusable, `insufficient_quota`/`model_not_allowed` already confirm live keys, the key's id is never placed in the client envelope (decision 4), and the rotation-grace path keeps folding into `invalid_api_key`. 401 is kept because an expired key fails authentication the same way `invalid_api_key` does (same `Verify` lookup, `identity.go:329-342`). The admin plane has no 403 at all — every failure, including a valid credential of an insufficient tier, is 401 (`admin.go:316-320`; `docs/how-to/admin-api-rbac.md:193`). The data plane has exactly one 403, `ErrModelNotAllowed`/`ErrSourceIPNotAllowed` → `http.StatusForbidden` (`main.go:2153-2154`), envelope `permission_error` with `model_not_allowed`/`source_ip_not_allowed` (`error_envelope.go:213-216`, pinned at `error_envelope_test.go:71-72`), raised only after `Verify` has already accepted the key (`dataplane.go:3233-3246`) — an authorization decision about an authenticated key, which an expired key never reaches, so `key_expired` belongs with the 401s.
- **A `SpanProcessor`/`pkg/` client library**: out of scope; `adminapi` stays `internal`.
- **`init --write-secrets <dir>`** (`0o600` token/key files written by `init`): rejected — a second secret location to back up and rotate, when the env route is what the gateway (`main.go:646-649`) and every admin how-to already use; the no-secret-on-disk-by-default rule stays.
- **A schema or field-set version on `MutationEvent`** for `expires_at`'s rollout: rejected (decision 4) — outside `signingInput` it is unauthenticated; inside it, every older replica rejects every event for the rollout's duration.
- **Doing nothing**: the first run stays a nine-step manual procedure the report's ground truth already marks as the adoption blocker.
