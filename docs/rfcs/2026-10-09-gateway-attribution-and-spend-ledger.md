## Summary

**13a.** Every data-plane request gains a bounded, gateway-derived attribution record: the client tool normalised from `User-Agent` into a thirteen-value vocabulary, and whatever `x-claude-code-*` headers Claude Code sent — the session id, which arrives on every request; the agent and parent-agent ids, which arrive without the hint flag but only on requests issued by a subagent (the parent-agent id only for nested agents; protocol page header table, line 59); and the bounded hint headers that arrive only when the developer sets `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` on Claude Code ≥ v2.1.273 (`-prompt-id` ≥ v2.1.283; protocol page lines 63 and 70). A shared middleware wrapping the mux captures them once, caps and validates every value, and places them on the context through a private-key carrier in the telemetry leaf (`telemetry.WithAttribution` / `AttributionFromContext`); `finalize` reads the carrier the way it reads `AgentRunIDFromContext` today. Bounded values become span attributes and metric dimensions; identifiers become span attributes only, never a metric label, never a log field, never a cache-key, guardrail, routing or admission input. Identifier capture is on by default behind a global and a per-key switch (gate G14, the owner's call). No `api/` change (gate G13 default).

**13d.** A new leaf `internal/spendledger` keeps hourly, UTC-aligned spend buckets keyed by (virtual key, served model, client tool, session), written from `finalize` under the exact `billable` gate that already feeds `kelvran.llm.spend_usd`, bounded (at most 2,000 live sessions per key per retention window, the rest folded into `other`), retained 7 days, persisted either to its own bbolt file or to Redis hashes when the budget already lives in Redis. `GET /admin/spend?group_by=key|model|tool|session&key=&since=&until=` reads it; `DELETE /admin/virtual_keys/{name}` erases a key's rows; `POST /admin/spend/erase` erases one session. The decision-event stream to Vector and the evals remains the long-retention path; the ledger is the gateway's own seven-day answer to "who spent what".

## Motivation

- **Attribution stops at the virtual key.** The three public handlers read exactly four request headers themselves — `Authorization`, `X-Kelvran-End-User-Id`, `Idempotency-Key` and, through the propagator, `traceparent`/`baggage` (`gateway/cmd/gateway/main.go:2001-2011`, `:2098-2105`, `:2065-2066`; `models_handler.go:96`). No non-test Go file reads `User-Agent` or any `x-claude-code-*` header. The one per-run identifier that reaches `finalize` is the `agent_run_id` W3C Baggage member (`gateway/internal/telemetry/telemetry.go:928-933`), which a client must know to send. Claude Code, by contrast, sends `x-claude-code-session-id` on every request to any base URL, `-agent-id` and `-parent-agent-id` on subagent requests (flag-independent; the parent id only for nested agents), and the hint headers (`-request-class`, `-agent-type`, `-prompt-id`, `-compaction`, `-context-compacted`, `-prev-tool-durations`) when `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` is set — "the rest the gateway may consume for routing, attribution, and tracing, and need not forward" (protocol page, lines 58-77). LiteLLM already tags spend with the `User-Agent` product token by default (round-4 report, line 161).
- **Spend has one dimension.** `kelvran.llm.spend_usd` is a `Float64Counter` with zero attributes (`telemetry.go:670-685`), recorded at two sites (`gateway/internal/gateway/dataplane/dataplane.go:4772-4775` under `billable`; `:3343-3345` for embeddings). The budget tracker is keyed by virtual key alone (`gateway/internal/budget/budget.go:435`, `:474`, `:972`), the only spend route is `GET /admin/virtual_keys/{name}/spend` (`gateway/internal/admin/admin.go:227-232`), and the 2026-09-12 cost-attribution RFC deferred any group-by beyond a single `--agent-run-id` in the evals (`docs/rfcs/2026-09-12-gateway-cost-attribution-aggregation.md:67`). Round-4 lane 4 recorded the gap plainly: "no group-by spend pivot (key × model × tool)" (report line 162).
- **Prior verdicts stand.** The cost-attribution RFC rejected any agent-run identifier as a metric dimension — "real cardinality risk … that every other metric in this codebase deliberately avoids" (`:62`) — and the cache-savings RFC kept `kelvran.cache.savings_usd` dimensioned by layer only (`docs/rfcs/2026-09-12-gateway-cache-savings-agent-attribution.md:25`). This RFC keeps that rule: identifiers go on spans and into the ledger, never on a metric. The request-log-store RFC (design-only, deferred pending a trigger that has not fired as of 2026-10-09; `docs/rfcs/2026-09-25-gateway-request-log-store-design.md:5`) established that no bbolt store in the codebase has a retention sweep and that a store written at proxied-traffic volume needs a max-age bound (`:210`, `:224`); it pointed at the `BudgetResetIntervalSeconds` idiom, whose zero means never-expiring (`:224-228`) — the ledger is the first store to carry such a bound, and it deliberately departs from that zero rule (see Ledger bounds below). `DECISIONS.md:279` records that `agent_run_id` is "trivially spoofable by rotating the value per request" and therefore never gates admission; the same holds for every header here.

## The facts that shape the design

1. **A cross-route capture point exists.** The data server's handler is `trackInFlight(&inFlight, wrapHTTPServerSpan(mux))` (`main.go:630`), where `wrapHTTPServerSpan` is `otelhttp.NewHandler(handler, "gateway.http")` (`:902-904`). That wrapper already extracts both `traceparent` and `baggage` for every route (otelhttp v0.71.0 `handler.go:98`) — with the propagator captured once at construction (`config.go:55`, `otel.GetTextMapPropagator()` in `newConfig`), so the extraction is complete only because `telemetry.Init` (`main.go:574`) installs the composite propagator before the server is built at `main.go:630`; 13a's tracing test constructs the handler through the same path (`Init` first), and the removal of the per-handler calls below is conditional on that ordering being preserved — starts the `gateway.http` server span (`handler.go:127`), threads its context to the handlers (`handler.go:184`), and already sets `user_agent.original` and `client.address` on that span. The per-handler `telemetry.ExtractContext` calls at `main.go:2001`, `:2065`, `:2104` (`telemetry.go:924-926`) are redundant for Baggage but NOT for TraceContext: when a client sends `traceparent`, `TraceContext.Extract` (otel v1.46.0 `propagation/trace_context.go:72-78`) replaces the server span context in ctx with the client's remote one, so the `chat <model>` span (`dataplane.go:3485`, `streaming.go:168`) is parented to the client's span instead of `gateway.http`, contrary to `main.go:892-894`'s own doc. 13a removes the three calls and adds a test asserting that `chat <model>`'s parent is `gateway.http` when a `traceparent` is present. `user_agent.original` need not be duplicated onto the `chat <model>` span.
2. **Two carrier precedents, one of them wrong for this.** `agent_run_id` is a Baggage member read by `AgentRunIDFromContext` (`telemetry.go:931`); there is no setter, and the composite propagator is installed unconditionally (`:834-837`). Baggage is a propagation mechanism: anything placed in it travels with the context, and although outbound upstream calls inject nothing today (no `Inject` call exists; `main.go:352-353`, `:1296-1312` build plain clients), the first `otelhttp.NewTransport` would forward it to providers. The dataplane's own precedent for gateway-internal context state is a private-key value (`gateway/internal/gateway/dataplane/overhead.go:8-39`: `type overheadContextKey struct{}`, nil-safe accessor). The telemetry package has no `context.WithValue` key yet and imports nothing from the module (`telemetry.go:18-39`, the import block: stdlib and `go.opentelemetry.io/*` only — the dataplane path at `:50`/`:84` is an instrumentation-scope string, not an import; `dataplane.go:4708-4711` calls it a "dependency-free leaf").
3. **The streaming branch forks before the buffered path's context work.** `if req.Stream {` (`main.go:1996-1999`) precedes `ExtractContext` at `:2001`; `handleStreamingChatCompletion` builds its own context at `:2104`. A capture placed in one handler body misses the other; the mux wrapper misses neither.
4. **Embeddings have no span and no `finalize`.** `HandleEmbeddings` records `RecordLLMSpend` directly (`dataplane.go:3343-3345`) and logs its own line (`:3403-3437`); attribution for embeddings must be read from the context at that site.
5. **Metric cardinality is bounded by construction today.** `gen_ai.client.operation.duration` carries six attributes (`telemetry.go:483-506`, including `kelvran.fallback.outcome`); `kelvran.virtual_key.id` already dimensions `kelvran.ratelimit.fail_open`, `kelvran.streaming.cost_estimated` (`:247-249`) and `kelvran.fallback.rescued`; the model attribute is sentinelled to `unresolved` when no deployment resolved (`dataplane.go:4675-4683`) and model strings are cut at 256 bytes (`:5099-5109`).
6. **Config conventions.** Per-key booleans use `assignBool` (loud on a non-bool, silent default when absent; `config.go:1871-1902`, precedent `cache_scope_to_end_user` at `:1135-1137`); optional top-level sections use `getMap` (`:1257-1260`); the mini-YAML parser has no list support (`:1551-1558`); unknown keys are ignored everywhere except inside `models:` entries (`:1494-1512`); closed string vocabularies are validated with `switch`/`default` (`:1241`). A per-key bool flows through five sites, not one — `cache_scope_to_end_user` today: YAML (`config.go:427`, `:1135`), the `main.go:995` copy from `controlplane.VirtualKeyConfig` into `identity.VirtualKey`, the admin upsert request and list response (`admin.go:106`, `:720`, `:1002`, `:1029`), the propagation payload (`configpropagation.go:271`) and the `identity.VirtualKey` ↔ payload conversions (`dataplane.go:1439`, `:1459`). Both `assignBool` and JSON decoding preserve the Go zero value, so a default-true bool cannot be expressed by a positive-sense field without seeding it at every one of those sites.
7. **The log line carries no identifiers at the top level.** `logRequest` (`dataplane.go:5142-5183`) emits `trace_id`, `span_id`, `model`, cache fields, `virtual_key_id`, token counts, cost and the `gatewayevents_v1` JSON string; `agent_run_id` appears only inside that string.
8. **Erasure today.** `DELETE /admin/virtual_keys/{name}` (Admin-only, `admin.go:220`, `:747-770`) runs `applyVirtualKeyDeleteLocked` (`dataplane.go:1677-1716`): verifier swap, identity-store delete, `budget.Delete(name)` — which in Redis mode `DEL`s the key's spend, alert and warn-alert hashes (`gateway/internal/budget/redisbudget/redisbudget.go:453-458`) and in bbolt mode deletes the row (`budget.go:972-993`); `DeleteVirtualKey` then publishes `virtual_key_delete` (`dataplane.go:1649`) and every replica runs the same locked body on receipt (`:1669-1673`). Cache erasure is per replica with no propagation event (`dataplane.go:2115-2145`; `docs/operations/DATA-SUBJECT-REQUESTS.md:99-115`). `configpropagation` has exactly three event types and `cmd/gateway`'s switch silently drops unknown ones (`configpropagation.go:81`, `:229`, `:233`; `main.go:770-811`).
9. **Admin conventions.** Tiers are per-route middleware (`admin.go:308-445`); CostViewer authenticates exactly one route (`:227-232`); the only query-string parser is `GET /admin/audit` (`:505-547`) and nothing clamps a result set; errors are plain text, never a JSON envelope (`docs/reference/admin-api.md:16`); successes go through `writeJSONResponse` (`admin.go:1171-1176`) except `GET /admin/config` and `GET /admin/audit`; money is a decimal string; no admin route bounds its request body (`main.go:686-699`). The audit trail must never carry spend figures (`docs/reference/admin-api.md:561`).
10. **Stores.** Three bbolt stores open with `Options.Timeout = 1 s` and wrap `ErrTimeout` (`gateway/internal/budget/boltstore/boltstore.go:58-80`); `openPersistStoreWithRecovery` is generic (`main.go:1453`); `BackupStores` copies every `backup.DBBacked` candidate as `<kind>-<stamp>.bbolt` (`dataplane.go:1144-1172`); `kelvran.persistence.failed` takes `store_kind` ∈ {`budget`, `identity`} (`telemetry.go:728-747`); `BudgetConfig.RedisAddr` wins over `PersistPath` with a warning (`config.go:512-517`); Redis budget values are nano-USD integers (`budget.go:167-181`), keys `budget:<QueryEscape(key)>` with a once-per-window `PEXPIRE` (`redisbudget.go:85-101`, `:317-318`). No code anywhere folds overflow into an `other` bucket; `anomaly.Detector.perKey` is unbounded (`gateway/internal/anomaly/detector.go:29-56`).

## Detailed Design

### Decisions this RFC settles

| Question | Decision |
|---|---|
| Carrier | `telemetry.Attribution` (plain `string`/`int` fields), `telemetry.WithAttribution(ctx, a) context.Context` and `telemetry.AttributionFromContext(ctx) Attribution` over a private key type, set once by a mux-level middleware; never Baggage (would propagate upstream the day an outbound transport injects), never a handler parameter (that pattern is reserved for admission-affecting inputs such as `X-Kelvran-End-User-Id`) |
| Capture point | `captureAttribution(next http.Handler)` wrapped around the mux inside `trackInFlight` and outside `wrapHTTPServerSpan`, so chat (buffered and streaming), embeddings, models and any future ingress are covered once; the per-handler `ExtractContext` calls are removed (fact 1: otelhttp already extracts, and the second extract re-parents the `chat <model>` span to the client) |
| `User-Agent` | The first whitespace-delimited token (≤ 64 bytes, printable ASCII), split at its first `/` into a product and a trailer; the product is matched case-insensitively after stripping a leading `Async` and then a leading `Azure`, and for the Stainless-generated SDKs the first word of the trailer selects the language (`OpenAI/Python 3.14.1` → `openai_python`); normalised into `kelvran.client.tool` ∈ {`claude_code`, `openai_python`, `openai_node`, `openai_go`, `anthropic_python`, `anthropic_node`, `anthropic_go`, `codex`, `aider`, `continue`, `litellm`, `curl`, `other`}; the mapping table is code, extended only by a commit; unknown or malformed → `other`; the raw token is not stored (the `gateway.http` span already has `user_agent.original`) |
| Identifiers | `x-claude-code-session-id`, `-agent-id`, `-parent-agent-id`, `-prompt-id`: ≤ 128 bytes of `[A-Za-z0-9._:-]`; anything else is dropped (absent), never truncated into a different identifier. The page does not specify the identifier alphabet (only `-prompt-id` is documented as a UUID, line 70; teammate agents "reuse a stable name-based ID", line 60, with no encoding given), so the set is pinned from a dedicated 13a live capture, not RFC-1's `claude -p` step (a single non-interactive prompt spawns no subagent and no teammate, so it can never carry an agent id): an interactive Claude Code session against the gateway that spawns a subagent and runs an agent-team teammate, executed once with `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` and once with the variable unset, recording every `x-claude-code-agent-id` / `-parent-agent-id` value seen — the same capture settles the implementation question below. A value outside the set increments a bounded `kelvran.attribution.dropped{header=<name>}` counter so silent loss is visible |
| Bounded hints | `-request-class` ∈ {`main`, `subagent`, `workflow`, `compaction`, `auxiliary`}, `-compaction` and `-context-compacted` ∈ {`auto`, `manual`, `reactive`} — any other value → `other`; `-agent-type` is an open set on the page (built-in names, `custom`, `teammate`, `fork`), so it is kept as a span attribute capped at 64 bytes and is **not** a metric dimension |
| `-prev-tool-durations` | Parsed per the page's encoding (split `;` then `=`, percent-decode names, ≤ 32 entries, ≤ 4 KB, first entries kept); stored as two bounded span attributes, `kelvran.claude_code.prev_tool_count` (int) and `kelvran.claude_code.prev_tool_total_ms` (int), plus the raw header ≤ 4 KB as `kelvran.claude_code.prev_tool_durations`; absence is not "no tools ran" |
| Span attributes (`chat <model>` span) | `kelvran.client.tool`; `kelvran.claude_code.session_id`, `.agent_id`, `.parent_agent_id`, `.prompt_id`, `.request_class`, `.agent_type`, `.compaction`, `.context_compacted`, `.prev_tool_*` — each only when present |
| Metric dimensions (bounded only) | `kelvran.llm.spend_usd` gains `kelvran.virtual_key.id`, `kelvran.client.tool`, `kelvran.claude_code.request_class`; `gen_ai.client.operation.duration` gains `kelvran.client.tool` and `kelvran.claude_code.request_class` (via its own attribute slice, like `kelvran.fallback.outcome`); no identifier ever becomes a metric label. Departures from the plan's 13a text: `agent_type` is not a dimension (open set on the page, span-only); `kelvran.virtual_key.id` goes on `kelvran.llm.spend_usd` only, not on `gen_ai.client.operation.duration` — a per-key series on the dashboards' primary histogram would multiply its existing six-attribute product by the operator's key count, and the ledger answers per-key spend; the plan listed both on both instruments |
| Log line | `client_tool` and `request_class` become top-level `chat_completion` / `embeddings` fields; identifiers never appear in a log line |
| Decision event | No proto change (G13 default): attribution rides on spans and the ledger; `GatewayDecisionEvent` is untouched, so no `api/` ask is needed |
| Default and switches (G14) | Identifier capture ON by default; `attribution.capture_ids: false` (top-level; stored inverted, see 13a Config) turns it off globally; per-key `attribution_capture_ids: false` turns it off for one key; bounded values are always captured. Recommendation: ON — the page says an agent id "identifies an agent, not a person or a device"; the owner decides whether session and prompt ids are personal data in their deployments |
| Attribution never influences | `cache.Key`/`NormalizedKey`/L3, guardrails, routing, fallback eligibility, rate limits, budgets, idempotency — pinned by a test that two requests differing only in attribution share one L1 key |
| Ledger shape | Hourly UTC-floored buckets, key `(virtual key, served model, client tool, session)` → `{spend nano-USD int64, requests int64}`; `session` = `x-claude-code-session-id` if present, else the `agent_run_id` Baggage member **if it satisfies the same identifier grammar** (≤ 128 bytes of `[A-Za-z0-9._:-]`; `AgentRunIDFromContext` returns the percent-decoded Baggage value verbatim, `telemetry.go:931`, so without this check a `|` or `#` inside it would collide with the bbolt key and Redis field delimiters below), else `""`; a non-conforming `agent_run_id` is counted on `kelvran.attribution.dropped{header=baggage.agent_run_id}` and never stored, so every stored session satisfies the erase route's grammar. | Ledger bounds | Per key, at most 2,000 distinct sessions with rows in the retention window; a new session beyond that writes to `session = "other"`; retention 7 days (`ledger.retention_hours`, absent → 168; `0` is rejected at config load — a ledger is never unbounded, a deliberate departure from the `BudgetResetIntervalSeconds` idiom's zero-means-never-expiring rule, `docs/rfcs/2026-09-25-gateway-request-log-store-design.md:224-228`); the whole-hour unit is the retention unit |
| Ledger persistence | bbolt (`ledger.persist_path`, own file, nested bucket per hour so retention is one bucket delete) or Redis when `budget.redis_addr` is set (`ledger:<hour>:<QueryEscape(key)>` hash, field `<model>|<tool>|<session>`, `HINCRBY` nano-USD, `PEXPIRE` set once per hash to retention); same nano-USD precision bound as the budget |
| Read route | `GET /admin/spend?group_by=key|model|tool|session&key=&since=&until=`: Admin and Viewer for any query; CostViewer only when `key=` names one key (gate G27); `since`/`until` RFC 3339, default the last 24 h, window clamped to the retention; rows sorted by spend, `spend_usd` as a decimal string, `requests` as an integer; plain-text errors, per the admin convention |
| Erasure | `DELETE /admin/virtual_keys/{name}` cascades to the key's ledger rows on every replica that applies the delete (bbolt: each replica's own file; Redis: shared, idempotent); `POST /admin/spend/erase` with body `{"session": "<id>"}`, Admin-only (irreversible), erases that session's rows across the window on this replica (bbolt) or the shared store (Redis); no new propagation event in v1 (gate G28); rows already folded into `other` cannot be erased individually and the docs say so |
| Second aggregation surface | The ledger answers the last seven days inside the gateway; the decision-event stream (Vector → object storage → `evals cost-report`) stays the long-retention and offline path. Both are fed under the same `billable` gate; the ledger rounds each cost to a whole nano-USD (the Redis budget's rule, `budget.go:174-176`) while the decision event carries the exact decimal string (`dataplane.go:4713`), so the two agree to within 1e-9 USD per request on any window they share |

**Departures from the plan's text** (the plan is the file named in Status; where the two differ, this RFC is authoritative): capture point — a mux middleware, not "both handlers" (fact 3); carrier — the plan's `telemetry.WithAttribution`/`AttributionFromContext` context value is kept as written, but its description of that value as "the exact `AgentRunID` precedent" is dropped, because `AgentRunIDFromContext` reads a Baggage member and Baggage is rejected here (fact 2); `user_agent.original` stays on the `gateway.http` span only and is not duplicated as a `chat <model>` attribute (fact 1); the per-key switch is the YAML bool `attribution_capture_ids` (the `getBool`/`assignBool` idiom, `config.go:1135`), not the enum `attribution: off`; `POST /admin/spend/erase` takes a JSON body like `POST /admin/cache/erase` (`admin.go:950-951`), not `?session=`; ledger values are nano-USD `int64` like the Redis budget (`budget.go:167-181`), not `decimal`; metric dimensions as the row above records; `kelvran.client.tool` has thirteen values, not the plan's eleven (`openai_go`, `anthropic_go` added for the RFC-1 §11 matrix SDKs); the `User-Agent` rule is the product/trailer split below, not the plan's "text before the first `/` or space", which would have classified every Stainless-generated SDK as `other`; CostViewer reads `GET /admin/spend` only with `key=` (G27), not unconditionally as the plan's "(cost-viewer tier)" implied.

### 13a. Attribution carrier

**Telemetry leaf.** `type Attribution struct { ClientTool string; SessionID, AgentID, ParentAgentID, ClaudeCodePromptID string; RequestClass, AgentType, Compaction, ContextCompacted string; PrevToolDurations string; PrevToolCount, PrevToolTotalMS int }`, `type attributionContextKey struct{}`, `WithAttribution`, `AttributionFromContext` (zero value when absent, like `upstreamDurationPointerFromContext` returning nil). `ClaudeCodePromptID` is the `x-claude-code-prompt-id` header (attribute `kelvran.claude_code.prompt_id`) and is distinct from the existing `ChatCompletionResult.PromptID`/`kelvran.prompt.id` (`result.go:163`, `:378`), which is Kelvran's own prompt-management id from `req.PromptID` (`dataplane.go:4723`); the two share a result type and must not share a name. Constants in `result.go`: `AttrKelvranClientTool = "kelvran.client.tool"`, `AttrKelvranClaudeCodeSessionID = "kelvran.claude_code.session_id"` and siblings. `ChatCompletionResult` gains `Attribution Attribution`; `RecordChatCompletionResult` appends each non-empty field as a span attribute; `RecordChatCompletionMetrics` adds `kelvran.client.tool` and `kelvran.claude_code.request_class` to the duration histogram's own slice (`durationAttrs`, the pattern 13b introduced) and leaves the token instruments' `attrs` untouched; `RecordLLMSpend(ctx, spendUSD, keyID, clientTool, requestClass)` replaces the attribute-free signature at both call sites. Empty bounded values are recorded as `other` (`client.tool`) or `none` (`request_class`) so every data point carries the dimension.

**Middleware.** `cmd/gateway/attribution.go`: `captureAttribution(policy attributionPolicy, next http.Handler) http.Handler` reads the headers, applies the caps and vocabularies above, consults the global `capture_ids` policy (the per-key flag cannot be evaluated here — see the next sentence), and calls `next.ServeHTTP(w, r.WithContext(telemetry.WithAttribution(ctx, a)))`. Because the virtual key is not known until the pipeline authenticates, the per-key switch is applied where the carrier is read: `finalize` and `HandleEmbeddings` copy the carrier, blank the four identifier fields when `vk.AttributionIDsDisabled` is set, and every sink — `RecordChatCompletionResult`'s span attributes, `sessionFor` for the ledger, the log line — reads the blanked copy, so a key-level opt-out needs no second parse. `main.go:630` becomes `trackInFlight(&inFlight, captureAttribution(policy, wrapHTTPServerSpan(mux)))`.

### 13d. Spend ledger

**Leaf `internal/spendledger`** (`mayDependOn: [telemetry]` for `RecordPersistenceFailed` with a new `store_kind` value `ledger`; `dataplane` and `admin` gain it in `mayDependOn`). API: `Record(ctx, Entry{Key, Model, Tool, Session string; At time.Time; SpendNanoUSD, Requests int64}) error`, `Query(ctx, Query{GroupBy, Key string; Since, Until time.Time}) ([]Row, error)`, `DeleteKey(ctx, key string) error`, `DeleteSession(ctx, session string) error`, `Sweep(ctx, now time.Time) error`, `Close() error`, `Store() backup.DBBacked`-compatible accessor for bbolt. Two backends behind one interface: `spendledger/boltstore` (file `ledger.persist_path`; top-level bucket per UTC hour named by `hourUnix`; inside, key `key|model|tool|session` → JSON `{spend, requests}`; `Sweep` deletes whole hour buckets older than retention; `DeleteKey` scans each live hour bucket for the key prefix; `Options.Timeout = 1 s` like the others) and `spendledger/redis` (`ledger:<hourUnix>:<QueryEscape(key)>` hashes; `HINCRBY` on `<model>|<tool>|<session>` and `<model>|<tool>|<session>#n`; `PEXPIRE` to retention on first write; `Query` scans the hours in the window with `HGETALL` per key, or `SCAN ledger:<hour>:*` for cross-key group-bys; `DeleteKey` = `DEL` of the key's hashes across the window; `DeleteSession` = `HDEL` of matching fields across the window). The session cap is enforced in the leaf: a per-key set of live sessions (bbolt: a `sessions/<key>` bucket; Redis: `SADD` on `ledger:sessions:<key>`). The set is derived state, not a second source of truth — the hourly sweep rebuilds it from the live hour buckets after the expired hours are gone (bbolt inside `Sweep`; Redis by the same sweep goroutine reading the key's live hour hashes, then `DEL` + `SADD`), and `DeleteSession`/`DeleteKey` remove the member(s) in the same call — so the bound is exactly "sessions with rows in the window" and an erased or expired session frees its slot rather than holding it until a single set-wide expiry; at 2,000 the entry is written under `other`. `kelvran.persistence.failed`'s description and `RecordPersistenceFailed`'s doc (`telemetry.go:731`, `:736`, "budget or identity") and `docs/reference/metrics-and-logs.md:117`'s `kelvran.persistence.store_kind` row gain `ledger`.

**Write hook.** In `finalize`, directly after `RecordLLMSpend` and under the same `billable` gate (`dataplane.go:4772-4775`), `p.ledger.Record(settleCtx, Entry{Key: vk.ID, Model: realServingModel(dep, req.Model), Tool: attribution.ClientTool, Session: sessionFor(attribution, ctx), At: now, SpendNanoUSD: budget.USDToNanoUSD(cost), Requests: 1})` — `budget.usdToNanoUSD` (`budget.go:174-176`, `Shift(9).Round(0).IntPart()`) is unexported today and the leaf may not import `budget`, so 13d exports it and its inverse (`nanoUSDToUSD`, `:179-181`) and `dataplane` converts in both directions (the leaf stores and returns `int64`; `dataplane` formats `spend_usd` for `admin`, which cannot import `budget` either), keeping the nano-USD rule in one package; errors are logged once and counted as `kelvran.persistence.failed{store_kind=ledger}`, never failing the request. The embeddings site (`:3343-3345`) records the same way with `Model: dep.Model` (the served model, `:3337`, which the cost at `:3339` is already computed from; identical to `req.Model` today since embeddings have no fallback chains). `sessionFor` prefers the Claude Code session id, then `AgentRunIDFromContext` when it passes the identifier grammar, else `""`. The write uses `settleCtx` (`:4495-4496`) so a client disconnect does not drop it.

**Config.** `ledger: { persist_path: "", retention_hours: 168, max_sessions_per_key: 2000 }`; `persist_path` empty and `budget.redis_addr` empty → an in-memory ledger (lost on restart, still bounded); `budget.redis_addr` set → the Redis backend regardless of `persist_path` (same precedence rule as the budget, same warning). `on_corrupt_store` applies to the bbolt file through `openPersistStoreWithRecovery`.

The read route registers with `requireAnyBearerToken(h, admin, viewer, cost_viewer)`; the handler reads `credentialTierFromContext` and answers 401 when the tier is `cost_viewer` and `key=` is empty — the first tier rule decided inside a handler rather than by route middleware (G27), which makes four present-tense "exactly one route" sentences false: admin.go's Credentials doc (`:61-65`), the spend route comment (`:222-226`), `requireAnyBearerToken`'s doc (`:369-372`) and `docs/how-to/admin-api-rbac.md:16` all change to "two read routes, the second only with `key=`". ## Drawbacks

- Three more dimensions on `kelvran.llm.spend_usd` (virtual key, tool, class) and two on the duration histogram — thirteen tools × seven classes (the five page values, `other`, `none`) — bounded, but the histogram is the dashboards' primary series and the product with its existing six attributes is real.
- A new mux-level middleware is the first wrapper with gateway-authored request logic besides in-flight tracking (`wrapHTTPServerSpan`, `main.go:902-904`, delegates entirely to otelhttp, so this is the third wrapper at `main.go:630`); every future route inherits it, which is the point, but a bug there touches every request.
- Identifier capture on by default puts Claude Code session and prompt ids into whatever tracing backend the operator runs, with Kelvran offering no erasure there. The switches exist; the classification is the owner's (G14).
- The ledger is the first bbolt store with a retention sweep and the first with a cap-and-fold rule; `other` is lossy by design and cannot be un-folded or erased per session.
- Two spend surfaces (ledger, decision-event stream) can disagree outside the seven-day window or when a Redis write fails; the failure counter is the only signal.
- `GET /admin/spend` with `group_by=session` on Redis is a `SCAN` per hour across keys; cheap at operator scale, documented as not a hot path.
- The `User-Agent` table is a maintained list; a new SDK is `other` until a commit adds it.

## Alternatives Considered

- **Baggage for attribution.** Rejected: Baggage is the client's propagation channel and would travel upstream with the first injecting transport; the gateway must not forward a session id to a provider (protocol page: "need not forward").
- **Handler parameters.** Rejected: that pattern exists for `X-Kelvran-End-User-Id` because it feeds the cache key; attribution feeds nothing on the request path and would bloat three signatures.
- **Identifiers as metric dimensions.** Rejected, as the 2026-09-12 RFCs did: unbounded cardinality.
- **Proto fields now.** Rejected (G13 default): `api/` changes require the owner's go-ahead (`AGENTS.md:40`, precedents `DECISIONS.md:222`, `:250`, `:260`), and the contract RFC (`docs/rfcs/2026-09-03-api-gatewayevents-contract.md:23`, `:30`) rejects as YAGNI any field the producer cannot honestly populate — hint headers are absent by default.
- **Serving `spend --by` from the decision-event stream only.** Rejected: that path needs object storage and the evals to answer "what did this key spend on which model this afternoon"; operators asked for the gateway to know. Kept as the long-retention path.
- **Identifiers off by default.** Not chosen as the default (G14) because the page says the agent id is not a user identifier (line 60) — it is silent on session and prompt ids, which is exactly why G14 is the owner's classification call — and the attribution value is in the ids; offered as the one-line global switch.
- **Unbounded sessions.** Rejected: a tenant rotating session ids per request would grow the ledger without limit; the 2,000 cap with `other` folding bounds every backend.
- **Do nothing.** Leaves spend attributable only to a virtual key, and every Claude Code session indistinguishable from the next.
