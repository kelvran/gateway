# RFC: Fallback rescue telemetry and a Prometheus pull endpoint

- **Status**: accepted for 13b (no owner gate; next code item in the plan's Tier D sequence); proposed for 13c until the owner answers the three questions under "Unresolved Questions" (an unauthenticated third listener, two new dependencies, and whether Go runtime metrics ride along)
- **Date**: 2026-10-09
- **Author(s)**: gateway maintainers (plan items 13b and 13c, item 13 of `docs/upgrade-research/kelvran-deep-research-round4-discoverability-2026-10-08.md` (line 234), RFC-4 of the discoverability plan approved on 2026-10-08 — a file outside the repository, whose Tier D sequence and gate table are quoted where this RFC relies on them; written against `main` at 03056fe6)

Every claim about the gateway below was re-read in the code on 2026-10-09 and carries its anchor. Claims about the OpenTelemetry Prometheus exporter come from the module's own `config.go` at the version named, downloaded into the module cache for this RFC.

## Summary

Two small, independent observability additions. **13b**: a `kelvran.fallback.rescued` counter — a request whose first deployment failed and whose fallback produced the response `finalize` bills — recorded in `finalize` from the `fallbackInfo` the pipeline already threads through, with a bounded error class and the from/to deployment names; plus a `kelvran.fallback.outcome` attribute (`none` / `rescued` / `exhausted`) on the existing `gen_ai.client.operation.duration` histogram and a `kelvran.fallback.hops` span attribute. Today a fallback is visible only as a span event per failed hop, three fields on the decision event and the `anomaly_detected_fallback_rate_shift` warning; nothing aggregates "how often does the chain save a request" for a dashboard or an alert. **13c**: an optional Prometheus pull endpoint, `GET /metrics` on its own third listener (`telemetry.prometheus.listen_addr`, default `127.0.0.1:9464`), implemented as an additional reader on the same `MeterProvider` the OTLP or stdout exporter already feeds, so an operator with an existing Prometheus scrapes the gateway directly while traces keep flowing over OTLP. A name-parity test holds both paths to the same metric and label names the shipped dashboard and SLO rules use.

## Motivation

- **A rescued request is invisible in aggregate.** `fallbackInfo{happened, from, reason}` (`gateway/internal/gateway/dataplane/dataplane.go:2563-2567`) is built at four sites — the buffered chain (`:3753`) and legacy single fallback (`:3781`), and their streaming twins (`streaming.go:581`, `:594`; the plan's 13b note counts three construction sites, but the streaming path has two, so four) — and consumed in `finalize` (`dataplane.go:4470`) only as three fields on the `GatewayDecisionEvent` (`:4748-4750`) and as the input to the fallback anomaly detector (`:4808`). Per failed hop, `RecordFallbackHop` (`gateway/internal/telemetry/telemetry.go:282`, called from `fallback.go:549`) adds a span *event* with `kelvran.deployment.name`, `kelvran.fallback.hop.error_class` and the hop duration — a per-trace signal, not a metric. The error class exists (`classifyFallbackError`, `fallback.go:186`: `content_policy`, `context_window_exceeded`, `generic`, constants at `:34-38`) and is recorded per failed hop on the `fallback_hop` span event, but it never reaches `fallbackInfo` or any metric; the successful terminal hop emits nothing (`fallback.go:543-549`). None of the twenty-one instruments the gateway declares (`telemetry.go`; the `kelvran.*` set is `budget.fail_open`, `budget.threshold_crossed`, `cache.l3.gate_outcome`, `cache.lookup`, `cache.savings_usd`, `configpropagation.publish_failed`, `configpropagation.subscribe_stopped`, `guardrail.fail_open`, `llm.spend_usd`, `persistence.failed`, `ratelimit.fail_open`, `streaming.cost_estimated`, `streaming.near_duplicate_collision`; the other eight are the `gen_ai.client.*` histogram and token instruments) counts a fallback outcome. The round-4 report (line 162) frames a rescued-requests counter as the "value delivered" metric mature dashboards show, and item 13 (line 234) sizes it at 3 d / 3 h.
- **Metrics leave the process only by push.** `telemetry.Init` (`telemetry.go:790`) builds one `MeterProvider` with one `PeriodicReader` over the chosen exporter (`:848-851`), and the exporter is a single switch — `stdout`, `otlp`, or `none` (which returns before any provider is built, `:801-803`). An operator who runs Prometheus without an OTel Collector cannot scrape Kelvran; the documented routes are the compose `observability` profile (`grafana/otel-lgtm:0.33.0`, `docker-compose.yml`), whose bundled Prometheus ingests OTLP, and `telemetry.exporter: otlp` pointed at any OTLP-accepting backend (`docs/operations/TELEMETRY.md:37`), including Prometheus's own OTLP receiver — push only, no service discovery or `up` signal. The comparison page already states this plainly ("no Prometheus `/metrics` endpoint", `docs/explanation/compare/portkey.md:89`; "do not need a Prometheus scrape endpoint", `:20`), `docs/operations/TELEMETRY.md:37` says "three exporters", and `docs/reference/metrics-and-logs.md:327` lists a `/metrics` endpoint among what the gateway does not have. All four statements must change when this ships.
- **Prior verdicts stand.** The 2026-09-24 scoping pass that concluded "do not scope an RFC for either yet" (`docs/upgrade-research/gateway-observability-devex-2026-09-24.md`, "Follow-up scoping") was about request replay and a bundled admin UI, not about metrics transport; nothing earlier rules on a pull endpoint. On the counter, the 2026-09-13 observability-maturity pass (`docs/upgrade-research/observability-monitoring-maturity-2026-09-13.md`, F6) left a fallback-frequency metric open for lack of peer precedent; the round-4 report (line 178) flipped that on Portkey's rescued-requests metric, which this RFC adopts. The dashboards and SLO rules shipped on 2026-09-14/15 and extended on 2026-09-18 (per-model burn-rate rules, `21e42983`) are the parity contract this RFC has to keep.

## Detailed Design

### Decisions this RFC settles

| Question | Decision |
|---|---|
| Counter name and unit | `kelvran.fallback.rescued`, unit `{request}`, `Int64Counter`, recorded once per request in `finalize` when `fallback.happened && (err == nil || billable)` — the same gate `finalize` already uses for pricing (`dataplane.go:4489`), so a streamed rescue that fails after its first byte, or a rescue the post-call guardrail blocks, counts as the billed rescue it is |
| Counter attributes (all bounded) | `kelvran.virtual_key.id` (existing precedent on `kelvran.ratelimit.fail_open`), `kelvran.fallback.from` (deployment name first tried), `kelvran.deployment.name` (the deployment that served), `kelvran.fallback.hop.error_class` (existing constant, deliberately reused: on the counter it is the class of the *first* deployment's failure, which is never a "hop"; on the `fallback_hop` span event (`telemetry.go:282`, called only from `fallback.go:549`) it is the class of a failed hop — one key, two documented meanings, so the panel's `kelvran_fallback_hop_error_class` label matches) |
| Outcome attribute | `kelvran.fallback.outcome` ∈ {`none`, `rescued`, `exhausted`} on `gen_ai.client.operation.duration` only; `rescued` = `fallback.happened && (err == nil || billable)`; `exhausted` = `fallback.happened && err != nil && !billable`; not added to the token counters (they already carry a modality dimension and a rescued request's tokens are not a different kind of token) |
| Hops | `kelvran.fallback.hops` span attribute (int); not a metric dimension |
| Where the class and hops come from | `fallbackInfo` gains `class string` and `hops int`, filled at the four construction sites. `hops` is counted at the two chain call sites by the `call` closure they already pass, which `attemptFallbackChain` invokes exactly once per hop that reaches `call(dep)` (`fallback.go:542`), so the chain's signature and its dozen test call sites are untouched; the chain's internal `realAttempts` is not reused because its increment (`:530`) precedes the inter-hop backoff and is one too high when `sleepOrCanceled` breaks the loop (`:531-537`) |
| Prometheus transport | A third listener serving only `GET /metrics`, no authentication, bind chosen by the operator, default loopback |
| Reader shape | Additive: the Prometheus exporter is a second reader on the same `MeterProvider`; `exporter: none` plus `prometheus.enabled: true` builds a provider with the Prometheus reader alone and no trace provider |
| Registry | A dedicated `prometheus.NewRegistry()` holding the OTel exporter plus client_golang's Go and process collectors (operators expect `go_goroutines` and `process_resident_memory_bytes` from a Go service); never the global default registry |
| Resource attributes on the pull path | `WithResourceAsConstantLabels` for exactly `service.instance.id` and `service.name`, so a per-replica query works identically to the OTLP path, where otel-lgtm's Prometheus promotes every attribute in its 27-entry `promote_resource_attributes` list (`docs/operations/grafana/prometheus/prometheus.yaml:21-48`), of which the gateway's code sets exactly these two (`telemetry.go:805-812`, `resource.New` with `WithAttributes` only, no detectors). `sdkmetric.WithResource` merges `resource.Environment()` first (`sdk/metric@v1.46.0/config.go:118`), so `OTEL_RESOURCE_ATTRIBUTES`/`OTEL_SERVICE_NAME` can add attributes at runtime that the OTLP path promotes and a fixed two-key allow-list would drop; the allow-list is therefore built at `Init` from the merged resource's actual keys, intersected with otel-lgtm's promote list where one is configured, and must grow in step with any attribute added in code; `target_info` is kept |
| Name parity | `TestPrometheusEndpointExposesEveryDashboardMetricName` scrapes the endpoint and asserts every gateway-exposed metric and label name used by `docs/operations/grafana/dashboards/kelvran-overview.json` and by the recording expressions in `docs/operations/grafana/prometheus/kelvran-slo-rules.yml` (the `kelvran:slo_errors:*` series its alert rules read are Prometheus recording-rule outputs and are excluded), plus `service_instance_id` and `service_name` as labels on every `kelvran_*` series — asserted explicitly, since no shipped panel or rule queries them yet |
| Exposition names | Derived from otlptranslator v1.0.0's rules, not decided live: a brace unit (`{request}`, `{lookup}`, `{USD}`) adds no suffix (`unit_namer.go:102`), `s` maps to `_seconds`, and a monotonic counter gets `_total` (`metric_namer.go:237-239`); so `gen_ai.client.operation.duration` (unit `s`, `telemetry.go:309`) is `gen_ai_client_operation_duration_seconds_{count,sum,bucket}`, `kelvran.llm.spend_usd` (`{USD}`, `:631`) is `kelvran_llm_spend_usd_total`, `kelvran.cache.lookup` (`{lookup}`, `:595`) is `kelvran_cache_lookup_total`, and the new counter is `kelvran_fallback_rescued_total` — the names the OTLP path already produces; the live scrape confirms them |
| `listen_addr` semantics | Omitted → `127.0.0.1:9464`; present but empty → load error (the `admin.token_env` convention, `main.go:644-647`: set but empty refuses to start — stricter than `admin.listen_addr`, whose empty value takes `defaultAdminListenAddr` at `:670-672`, and the same loud-error posture `assignBool` takes for a present-but-invalid value, `config.go:1892-1901`); a misspelled key is simply absent and binds the default, as for every other optional key — `Load` rejects unknown keys only inside `models` entries (`config.go:1510`) |
| Dependencies | `go.opentelemetry.io/otel/exporters/prometheus v0.68.0` (the version whose `go.mod` requires `go.opentelemetry.io/otel v1.46.0` and `sdk/metric v1.46.0`, Kelvran's pins; v0.69.0 requires v1.47.0) and `github.com/prometheus/client_golang v1.24.1` (its requirement), plus a direct import of `github.com/prometheus/otlptranslator v1.0.0` (the exporter's own namer, compiled in regardless) for `WithTranslationStrategy`; pure Go, so the `FROM scratch` image is unaffected |

### 13b. `kelvran.fallback.rescued`

**`fallbackInfo`** (`dataplane.go:2563`) becomes `{happened bool; from string; reason string; class string; hops int}`; its doc comment (`dataplane.go:2550-2562`, "this stays a fixed 3-field record on purpose") is rewritten to say the three wire-backed fields are unchanged and the two new fields feed telemetry only, never `api/gatewayevents/v1`. At the chain sites (`dataplane.go:3753`, `streaming.go:581`) `class = classifyFallbackError(originalErr)` and `hops` is the number of hops admitted to `call(dep)` (a hop the deployment TPM gate then rejects before any upstream request still counts, like the `fallback_hop` span event): the `call` closure each site passes to `attemptFallbackChain` (`fallback.go:479`) increments a local counter, because the chain invokes it exactly once per admitted hop (`:542`), so no signature changes — `realAttempts` is not reused, being incremented at `:530` before the inter-hop backoff and one too high when `sleepOrCanceled` breaks the loop (`:531-537`). At the legacy single-fallback sites (`dataplane.go:3781`, `streaming.go:594`) `class = classifyFallbackError(err)` and `hops = 1`. `runMissPath` must propagate `fallback` on its error branch: today `fallback` is a local of the singleflight closure (`dataplane.go:3729`), the closure returns only the error when the last hop fails (`:3790`) or when the post-call guardrail blocks an already-billable response (`:3798`, `:3812-3813`), and `runMissPath`'s error return hands `finalize` a zero `fallbackInfo{}` (`:3833`) — so without this change `exhausted` is unreachable on the buffered path and a rescued-then-guardrail-blocked request is reported as `none`. The fix captures it the way `blockedResp`/`blockedDep` already are (a `missFallback fallbackInfo` the closure assigns) and returns it at `:3833`; the blocked case then classifies as `rescued`, since the upstream fallback succeeded and the request is billed. Only the streaming path (`streamDeploymentWithFallback`, `streaming.go:530-599`) returns `fallback` alongside an error today.

**`finalize`** (`dataplane.go:4470`), after `outcome := outcomeFor(err)`: 

```go
fallbackOutcome := telemetry.FallbackOutcomeNone
switch {
case fallback.happened && (err == nil || billable): // the gate the cost block below already uses
    fallbackOutcome = telemetry.FallbackOutcomeRescued
    telemetry.RecordFallbackRescued(ctx, virtualKeyID, fallback.from, dep.Name, fallback.class)
case fallback.happened: // err != nil && !billable
    fallbackOutcome = telemetry.FallbackOutcomeExhausted
}
```

`ChatCompletionResult` gains `FallbackOutcome string` and `FallbackHops int`; `RecordChatCompletionMetrics` (`telemetry.go:447`) records the duration histogram with a separate slice — `durationAttrs := append(append([]attribute.KeyValue{}, attrs...), attribute.String(AttrKelvranFallbackOutcome, r.FallbackOutcome))` passed only to `operationDurationHistogram.Record` (`:463`) — and leaves `attrs` itself untouched, because `attrs` is also copied into `modalityAttrs` (`:474`, the five token counters) and passed bare to `inputTokensOperationHistogram`/`outputTokensOperationHistogram` (`:477`, `:481`); a unit test asserts the outcome attribute is absent from every token instrument; `finalize` sets `kelvran.fallback.hops` on the span when `hops > 0`. The decision event, the anomaly detector (`:4808`) and `RecordFallbackHop` are untouched in code; the span event stays the per-hop detail, the counter is the aggregate. *Implementation note (2026-10-09):* handing `fallback` out of `runMissPath`'s error branch also changes the decision event's *values* on a failed buffered request — `fallback_happened` / `fallback_from_deployment` / `fallback_reason` are now populated when a fallback was attempted, where they were always `false` / empty (the streaming path already reported them, so this removes an inconsistency) — and the fallback-rate anomaly detector therefore observes exhausted buffered fallbacks too. The wire schema is unchanged; recorded in the changelog. Two further design-vs-code drifts, accepted: the instrument description shipped as "Requests whose first deployment failed and whose fallback produced the billed response." (tighter than "succeeded", since a guardrail-blocked rescue counts), and the record travels out of `runMissPath` as its named return `fallback`, assigned inside the closure like `billable`, rather than as a separate `missFallback` local. A singleflight follower of a rescued leader receives the leader's record on the success path (as its decision event always has) and therefore counts as rescued; an exhausted leader's followers keep the zero record and read `none`.

**Telemetry package**: `fallbackRescuedCounter = mustInt64Counter(meter, "kelvran.fallback.rescued", WithDescription("Requests whose first deployment failed and whose fallback succeeded."), WithUnit("{request}"))` beside the other `kelvran.*` counters; `RecordFallbackRescued(ctx, keyID, from, to, class string)`; new constants `AttrKelvranFallbackFrom = "kelvran.fallback.from"`, `AttrKelvranFallbackOutcome = "kelvran.fallback.outcome"`, `AttrKelvranFallbackHops = "kelvran.fallback.hops"` in `result.go` next to `AttrKelvranFallbackHopErrorClass` (`:191`). Cardinality: keys × from-deployments × to-deployments × 3 classes — deployments are a small operator-owned set, and the key dimension already exists on the fail-open counters.

**Grafana and docs**: two panels in `kelvran-overview.json` — "fallback rescues per hour by class" (`sum by (kelvran_fallback_hop_error_class) (rate(kelvran_fallback_rescued_total[5m])) * 3600`) and "rescue ratio" (`sum(rate(gen_ai_client_operation_duration_seconds_count{kelvran_fallback_outcome="rescued"}[5m])) / sum(rate(gen_ai_client_operation_duration_seconds_count{kelvran_fallback_outcome=~"rescued|exhausted"}[5m]))`); one row in `docs/operations/TELEMETRY.md`'s signal table and the counter list; `docs/reference/metrics-and-logs.md`; the changelog.

### 13c. Prometheus pull endpoint

**Config.** `controlplane.TelemetryConfig` (`config.go:462-466`) gains `Prometheus struct{ Enabled bool; ListenAddr string }`, parsed from `telemetry.prometheus.{enabled, listen_addr}` with `getMap`/`assignBool`/`getString` next to the existing two keys (`config.go:1257-1260`). `ListenAddr` omitted → `""` at load, resolved to `127.0.0.1:9464` by `cmd/gateway` the way `defaultAdminListenAddr` is applied; present and empty → load error naming the key. `telemetry.Config` (`telemetry.go`, `{Exporter, OTLPEndpoint}`) gains `PrometheusEnabled bool`.

**`telemetry.Init`.** When `PrometheusEnabled`: build `reg := prometheus.NewRegistry()`, register `collectors.NewGoCollector()` and `collectors.NewProcessCollector(...)`, construct `promExporter, err := otelprom.New(otelprom.WithRegisterer(reg), otelprom.WithoutScopeInfo(), otelprom.WithResourceAsConstantLabels(attribute.NewAllowKeysFilter("service.instance.id", "service.name")), otelprom.WithTranslationStrategy(otlptranslator.UnderscoreEscapingWithSuffixes))` and pass it as an extra `sdkmetric.WithReader(promExporter)` on the provider (`:848-851`). The `none` early return (`:801-803`) becomes: no trace provider, and a metrics provider only if Prometheus is enabled. The exporter satisfies `sdkmetric.Reader`, so `meterProvider.Shutdown` (`:868`) covers it. `telemetry.PrometheusHandler() http.Handler` returns `promhttp.HandlerFor(reg, promhttp.HandlerOpts{})` or `nil` — package-level state, the same shape as `InstanceID`. Option names verified in the module's `config.go` at v0.68.0: `WithRegisterer`, `WithoutScopeInfo`, `WithoutTargetInfo`, `WithResourceAsConstantLabels`, `WithoutUnits`, `WithoutCounterSuffixes`, `WithTranslationStrategy`, `WithNamespace`. Translation is pinned explicitly with `WithTranslationStrategy(otlptranslator.UnderscoreEscapingWithSuffixes)`: it is the v0.68.0 default (`config.go:34-35`), but the option's own doc (`:103-118`) says the default depends on `prometheus/common`'s `NameValidationScheme` (whose default is `UTF8Validation` in v0.70.1, `model/metric.go:51`) and that a future release will change it, and `WithoutUnits`/`WithoutCounterSuffixes` are marked `Deprecated` (`:140`, `:160`) and are not used. Pinning is what keeps the `_total` and `_seconds` names the dashboards use from depending on a default the module documents as in flux.

**`cmd/gateway`.** A third `*http.Server` built like the admin server (`main.go:643-701`): `Addr` from config, `Handler` a mux whose only route is `GET /metrics` (`HEAD` allowed, other methods 405, other paths 404), `ReadHeaderTimeout: 10 * time.Second` (`:634`), started in its own goroutine with its own error channel like `adminServeErr` (`:827-841`), logged as `metrics server listening` with `addr`, and added to the `shutdownServersConcurrently` call (`:853-856`) so it drains with the others inside the existing stop budget. A bind failure is a startup error, as for the other two listeners.

**Deploy.** `deploy/k8s/base/deployment.yaml` exposes only `http` 8080 today (`:159-160`); the k8s how-to gains the opt-in recipe — `listen_addr: "0.0.0.0:9464"`, a `metrics` containerPort, `prometheus.io/scrape: "true"` / `prometheus.io/port: "9464"` pod annotations, and a NetworkPolicy that admits the Prometheus namespace only. `docs/operations/DEPLOY.md` gets a static `scrape_configs` snippet. For the compose profile, otel-lgtm's Prometheus needs a scrape job for `gateway:9464` and `gateway2:9464`; the profile already mounts a full replacement `prometheus.yaml` into otel-lgtm at the image's real config path (`docker-compose.yml:242`, confirmed live 2026-09-15 per that file's header and the compose comment at `:234-241`), alongside the Grafana provisioning file, the dashboard and the SLO rules (`:232-233`, `:243`); the recipe adds a `scrape_configs:` job for the two gateways to `docs/operations/grafana/prometheus/prometheus.yaml`, which today has `rule_files:` and `alerting:` blocks but no scrape job.

**Threat model.** A new Gateway Information Disclosure clause: the endpoint is unauthenticated by design (Prometheus scrapes without credentials unless configured) and exposes virtual-key ids as label values on the fail-open and rescued counters, spend aggregates (`kelvran_llm_spend_usd_total`), model and deployment names, and Go runtime detail; hence loopback by default, operator-chosen bind, and the k8s recipe's NetworkPolicy. Unlike the opt-in `admin.enable_pprof` surface (`THREAT_MODEL.md`'s Gateway Elevation-of-Privilege row, "New consideration added 2026-09-14"), which sits behind the admin bearer because a heap dump is an unscoped read of process memory, `/metrics` carries no credential: it exposes aggregates and label values, never process memory, and the admin listener is nil without `admin.token_env` (Alternatives). A dated entry is added under `THREAT_MODEL.md`'s "Review Cadence & Change Log". `SECURITY.md` is unchanged (nothing new is retained).

**Docs.** `docs/operations/TELEMETRY.md` ("three exporters" → the exporter switch plus an optional pull reader; a "Prometheus pull" subsection with the parity contract), `docs/reference/config.md` and `gateway/config.example.yaml` (`telemetry.prometheus` keys, commented out), `docs/reference/metrics-and-logs.md`, `docs/operations/DEPLOY.md`, `docs/how-to/deploy/kubernetes-kustomize.md`, `docs/explanation/compare/portkey.md:20,89`, `gateway/ARCHITECTURE.md`'s `/internal/telemetry` package-map entry (line 473), the changelog (`## Added`, two entries).

## Drawbacks

- 13b adds a dimension to `gen_ai.client.operation.duration` (×3 series) and a counter keyed by virtual key; both are bounded, but the histogram is the dashboards' primary series and every new dimension is permanent.
- Hop counting lives in the `call` closures at the two chain call sites rather than in `attemptFallbackChain` itself — slightly less visible than a return value, chosen to leave the chain's signature and its dozen test call sites alone.
- 13c adds two direct dependencies (three direct imports, counting `prometheus/otlptranslator`) and their transitive set — new modules `prometheus/client_model v0.6.2`, `prometheus/common v0.70.1`, `prometheus/otlptranslator v1.0.0`, `prometheus/procfs v0.21.1`, `beorn7/perks v1.0.1`, `munnerz/goautoneg`, plus a `klauspost/compress` bump from v1.18.7 (`gateway/go.mod:53`) to the v1.19.1 client_golang requires — all pure Go; `cespare/xxhash/v2`, `golang.org/x/sys`, `google.golang.org/protobuf`, `google/uuid`, `go-logr` and `go.yaml.in/yaml/v3` are already in `gateway/go.mod` (read from both modules' `go.mod` files in the module cache). govulncheck and the SBOM grow accordingly.
- A third listener is a third thing to bind, firewall and drain. The loopback default means a container deployment gets nothing until the operator binds `0.0.0.0`, which is the point.
- Package-level `PrometheusHandler()` state in `telemetry` mirrors `InstanceID` and the global OTel providers rather than improving on them.
- The pull path and the OTLP path can still diverge in ways the parity test does not see (histogram bucket boundaries, exemplars, `target_info` shape); the test pins names and labels, not values.

## Alternatives Considered

- **Serve `/metrics` on the admin listener with the Viewer token.** Prometheus can send a bearer, and the admin listener already has `ReadHeaderTimeout` and optional mTLS. Rejected for v1: the admin server is `nil` unless `admin.token_env` is set (`main.go:644`), so operators without an admin plane could not scrape; mixing a scrape target into the mutation surface widens the admin's exposure; and the SLO-rules workflow assumes a plain target. Kept as a possible later `telemetry.prometheus.listen: admin` option.
- **Serve `/metrics` on the data listener.** Rejected: the data plane is tenant-facing, and the exposition carries key ids and spend aggregates.
- **A fourth `exporter:` value, `prometheus`, in the existing switch.** Rejected: the switch couples traces and metrics, and the operators this serves want OTLP traces with pull metrics.
- **Record `rescued` inside `attemptFallbackChain`.** Rejected: the chain does not know whether the hop that returned success is the one `finalize` bills (streaming can still fail after the chain returns), and `finalize` is where every other per-request metric is recorded.
- **Make `rescued` a dimension on the token counters too.** Rejected: a rescued request's tokens are not a different modality; the duration histogram already distinguishes outcomes and carries `error.type`.
- **Do nothing.** Leaves the chain's value unmeasurable and Prometheus-only operators on a collector they may not run.
