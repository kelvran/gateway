### Finding 2 — The concurrency-race regression test is real, CI-run, and passing today — this is the one item that fully closes the loop from research to enforced practice (confidence: high — verified against source and CI workflow directly)

`gateway/cmd/gateway/concurrent_burst_regression_test.go` (added in the same `c3ec7b86` commit, reduced from 50→20-way concurrency in a same-day follow-up `70e5c531`) is a genuine `httptest`-based test: two fake upstream servers (one always-failing, one always-succeeding), a real `buildPipeline`-constructed gateway with **no health probing configured at all** (deliberately, to reproduce the exact "failure happens before the prober notices" production shape that caused the real bug), and 20 concurrent real HTTP requests through the gateway's own `chatCompletionsHandler`. The load-bearing assertion (`concurrent_burst_regression_test.go:222-227`) checks that no single logical request ever reaches the failing deployment more than once — the precise invariant the WRR-cursor race violated. This test is not gated behind any opt-in flag and runs as part of `go test ./... -race` (`.github/workflows/ci.yml:126`), which CI runs from the `gateway` working directory (`ci.yml:106-126`) — a scope that includes `cmd/gateway`. This is a real, CI-enforced regression guard for exactly the concurrency bug class `chaos-engineering-resilience-testing-2026-09-14.md` Finding 4 flagged as a genuine gap.

**Verdict: fully real — research → shipped, CI-enforced practice, no gap remaining for this specific bug class.**

### Finding 5 — New, environment-specific finding this session: Docker `pause`/`unpause` is a reliable network-partition simulator on this repo's colima setup; `testcontainers-go` `Stop`/`Start` is not (confidence: high — independently discovered and verified this session against this repo's real local Docker environment)

During an unrelated test-writing task this session, `docker pause <container>` / `docker unpause <container>` against a real container was confirmed to reliably simulate a network partition (the paused container stops responding to any traffic without the connection being torn down, unlike stopping the container) in this repo's own colima-based local Docker environment. Separately, `testcontainers-go`'s `Stop`/`Start` lifecycle methods do **not** reliably preserve the container's dynamic port mapping in this same environment — a re-started container can come back on a different host port than the one `testcontainers-go` originally reported, silently breaking any test that cached the port from the initial `MappedPort` call. This is consistent with, and extends, the already-documented colima-specific gotcha in this repo's own `AGENTS.md` ("Rootless Docker not found" — `testcontainers-go` never consults `docker context inspect` and misses colima's real socket path) — both are instances of `testcontainers-go`'s assumptions about a stock Docker daemon not holding on a colima-backed macOS setup. Toxiproxy's own approach (a long-lived proxy process with a stable HTTP control API, never restarting the underlying container) sidesteps the port-remapping trap entirely, which is a real, environment-grounded reason to prefer Toxiproxy — or a bare `docker pause`/`unpause` cycle — over any chaos design that relies on stopping/restarting a `testcontainers-go`-managed container in this repo specifically.

**Verdict: real, actionable, environment-specific — worth promoting into `AGENTS.md`'s Gotchas section (per that file's own "promote after 2+ occurrences" convention — this is the second, independent instance of a colima/testcontainers-go mismatch) the next time a chaos harness is actually built here.**

## Recommended next step

**Lowest-effort, highest-value load test:** reuse Finding 2's own pattern (`buildPipeline` + `httptest.Server` fakes, no Docker/new-toolchain dependency) rather than adopting `k6`/`vegeta`/Locust at all yet. Add one new Go test in the same family as `concurrent_burst_regression_test.go` that drives a few hundred concurrent requests against a fast-responding fake upstream and asserts `X-Kelvran-Overhead-Duration-Ms` (Finding 3's already-shipped header) stays under a smoke threshold, run as a normal `go test` in CI. This satisfies `TESTING.md` §7's "tiny smoke-only load test on PR" with zero new dependencies, since the header instrumentation and the mock-upstream-via-`httptest` pattern are both already proven in this exact codebase — only `k6`/`vegeta`/Locust adoption for the *full* nightly/pre-release Poisson-arrival profile remains a real, larger, separate follow-up.

**Lowest-effort, highest-value chaos experiment:** given Finding 5, skip Toxiproxy's HTTP control-API setup for a first CI-runnable pass and instead script a `docker compose pause <mock-upstream-service>` / `unpause` cycle around a live burst of requests through a real running gateway binary (the same production shape `concurrent_burst_regression_test.go` already builds, but via `docker compose` against a containerized mock upstream instead of an in-process `httptest.Server`), asserting the circuit breaker trips and recovers within the documented `maxConsecutiveChainFailures=3` bound. This converts `TESTING.md` §8's "provider-outage scenario → circuit-breaker/fallback-chain behavior" from a described-but-unenforced row into one real, repeatable CI job, using only `docker compose` — already in CI's toolchain — and avoids the port-remapping trap Finding 5 found in `testcontainers-go`'s `Stop`/`Start` lifecycle.
