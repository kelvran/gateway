## 1. Packaging, installation and distribution (run `wf_ee3b7828-690` — 105 agents, 1,445 tool uses, 59 min; 23 sources → 115 claims → 25 verified → 20 confirmed / 5 refuted → 12 synthesized findings)

**What survived.**

- `[V]` **GoReleaser is the release backbone every reference Go CLI uses**: one config yields static multi-arch binaries, archives, one checksums file, a syft SBOM per archive and deb/rpm/apk packages attached to the GitHub Release with no hosted infrastructure. Re-verified on k9s v0.51.0's live asset list (`checksums.sha256`, `*.sbom.json` per archive, `k9s_linux_{amd64,arm,arm64,ppc64le,s390x}.deb`). `[C]` Kelvran has no `.goreleaser.yaml`, no release workflow (workflows: ci, codeql, evals-judge-nightly, iac-scan, scorecard) and zero assets on every GitHub Release; `ci.yml`'s publish job reacts to `gateway/v*` tags with the GHCR image only.
- `[V]` **Sign the checksum file only, in the cosign v3 bundle format**: GoReleaser's sign page (updated 2026-09-05, re-fetched) says "it is generally enough to sign the checksum files only" and its recipe is `cosign sign-blob --bundle=${signature} ${artifact} --yes` producing `checksums.txt.sigstore.json`; user verification is `cosign verify-blob --certificate-identity … --certificate-oidc-issuer … --bundle checksums.txt.sigstore.json checksums.txt` then `sha256sum --check --ignore-missing`. Caddy's sign-every-artifact detached `.sig`/`.pem` layout is the deprecated v2 format. Kelvran already runs keyless cosign on images, so this is configuration, not new infrastructure.
- `[R]` **SLSA provenance for release binaries is unconfirmed**: both slsa-github-generator claims were refuted 0-3 (refutation text did not reach the synthesis). Keep advertising the verified SLSA Build L2 image provenance; do not promise provenance on binaries until separately verified.
- `[V]` **Homebrew means a cask in a tap, not a formula**: `homebrew_formulas` is "Deprecated in v2.10. Homebrew Casks should be used instead" (re-fetched). Casks "are supposed to be signed"; an un-notarized binary needs Apple notarization or GoReleaser's documented post-install `xattr -dr com.apple.quarantine` hook, which the page warns "Apple may disable … without notice" (re-fetched). Homebrew removed `--no-quarantine`, so users cannot opt out. Casks from GoReleaser are tap-only, never homebrew-core.
- `[R]` **Linux packaging has two tiers**: release-attached deb/rpm/apk (k9s, zero infra; deb outnumbers rpm ~3.6:1 and apk ~44:1 on k9s v0.51.0) versus a hosted apt repo (Caddy on Cloudsmith) whose package installs and auto-starts a systemd unit with a parallel testing channel. Kelvran is a daemon like Caddy, so a systemd unit matters; the hosted repo is a second step.
- `[V]` **Channel governance, Caddy-style**: six official channels and eleven explicitly labelled "community-maintained installation method" (re-fetched: the phrase appears exactly 11 times). Homebrew and the curl|sh installer are community-maintained even for Caddy. Own few channels well; label the rest.
- `[R]` **Upgrade and rollback are per channel** (`brew upgrade`, `apt upgrade`, `docker pull` by pinned tag, `helm upgrade`); Caddy's built-in `caddy upgrade` is labelled EXPERIMENTAL, only swaps the binary, has an open downgrade bug and fights apt. Defer a self-upgrade subcommand. Evidence on pinning is negative (Bifrost's chart `appVersion` stuck at 1.5.12 while the gateway is 2.2.6; LiteLLM's quickstart pulls a moving `main-stable` tag): automate `appVersion` bumps and pin quickstart image tags to the release.
- `[R]` **Competitors win the five-minute race with zero-config startup, not channel count**: Bifrost starts with no config file and is configured afterwards in an embedded web UI on the same port; LiteLLM's curl|sh (merged 2026-10-02) stands up gateway + Postgres + Admin UI via compose with generated master and salt keys and no user-authored config. `[C]` Kelvran's README `docker run -v $(pwd)/config.yaml:/config.yaml …` requires the user to author a 664-line-template-derived config first, and there is no `init` or zero-config mode (flags: `-config`, `-validate`, `-restore-*`).
- `[V]` **Do not copy Bifrost's npx/vendor-CDN pattern**: ~1.8 M Docker pulls vs ~52 K npm downloads (2-1, snapshot with CI noise), 100 releases with almost no assets (re-checked via the GitHub API: 100 releases, ≤6 assets in total), the npm launcher downloads an unverified binary from a vendor CDN with no checksum or signature, Scorecard Signed-Releases 0/10. GitHub Releases with signed checksums is strictly better.
- `[V]` **Helm as an OCI artifact on the GHCR namespace Kelvran already uses** (`oci://ghcr.io/kelvran/charts/gateway`) gets an Artifact Hub listing with no `index.yaml` or GitHub Pages, provided every chart version is a plain-semver OCI tag and the package is public (Artifact Hub docs re-fetched: "oci://registry/namespace/chart-name"). Listing is a manual control-panel step; cosign-signed charts have hit GHCR referrer-endpoint 429s (issue #4785). The chart can be derived from `deploy/k8s/base`.
- `[R]` **Adoption impact per channel is thin but directionally consistent**: container images dominate; GitHub Release asset download counts are public, GHCR pull counts are not. Instrument what is measurable before investing in long-tail channels.

**The blocker the lane found and the main session settled.** GoReleaser's monorepo support (`monorepo: tag_prefix: gateway/`, `dir: gateway`, which strips the prefix from `{{ .Tag }}`) is **"exclusively available with GoReleaser Pro"** (`[V]` page meta description, re-fetched 2026-10-08). Its own note says a `github.com/user/repo/moda` module's tags "should be named moda/v1.2.3", which is exactly Kelvran's `gateway/v0.17.0` scheme, and `[C]` that scheme is **required**, not optional: the Go module proxy resolves `github.com/kelvran/gateway/gateway@latest` to v0.17.0 only because the tags carry the `gateway/` prefix. Renaming tags is therefore off the table. Three real options: (a) GoReleaser Pro (paid); (b) open-source GoReleaser with `GORELEASER_CURRENT_TAG=gateway/v0.17.0` (documented cookbook, re-fetched) plus `--skip=validate` and hand-written `trimprefix` version templates — unproven, needs a one-hour spike; (c) a plain release workflow without GoReleaser: `go build` matrix, `sha256sum`, `syft`, `cosign sign-blob --bundle`, `nfpm` CLI, `gh release upload` — fully open source, indifferent to the tag scheme, and the same tool set the image job already uses. Recommendation: spike (b) for one hour; fall back to (c).
