## Question

## Summary

Round 3 surfaces no new caching category Kelvran should build. The two most promising-sounding 2026 innovations — KV-cache-aware routing (NVIDIA Dynamo, Gateway API Inference Extension) and finer-grained sub-completion caching (LMCache/CacheBlend, RAGCache) — are real and maturing, but both operate on live KV-cache tensors inside a self-hosted inference engine (vLLM, TensorRT-LLM, etc.), which Kelvran structurally cannot access since it is a gateway calling hosted provider APIs (Anthropic/Bedrock) that never expose such internals (Findings 1-2). Cache-aware budget/SLO integration and proactive provider-driven invalidation are both confirmed as genuine, unaddressed industry gaps (checked against Cloudflare AI Gateway and LiteLLM, the two most comparable products) — real opportunities, but with zero existing pattern to de-risk against, making them exploratory rather than validated builds (Findings 3-4). The round-2 decision to reject embedding-based semantic caching is now triply-reinforced by a second, independent 2026 security paper (CacheAttack/ICML 2026, 86% response-hijack rate) showing the locality-vs-collision-resistance trade-off is a permanent structural property of embedding caches, not a fixable bug — and confirming the attack is inapplicable to lexical/shingle matching (Finding 5). Net verdict: every avenue examined this round resolves to "not yet" or "structurally not applicable" for Kelvran's specific architecture; the two live gaps (budget-SLO linkage, proactive invalidation) are worth flagging as exploratory backlog items, not immediate builds.

## Findings

### Finding 1 — NOT APPLICABLE: KV-cache-aware routing is real but requires self-hosted inference infrastructure Kelvran doesn't operate (confidence: high)

KV-cache-aware ROUTING (NVIDIA Dynamo's worker-published-KV-event routing, and the Kubernetes Gateway API Inference Extension's Endpoint Picker prefix-cache scorer) is a real, actively-shipping 2026 pattern with measured wins (~2x TTFT in a Baseten/Qwen3-Coder benchmark) — but it is an infrastructure/topology feature for routing across a pool of SELF-HOSTED GPU inference workers based on their live, worker-published KV-cache state. It selects which backend server to send a request to, not whether/how to cache a response, and has no documented path for routing across third-party hosted model APIs. Every source (NVIDIA's own docs/README, the GIE project's own docs+live scoring-plugin code, an independently-traced Baseten benchmark) is unanimous that this requires direct Kubernetes/Gateway control over self-hosted GPU workers publishing their own KV-cache-state events — a mechanism with no third-party-hosted-API equivalent.

### Finding 2 — NOT APPLICABLE: sub-completion/KV-block-level caching is real but structurally impossible for a hosted-API gateway (confidence: high)

Finer-grained, sub-completion caching (KV-block reuse at non-prefix positions via CacheBlend/LMCache; RAGCache's "knowledge tree" caching of intermediate attention states for retrieved RAG chunks) is a real and matured 2026 research+production category. However, it requires a standalone daemon or in-process component with direct access to the inference engine's live KV-cache tensors (e.g., vLLM), and is architecturally impossible for a gateway that only calls out to hosted provider APIs — those providers (confirmed against Anthropic's own prompt-caching docs) expose caching only via an opaque, declarative flag with no access to raw KV-cache tensors or cache-key addressing. Confirmed via LMCache's own README/docs and the CacheBlend/RAGCache peer-reviewed papers (2.2-3.3x TTFT / 2.8-5x throughput gains in their own benchmarks). **This is a structural mismatch (deployment category), not a maturity gap** — it would remain true even if the state of the art advanced further, unless Kelvran itself became a self-hosted inference operator.

### Finding 3 — Real, unaddressed gap: cache-aware budget/SLO integration has no industry precedent anywhere checked (confidence: high) — exploratory, not a validated build

Cache-aware budget/quota integration (e.g., a virtual key's budget cap adjusted for expected cache savings, or a "cache hit rate SLO") has no real 2026 industry precedent. Cloudflare AI Gateway ships a first-class "Cached Responses" hit-rate metric but explicitly does not link it to its budget/cost-tracking feature (confirmed on the live Aug 27, 2026-updated doc, no cross-reference found anywhere in the product's docs). LiteLLM's virtual-key/team/user budgets are enforced purely against actual recorded spend, architecturally decoupled from any cache-hit logic — corroborated by LiteLLM's own GitHub issues showing cache-hit paths affect only rate limits, never spend caps. **This directly answers the research question: it is a genuine, currently-unaddressed gap across the two most comparable products checked, meaning Kelvran would be pioneering rather than adapting a validated pattern. Flagged as exploratory-value, not risk-free** — there is no proof of user demand or a working design to copy.

### Finding 4 — Real, unaddressed gap: true semantic caching AND proactive invalidation remain unshipped even at the closest comparable product (confidence: high)

True semantic (embedding-based) caching remains UNSHIPPED even at Cloudflare AI Gateway — one of the most comparable, well-resourced commercial products — with the vendor's own Aug 27, 2026 docs listing it only as a future roadmap item; the shipped cache is strictly exact-match (SHA-256 of the full request). The same product also has NO invalidation/purge API at all — expiration is TTL-only, with no mechanism tied to upstream provider/model-version changes. This **tempers the premise that semantic caching is a crowded, mature production space** — at the gateway-product level it largely isn't yet — and reinforces the "not yet/premature" verdict for both proactive invalidation and any renewed semantic-caching push, since even the closest comparable competitor hasn't shipped either.

### Finding 5 — Reinforced (new, independent evidence): embedding-based semantic caching now triply-confirmed as a permanent structural risk lexical matching avoids (confidence: high)

A second, independent 2026 peer-reviewed paper (CacheAttack, accepted ICML 2026) further reinforces the existing decision against embedding-based semantic caching: it demonstrates an 86% response-hijacking hit rate via a white-box GCG key-collision attack, including inducing malicious behavior in a financial-agent case study, and argues this is a PERMANENT structural property — the same embedding locality that boosts cache-hit rate is mathematically in tension with the cryptographic avalanche effect needed for collision resistance. The evaluation targets genuine embedding-based caches (distilbert-base-uncased embeddings); the gradient-based attack mechanism requires a differentiable embedding space and does not, on its face, transfer to lexical/shingle-based matching (Kelvran's approach). This is distinct from and additive to the NDSS 2026 semantic-cache-poisoning paper already cited in round 2 — a second, independent attack framework with a different, more general structural argument, qualifying as genuinely new corroboration.

## Caveats

- All findings in this round converge on "not yet" or "structurally not applicable" for Kelvran's specific gateway-to-hosted-API architecture — no "build now" item was identified.
- The two genuinely open gaps (cache-aware budget/SLO integration, proactive provider-driven invalidation) are validated as real gaps but have zero prior art anywhere checked (Cloudflare AI Gateway, LiteLLM) — building either would be exploratory/first-of-its-kind rather than a de-risked adaptation of an established pattern. Treat as backlog candidates for a future dedicated research pass on design options, not as ready-to-build specs.
- Several verifications relied on a single primary source because general web search tools were repeatedly rate-limited/blocked during verification — each still passed on primary-source strength alone.
- The NDSS/CacheAttack security papers are very recent (Feb 2026 and Jan/June 2026 respectively) — appropriate rigor for a fast-moving 2026 field, but there has been limited time for independent replication or rebuttal to surface.
- The Cloudflare AI Gateway findings are time-sensitive to an Aug 27, 2026 doc snapshot; Cloudflare could ship semantic caching, invalidation, or budget-SLO linkage at any time, which would change Findings 3-4's currency.

## Recommendation for Kelvran

1. **No action**: KV-cache-aware routing and sub-completion caching (Findings 1-2) — structurally inapplicable to Kelvran's hosted-API gateway architecture, not a maturity gap that will close with more waiting.
2. **Exploratory backlog, not ready-to-build**: cache-aware budget/SLO integration and proactive provider-driven invalidation (Findings 3-4) — real gaps, but Kelvran would be pioneering, not adapting; worth a dedicated design-options research pass before committing to a spec, and worth validating real operator demand first.
3. **No action, reinforced**: continue declining embedding-based semantic caching (Finding 5) — a second independent 2026 security paper adds new, non-redundant corroboration for a decision already made twice.
