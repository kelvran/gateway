# Glossary

This page defines every Kelvran-specific term in one or two sentences and names the file that defines it, so the other pages can use the term without re-explaining it. It is for operators, client developers and contributors who meet a term in a config file, a log line, an error envelope or another page and need its exact meaning. Entries are grouped by area; within a group they are alphabetical. Each definition states the default and the validation rule as the code has them at the cited location. Where a capability is on `main` but not in the latest release, the entry says so in the words "on main since <date>, not in gateway/v0.17.0".

Current releases: `gateway/v0.17.0` (2026-10-07) and `evals/v0.10.1` (2026-09-22); see [VERSIONING.md](../VERSIONING.md).

## 1. Deployables, versions and build identity

| Term | Definition | Defined in |
|---|---|---|
| **api/ contract** | The protobuf contract under `api/` that is the only link between the two deployables. It is versioned on its own and checked by `buf breaking` in CI. See *GatewayDecisionEvent*. | `api/gatewayevents/v1/gatewayevents.proto`; [VERSIONING.md](../VERSIONING.md) section 1 |
| **Build identity** | The `version`, `commit` and `date` values injected at build time with `-ldflags "-X main.version=… -X main.commit=… -X main.date=…"`, printed by `gateway -version` and logged once at start as `build_info`. A plain `go build` or `go run` reports `version=dev`, `commit=none`, `date=unknown`, which identifies a non-release build. On main since 2026-10-08, not in gateway/v0.17.0. | `gateway/cmd/gateway/version.go` |
| **Deployable** | One of the two independently versioned artifacts Kelvran ships from one repository: `gateway` (Go) and `evals` (Python). They share no build and no runtime dependency; the `api/` contract is the only coupling. | [ADR 0001](../decisions/0001-monorepo-two-deployables.md); [VERSIONING.md](../VERSIONING.md) |
| **evals** | The Python deployable. It never sits in the request path: it calls the gateway for offline rollouts and reads the gateway's `gatewayevents_v1` telemetry for regression detection. Tagged `evals/vX.Y.Z`. See section 9. | [evals/ARCHITECTURE.md](../../evals/ARCHITECTURE.md) |
| **gateway** | The Go deployable: the HTTP gateway with routing, virtual keys, budgets, rate limits, the embedded cache, guardrails and the admin API. Tagged `gateway/vX.Y.Z`. | [gateway/ARCHITECTURE.md](../../gateway/ARCHITECTURE.md) |
| **gateway/vX.Y.Z, evals/vX.Y.Z** | The two tag lines. The `gateway/` prefix is required by Go's nested-module rule; image tags and release-asset names drop the prefix. Both lines follow Semantic Versioning 2.0.0. | [VERSIONING.md](../VERSIONING.md) section 1; [explanation/versioning.md](../explanation/versioning.md) |
| **Instance ID** | `hostname:pid` of one gateway process, computed once at start. Emitted as the OTel resource attribute `service.instance.id`, as `kelvran.instance.id` on metrics, and as the origin of config-propagation events so a replica ignores its own mutations. | `gateway/internal/telemetry/telemetry.go` (`InstanceID`); `gateway/cmd/gateway/main.go` |

## 2. Identity and tenancy

| Term | Definition | Defined in |
|---|---|---|
| **allowed_models** | A virtual key's optional allow-list of canonical model names. Empty means every configured model is allowed. A request for a model outside the list is rejected with code `model_not_allowed` (HTTP 403). | `gateway/internal/gateway/controlplane/config.go` (`VirtualKeyConfig.AllowedModels`); `gateway/cmd/gateway/main.go` |
| **allowed_source_cidrs** | A virtual key's optional source-IP allow-list, written as a map of CIDR strings to `true`. A request from outside the list is rejected with code `source_ip_not_allowed` (HTTP 403). | `gateway/internal/identity/identity.go` (`AllowedSourceCIDRs`); [config.example.yaml](../../gateway/config.example.yaml) |
| **Bearer token** | The raw virtual-key secret a client sends in the `Authorization` header. The gateway hashes it with SHA-256 and looks the digest up among configured `key_hash` values; it never stores or logs the raw secret. | `gateway/internal/identity/identity.go` package comment |
| **cache_scope_to_end_user** | A per-key boolean (default `false`). When `true`, the `X-Kelvran-End-User-Id` header is folded into the key's L1, L2 and L3-lite cache partitions (an L1/L2 key field, and the per-tenant scope `cache.ScopeKey(vk.ID, endUserScope)` that all three layers bucket on) so one end user's response is never served to another behind the same key. When `true` and the header is absent, the entry gets a request-unique scope derived from the span ID, so it can never be shared. | `gateway/internal/identity/identity.go` (`CacheScopeToEndUser`); `gateway/internal/gateway/dataplane/dataplane.go` (`resolveCacheEndUserScope`, `checkLexicalCache`); `gateway/internal/cache/key.go` (`ScopeKey`) |
| **End-user ID** | The value of the caller-supplied, unauthenticated `X-Kelvran-End-User-Id` header. It is a cache-partitioning signal only, in the same trust class as `agent_run_id`; Kelvran authenticates virtual keys, not end users. | `gateway/internal/gateway/dataplane/dataplane.go` (`EndUserIDHeader`) |
| **key_hash** | The hex-encoded SHA-256 digest of a virtual key's raw secret, stored in config instead of the secret. Example from `config.example.yaml`: the secret `example-team-alpha-secret-do-not-use` has `key_hash: 6701a1ecc6b08958fa24e13f267aac7233d47f390e92e71f8cc8fb3144672cf1`. | `gateway/internal/gateway/controlplane/config.go` (`VirtualKeyConfig.KeyHash`); [config.example.yaml](../../gateway/config.example.yaml) |
| **Rotation grace period** | After a virtual-key rotation, the previous hash (`PreviousKeyHash`) keeps resolving to the same key until `PreviousKeyHashExpiresAt`; after that it fails closed. Only one previous generation is tracked; a second rotation overwrites it. | `gateway/internal/identity/identity.go`; [how-to/rotate-credentials.md](../how-to/rotate-credentials.md) |
| **Tenant** | Synonym for one virtual key. The key's ID is the tenant dimension for rate-limit buckets, budget tracking and cache keys. | `gateway/internal/identity/identity.go` (`VirtualKey.ID`) |
| **Virtual key** | A credential Kelvran itself issues to a client team. In config it is a named entry under `virtual_keys:` holding a `key_hash`, an optional `budget_usd`, optional `allowed_models`, optional `allowed_source_cidrs` and optional rate-limit knobs. Its name (the YAML key) is its ID. | `gateway/internal/gateway/controlplane/config.go` (`VirtualKeyConfig`); [RFC 2026-09-02 virtual keys and budgets](../rfcs/2026-09-02-virtual-keys-budgets.md); [how-to/virtual-keys-and-budgets.md](../how-to/virtual-keys-and-budgets.md) |

## 3. Routing

| Term | Definition | Defined in |
|---|---|---|
| **Adapter** | See *Provider*. |  |
| **Canary** | See *Sticky*. |  |
| **Cost tier** (`cost_tier`) | An operator-set integer per deployment; lower means cheaper. `0` (default) means no tier. A negative value is a config error. The router prefers the lowest tier that has a healthy deployment only when every deployment of that model has a tier; one untiered deployment disables the preference for the whole model group. Not a learned or price-table-derived signal. | `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig.CostTier`); `gateway/internal/router/router.go` |
| **Deployment** | One route from a canonical client-facing `model` to a concrete `provider`, `upstream_model` and `base_url`. Several deployments may share one `model`; the router then spreads requests across them. `base_url` must be `https` unless `allow_insecure_http` is set on that deployment. | `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig`); [how-to/routing-and-failover.md](../how-to/routing-and-failover.md) |
| **Deployment capacity** | A deployment-scoped ceiling, in memory per replica, on RPM (`rate_limit` burst/refill, both set or both unset), TPM (`tpm_capacity`/`tpm_refill_per_second`, both set or both unset, default disabled) or in-flight requests (`max_concurrent_requests`, `<= 0` means unlimited). Exhaustion is a `DeploymentCapacityError` with reason `concurrency`, `rate_limit` or `tpm`, returned as HTTP 503 with code `deployment_capacity_exceeded`, Outcome `OUTCOME_DEPLOYMENT_CAPACITY`, and classified `generic` for fallback. | `gateway/internal/gateway/controlplane/config.go`; `gateway/internal/gateway/dataplane/fallback.go` (`DeploymentCapacityError`); `gateway/cmd/gateway/main.go` |
| **Fallback chain** (`fallback_chains`) | A per-deployment map from a fallback class to an ordered list of other deployment names tried, in order, when a call to this deployment fails with that class. Targets may serve a different model. Empty (default) means the deployment uses the router-based single fallback instead. At most 3 consecutive failed real hops end one chain walk (`maxConsecutiveChainFailures`). | `gateway/internal/gateway/controlplane/config.go` (`FallbackChains`); `gateway/internal/gateway/dataplane/fallback.go`; [RFC 2026-09-07 error-classified fallback chains](../rfcs/2026-09-07-gateway-error-classified-fallback-chains.md) |
| **Fallback class** | One of three strings an upstream failure is classified into: `content_policy`, `context_window_exceeded` or `generic`. `context_window_exceeded` and `content_policy` are detected by keyword match on a non-2xx upstream error body (`UpstreamHTTPError`); `content_policy` is also raised for a provider's in-band safety block (`adapter.ErrProviderContentPolicyBlocked`, Gemini's `promptFeedback.blockReason` on a 200 response). Anything else, including rate limits, a `DeploymentCapacityError`, network failures and every other condition, is `generic`. | `gateway/internal/gateway/dataplane/fallback.go` (`FallbackClass*`, `classifyFallbackError`, `UpstreamHTTPError`); `gateway/internal/adapter/errors.go` (`ErrProviderContentPolicyBlocked`) |
| **Health probe** | A periodic synthetic request to each deployment, shaped by its *Kind* (a 1-token chat completion or a one-string embedding). Off unless `health_probe.interval_seconds > 0`. A deployment leaves routing after `unhealthy_threshold` consecutive failures (default 3) and returns after `healthy_threshold` consecutive successes (default 2), then ramps from `recovery_ramp_initial_percent` (default 20, clamped to 100) of its weight over `recovery_ramp_steps` (default 4) more successes. Kind-shaped probes are on main since 2026-10-08, not in gateway/v0.17.0; in gateway/v0.17.0 every deployment receives the chat-shaped probe. | `gateway/internal/gateway/controlplane/config.go` (`HealthProbeConfig`); `gateway/internal/router/health.go`; [RFC 2026-09-07 active health probing](../rfcs/2026-09-07-gateway-active-health-probing.md) |
| **Kind** (`kind`) | What a deployment serves: `chat` (default; `""` is normalized to `chat`) or `embedding`. The two kinds form disjoint routing pools. `kind: embedding` is accepted only for `provider: openai` or `provider: bedrock`; any other provider fails config load. | `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig.Kind` and its parser) |
| **Latency de-weighting** | A soft, probe-derived reduction of a deployment's effective weight when its rolling-average probe latency is high relative to its model-group peers, applied by a Bresenham-style thinning gate. Traffic-independent: it never learns from real request traffic. | `gateway/internal/router/router.go` package comment; `gateway/internal/router/health.go` (`SetLatencyFactor`) |
| **Model** (`model`) vs **upstream_model** | `model` is the canonical name clients send; routing, `allowed_models`, `price_table` and `GET /v1/models` are keyed by it. `upstream_model` is the provider-side identifier actually sent on the wire and may differ (for example a versioned Anthropic ID). `/v1/embeddings` sends `upstream_model` on the wire on main since 2026-10-08, not in gateway/v0.17.0, which forwarded the canonical name. `GET /v1/models` itself is on main since 2026-10-08, not in gateway/v0.17.0. | `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig.Model`, `UpstreamModel`); `gateway/internal/gateway/dataplane/models.go` |
| **Provider** (`provider`) | The adapter-registry key naming the wire format a deployment speaks: one of `openai`, `anthropic`, `gemini`, `bedrock`, `openaicompat`. An **adapter** is the pure translation between Kelvran's canonical request/response schema and that provider's native shape (`ToProvider`, `FromProvider`, `Name`). | `gateway/cmd/gateway/main.go` (`newAdapterRegistry`); `gateway/internal/adapter/types.go` (`Adapter`); [how-to/provider-credentials.md](../how-to/provider-credentials.md) |
| **Router-based single fallback** | The default failover for a deployment with no `fallback_chains`: on error the router picks one more deployment of the same model. | `gateway/internal/gateway/controlplane/config.go` (`FallbackChains` comment); [config.example.yaml](../../gateway/config.example.yaml) deployments comment |
| **Smooth weighted round-robin (WRR)** | The selection algorithm (the LVS/IPVS `wrr.c` algorithm) the router uses across the deployments of one model, in proportion to each deployment's `weight`. | `gateway/internal/router/router.go`; [RFC 2026-09-04 weighted routing](../rfcs/2026-09-04-weighted-routing.md) |
| **Sticky** (`sticky`) | A boolean (default `false`) marking a deployment as the canary side of a stable/canary pair within its model group. The virtual key's ID is hashed (FNV-1a) into one of 10,000 buckets and compared against a threshold, so raising the canary's weight only adds tenants to the canary side and never moves an already-canary tenant back. | `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig.Sticky`); `gateway/internal/router/sticky.go` |
| **Virtual model alias** | Two or more deployments sharing one `model` value while pointing at different providers or upstream models, so one client-facing name fans out across providers. No separate config construct exists; it is the ordinary shared-`model` case. | [config.example.yaml](../../gateway/config.example.yaml) "Virtual model aliasing" comment; [gateway/ARCHITECTURE.md](../../gateway/ARCHITECTURE.md) router entry |
| **Weight** (`weight`) | A deployment's share of its model group's traffic under WRR. A negative value is a config error; `0` means unset and resolves to weight `1`. The admin API can change it at run time (`deployment_weight` propagation event). | `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig.Weight`); `gateway/internal/router/wrr.go` (`newModelState`) |

## 4. Rate limits, budgets and cost

| Term | Definition | Defined in |
|---|---|---|
| **Billable** | `true` only for a genuine, unshared upstream call this request itself paid for. A cache hit on any layer and a coalesced singleflight follower are not billable, so budget spend, TPM debit and the token-usage counters are recorded once per real upstream call. Span attributes (`kelvran.cost.usd`, token counts) are set regardless. | `gateway/internal/telemetry/result.go` (`Billable`); [RFC 2026-09-05 cost double counting](../rfcs/2026-09-05-gateway-cost-double-counting.md) |
| **Budget** (`budget_usd`) | A virtual key's cumulative USD spending cap, stored as a decimal, never a float. `0` means unlimited. Exceeding it returns code `insufficient_quota` and Outcome `OUTCOME_BUDGET_EXCEEDED`. | `gateway/internal/gateway/controlplane/config.go` (`VirtualKeyConfig.BudgetUSD`); `gateway/internal/identity/identity.go` |
| **Budget alert ladder** | A fixed, non-configurable ladder of 50 %, 75 %, 90 % and 100 % of `budget_usd`. Each bucket is reported once per rolling-window epoch when first crossed. Distinct from `budget_warn_percent`. | `gateway/internal/budget/budget.go` (`BudgetAlertBuckets`) |
| **Budget reset interval** (`budget_reset_interval_seconds`) | When positive, makes `budget_usd` a rolling window of that many seconds (for example `2592000` for 30 days) instead of a lifetime cap. `0` (default) never resets. | `gateway/internal/gateway/controlplane/config.go` (`BudgetResetIntervalSeconds`) |
| **budget_warn_percent** | A fraction of `budget_usd` (for example `0.8`) at or above which the gateway logs `budget_warn_threshold_crossed` on every billable completion. Log-only; the request is never altered. `0` (default) disables it. Meaningless when `budget_usd` is `0`. | `gateway/internal/identity/identity.go` (`BudgetWarnPercent`) |
| **Concurrency limit** | Two different scopes. Per virtual key: `max_concurrent_requests` bounds one caller's in-flight requests (`<= 0` unlimited; rejection code `concurrency_limit_exceeded`, HTTP 429). Per deployment: `max_concurrent_requests` bounds in-flight requests against one deployment across every key (`<= 0` unlimited; a *Deployment capacity* error, HTTP 503). | `gateway/internal/identity/identity.go`; `gateway/internal/gateway/controlplane/config.go` (`DeploymentConfig.MaxConcurrentRequests`) |
| **per_model** | An optional per-key map from a model name to its own RPM `burst`/`refill_per_second` pair, consulted before the key's default bucket, plus an optional `tpm_capacity`/`tpm_refill_per_second` pair (both set or neither). `burst` and `refill_per_second` must both be positive; a missing or non-positive value fails config load (`must set positive burst and refill_per_second`) and is a 400 on the admin API. Enforced in in-memory and Redis mode. | `gateway/internal/gateway/controlplane/config.go` (`ModelRateLimitConfig`, `parsePerModelRateLimits`); `gateway/internal/ratelimit/limiter.go` (`KeyConfig.PerModel`); `gateway/internal/admin/admin.go` (`per_model` validation) |
| **Reserve-then-reconcile** | The TPM accounting order: tokens are reserved from the bucket before the upstream call (the bucket's running mean of past real counts; the full balance on cold start), reconciled to the real count after a success, and released after a failure. Applied per hop for deployment-scoped TPM, so a fallback hop reserves against the target deployment's bucket. | `gateway/internal/gateway/dataplane/deployment_tpm.go`; `gateway/internal/ratelimit/limiter.go` |
| **Retry-After / retry-storm mitigation** | On a rate-limit, deployment-capacity or upstream-error rejection, the gateway attaches a `Retry-After` header computed by per-key equal-jitter exponential backoff: base 500 ms, doubling per consecutive rejection, capped at 30 s, reset on the next success. If the provider's own `Retry-After` is larger it is used instead, capped at 60 s. Budget, guardrail, model-not-allowed and auth rejections carry no `Retry-After`. | `gateway/internal/ratelimit/backoff.go`; `gateway/internal/gateway/dataplane/retry_after.go`; `gateway/internal/gateway/dataplane/upstream_error.go`; [RFC 2026-09-07 retry-storm mitigation](../rfcs/2026-09-07-gateway-retry-storm-mitigation.md) |
| **RPM (requests per minute)** | A per-virtual-key token bucket with `burst` (capacity) and `refill_per_second`. A key that sets neither gets the gateway defaults `burst: 20`, `refill_per_second: 10`; setting only one of the pair is a config-load error. Rejection code `rate_limit_exceeded`, HTTP 429, Outcome `OUTCOME_RATE_LIMITED`. | `gateway/internal/ratelimit/limiter.go` (`DefaultKeyBurstCapacity`, `DefaultKeyRefillPerSecond`); `gateway/internal/gateway/controlplane/config.go` (`validateRateLimitPair`) |
| **TPM (tokens per minute)** | A separate per-virtual-key bucket (`tpm_capacity`, `tpm_refill_per_second`; `<= 0` means no TPM limit) counted in raw tokens, enforced in in-memory and Redis mode using *reserve-then-reconcile*. Deployments have their own TPM bucket (see *Deployment capacity*). | `gateway/internal/ratelimit/limiter.go` (`KeyConfig.TPMCapacity`); `gateway/internal/ratelimit/redislimiter/redislimiter.go` (`AllowTPM`, `AdjustTPM`) |
| **tpm_accounting** | Deployment-only weighting of the TPM count to match a provider's quota math: `output_token_multiplier` (unset means 1; values in `(0, 1)` or below 0 are rejected) and `exclude_cache_read_tokens` (default `false`). Weighted count = prompt tokens, minus cache-read tokens when excluded, plus completion tokens times the multiplier. The per-key TPM dimension is never weighted. | `gateway/internal/gateway/controlplane/config.go` (`TPMOutputTokenMultiplier`, `TPMExcludeCacheReadTokens`) |

## 5. Response cache

| Term | Definition | Defined in |
|---|---|---|
| **Cache key fields** | Every L1 and L2 key folds: layer tag, tenant (virtual key ID), model, serialized or normalized messages, `temperature`, `max_tokens`, guardrail policy version, `response_format` fingerprint, prompt fingerprint, end-user scope, `thinking_binding_mode` and the tools fingerprint. The layer tag keeps L1 and L2 keys from ever colliding. | `gateway/internal/cache/key.go` (`Key`, `NormalizedKey`); [RFC 2026-10-08 cache key tools fingerprint](../rfcs/2026-10-08-gateway-cache-key-tools-fingerprint.md) |
| **Fingerprint / NegationFingerprint** | Two hard-gate inputs. `Fingerprint` is the set of numbers, dates and capitalized multi-token sequences in a query (regex-based, no NER model, biased toward over-inclusion). `NegationFingerprint` is the set of negation particles present. An L3 candidate must match both sets exactly. | `gateway/internal/gateway/dataplane/entities.go` |
| **Guardrail policy version** (`guardrails.policy_version`) | A string stamped into every cache write. Default `v1`. Bump it when detectors or policy change so entries written under the old policy become misses. | `gateway/internal/gateway/controlplane/config.go` (`GuardrailsConfig.PolicyVersion`) |
| **Hard gate** | The mandatory checks an L3-lite candidate must pass before it is served: volatile-query bypass, entity/number/date fingerprint equality, the freshness/risk model (a single 24 h staleness budget, the `l3MinSimilarity` floor and model-ID equality), negation-particle equality, and exact equality on guardrail policy version, `response_format`, prompt, reasoning-block and tools fingerprints and on `thinking_binding_mode`. The tools-fingerprint gate is on main since 2026-10-08, not in gateway/v0.17.0. The gate names in telemetry are `volatile_bypass`, `entity_mismatch`, `freshness_risk_model` and `negation_mismatch`. Weakening the gate in favour of a bare similarity threshold is forbidden. | `gateway/internal/gateway/dataplane/dataplane.go` (`l3StalenessBudget`, `freshnessRiskModel`, `checkLexicalCache`); `gateway/internal/telemetry/telemetry.go` (`CacheL3Gate*`); [explanation/cache-gate.md](../explanation/cache-gate.md); [RFC 2026-10-08 cache key tools fingerprint](../rfcs/2026-10-08-gateway-cache-key-tools-fingerprint.md) |
| **Idempotency-Key** | A client header that claims a per-tenant, body-fingerprinted slot for 10 minutes (`idempotencyKeyTTL`). A duplicate with the same key and body replays the stored response; a duplicate arriving while the original is in flight waits for it. | `gateway/internal/gateway/dataplane/dataplane.go` (`idempotencyKeyTTL`, `idempotencyStoreKey`) |
| **L1** | Exact-match layer: a SHA-256 key over the fields above. Default TTL 5 minutes (`cache.ttl_seconds`). | `gateway/internal/gateway/dataplane/dataplane.go` (`CacheTTL` default); `gateway/internal/cache/key.go` (`Key`) |
| **L2** | Normalized-match layer: the same key fields over messages normalized by outer-whitespace trim, Unicode NFC and one trailing terminal punctuation mark stripped from the last message only. Default TTL 75 seconds. | `gateway/internal/gateway/dataplane/dataplane.go` (`CacheL2TTL` default, `normalizeMessages`); `gateway/internal/cache/key.go` (`NormalizedKey`) |
| **L3-lite** | Lexical near-duplicate layer: per-tenant MinHash signatures (3-word shingles, 128 hash values) searched for the top 5 candidates by estimated Jaccard similarity; a candidate needs similarity at or above `l3MinSimilarity = 0.9` and must pass every *hard gate*. Default TTL 5 minutes. Never embedding-based. | `gateway/internal/cache/lexical.go`; `gateway/internal/gateway/dataplane/dataplane.go` (`l3ShingleWords`, `l3SignatureSize`, `l3SearchK`, `l3MinSimilarity`); [RFC 2026-09-03 L3-lite](../rfcs/2026-09-03-cache-l3-lite-lexical-hard-gated.md) |
| **LexicalCandidate** | One L3-lite search hit: the stored entry plus its Jaccard-estimate similarity and the provenance the hard gate checks (including `GuardrailPolicyVersion`). | `gateway/internal/cache/lexical.go` (`LexicalCandidate`) |
| **LRU bound** | Every in-process cache instance is bounded per tenant: `maxEntries <= 0` resolves to 10,000 entries per tenant for L1, L2 and L3-lite alike, evicted LRU inside that tenant's own bucket, never a shared cap across tenants, and there is no unbounded mode. TTLs carry 10 % jitter by default. | `gateway/internal/cache/inprocess/inprocess.go` (`defaultMaxEntries`, `defaultJitterFraction`, `exactMatchTenantBucket`); `gateway/internal/cache/inprocess/lexical.go` (`NewLexicalCache`) |
| **Singleflight / coalescing** | Concurrent identical requests share one upstream call; the followers receive the leader's response and are not *billable*. | `gateway/internal/telemetry/telemetry.go` token-counter comment; `gateway/internal/telemetry/result.go` (`Billable`) |

## 6. Request-level features

| Term | Definition | Defined in |
|---|---|---|
| **Error envelope** | The OpenAI-shaped JSON body `{"error":{"message","type","param","code"}}` returned for every client-facing error on `/v1/chat/completions` and `/v1/embeddings`, with a stable `code` such as `invalid_api_key`, `rate_limit_exceeded`, `insufficient_quota`, `concurrency_limit_exceeded`, `deployment_capacity_exceeded`, `model_not_allowed`, `source_ip_not_allowed`. HTTP status codes are the same as in gateway/v0.17.0. The JSON envelope is on main since 2026-10-08, not in gateway/v0.17.0, which returned `text/plain` bodies. | `gateway/cmd/gateway/error_envelope.go`; [reference/error-codes.md](error-codes.md) |
| **Guardrails** | Pre-call and post-call content checks over six categories. Default actions: `credential`, `financial_id`, `government_id` are `block`; `contact_info`, `network_id`, `prompt_injection` are `warn`. `guardrails.category_overrides` maps a category to `block` or `warn`. The same defaults apply on detector error. A block returns Outcome `OUTCOME_GUARDRAIL_BLOCKED`. Optional additional detectors: AWS Bedrock Guardrails (`PROMPT_ATTACK`) and an embedding-similarity prompt-injection detector; both are additive to the regex detectors, never replacements. | `gateway/internal/guardrail/types.go`; `gateway/internal/guardrail/policy.go` (`DefaultPolicy`); `gateway/internal/gateway/controlplane/config.go` (`GuardrailsConfig`) |
| **Overhead header** (`X-Kelvran-Overhead-Duration-Ms`) | On a buffered chat completion, the gateway's own added latency in milliseconds: total wall-clock time minus the real upstream round-trip (including fallback retries and backoff). Not set on the streaming path. | `gateway/cmd/gateway/main.go` (`overheadDurationHeader`); [RFC 2026-09-14 overhead header](../rfcs/2026-09-14-gateway-overhead-duration-header.md) |
| **Prompt** (`prompt_id`, `prompt_version`, `prompt_label`, `prompt_variables`) | A server-side, operator-managed message template resolved into real messages before routing. `prompt_id` names it; `prompt_version` pins a version (`<= 0` means latest); `prompt_label` resolves whichever version a named label points at; setting both version and label is a client error. `prompt_variables` supplies `{{name}}` substitutions. ## 10. Not available today

Terms a reader may expect that name nothing in the code:

- **Semantic (embedding-based) L3 cache.** L3-lite is lexical (MinHash/Jaccard) only; `gateway/internal/cache/lexical.go` states "never embedding-based". Recorded as not built in [README.md](../../README.md) "Status and known limitations".
- **Redis-backed shared cache.** Every cache layer is in-process per replica. A design RFC exists ([RFC 2026-09-11](../rfcs/2026-09-11-gateway-redis-backed-cache-design.md)); nothing is built.
- **Session- or agent_run_id-level cost roll-up.** Cost finalize is per request; aggregating across a run means summing spans or `gatewayevents_v1` lines downstream ([gateway/ARCHITECTURE.md](../../gateway/ARCHITECTURE.md) request lifecycle).
- **Traffic-derived circuit breaker.** Health is probe-derived (see *Health probe*); there is no outlier detection or cooldown learned from real request failures (`gateway/internal/router/router.go` package comment).
- **Automatic price discovery.** *Cost tier* is operator-set; the gateway never derives it from the price table or from usage.
- **MCP/A2A brokering**, an admin web UI, a first-party SDK, an OpenAPI spec and a Helm chart are not built, by recorded decision; see [README.md](../../README.md) and [explanation/mcp-a2a-status.md](../explanation/mcp-a2a-status.md).
