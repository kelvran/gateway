# Kelvran vs Portkey AI Gateway

Kelvran is a self-hosted LLM gateway: one static Go binary (`github.com/kelvran/gateway/gateway`) plus a separate Python evals CLI, licensed Apache-2.0, with no hosted offering ([VERSIONING.md](../../VERSIONING.md), [security model](../security-model.md)). Portkey AI Gateway (`Portkey-AI/gateway`) is a TypeScript gateway on the Hono framework whose repository describes itself as routing to "1,600+ LLMs" with "50+ AI Guardrails"; the MIT repository is one part of a product whose documentation marks several features as hosted-only or enterprise-only, and whose homepage reads "Portkey is now PRISMA AIRS AI Gateway" ([repository](https://github.com/Portkey-AI/gateway), [portkey.ai](https://portkey.ai/)). This page compares the two as of 2026-10-09. Kelvran facts describe the `main` branch at commit `0863cb09`, 26 commits past `gateway/v0.17.0` and included in `gateway/v0.18.0` (2026-10-10); anything absent from `gateway/v0.17.0` is marked "since `gateway/v0.18.0`". Facts about Portkey AI Gateway come from its own documentation and repository on that date; verify before relying on them. Where Portkey's documentation distinguishes the open-source build from the hosted or enterprise edition, the cell says which one it describes. Every source is listed under [Sources](#sources) at the end.

## TL;DR

- Kelvran's one differentiator on this page is the correctness-gated near-duplicate cache. An L3 candidate is served only if its entity/number/date fingerprint set and its negation-particle set are *equal* to the request's, it is at most 24 h old, at or above 0.9 Jaccard, written for the same model id, and its policy-version, `response_format`, prompt, reasoning, thinking-binding and (since `gateway/v0.18.0`) tools fingerprints match exactly. The floor and the gate are Go constants with no config knob, and [AGENTS.md](../../../AGENTS.md) forbids shipping a change that weakens the gate "in favor of a bare similarity threshold" ([cache gate](../cache-gate.md)). Portkey's semantic cache is documented as cosine similarity above a threshold (default 0.95) plus exact match on model and parameters; it ignores the system prompt and documents no entity, negation or freshness gate beyond `max_age` ([Portkey cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic)).
- Portkey is older, larger and more featureful: first release 2024-01-03, 81 tags, 13,153 stars, a hosted cloud marked "Recommended", an Anthropic Messages endpoint, a 49-provider integration index, nested fallback/loadbalance/conditional routing, automatic retries and a circuit breaker. Kelvran is five weeks old with 0 stars, one maintainer, five provider adapters and no `/v1/messages`.
- The licence boundaries differ. Every Kelvran feature ships under Apache-2.0, in the gateway binary or the evals CLI. Portkey's repository is MIT, but budget limits, audit logs and semantic caching are documented as enterprise or select-Pro features, the Prometheus endpoint is documented only under the enterprise self-hosting docs with no counterpart in the MIT codebase, and the control-plane connection belongs to the enterprise hybrid deployment, and the enterprise gateway is versioned separately (v2.28.0 on 2026-10-08 against OSS v1.15.2 on 2026-01-12).
- Supply chain: Kelvran pins every GitHub Action to a commit SHA, publishes a cosign-signed image with a CycloneDX SBOM and SLSA Build L2 provenance (multi-arch since `gateway/v0.18.0`; the `:v0.17.0` image is amd64-only), and runs Dependabot, Scorecard and CodeQL; its 31 GitHub Releases before `gateway/v0.18.0` carry zero assets (`gateway/v0.18.0` is the first the asset-signing pipeline runs for). Portkey's workflows pin actions to mutable tags, publish to npm without `--provenance`, build the open-source image with no cosign or SBOM step (the enterprise image is Cosign-signed per its changelog), have no Dependabot configuration, and its releases also carry no assets.
- No cost or performance numbers appear here: Kelvran publishes none ([BENCHMARKS.md](../../operations/BENCHMARKS.md)), and this page quotes no Portkey benchmarks.

## Choose Kelvran if …

- You need per-key USD budgets, TPM limits and concurrency caps enforced inside the open-source binary with no control plane and no plan gate ([virtual keys and budgets](../../how-to/virtual-keys-and-budgets.md)). Portkey documents provider budget limits and rate limits as "Available on Enterprise plan and select Pro customers" ([budget limits](https://portkey.ai/docs/product/ai-gateway/virtual-keys/budget-limits)).
- You attribute spend per agent run: the W3C `baggage` member `agent_run_id` becomes a span attribute, a field on every decision event next to `cost_usd`, and a key in the per-key in-flight breakdown ([metrics and logs](../../reference/metrics-and-logs.md)). Portkey attributes cost per trace, per metadata key and per `_user` ([traces](https://portkey.ai/docs/product/observability/traces), [metadata](https://portkey.ai/docs/product/observability/metadata)).
- You need a near-duplicate cache hit to be refused when a number, date, capitalised entity or negation differs, with no deploy-time knob to loosen it ([cache gate](../cache-gate.md)).
- Your procurement asks for SHA-pinned CI, a signed image, an SBOM and provenance today ([release artifacts](../../reference/release-artifacts.md)).
- You want one Apache-2.0 licence over everything, with no hosted or enterprise split ([LICENSE](../../../LICENSE), [README](../../../README.md)).
- Your observability is OpenTelemetry-native and you do not need a Prometheus scrape endpoint or a vendor dashboard ([metrics and logs](../../reference/metrics-and-logs.md)).

## Choose Portkey AI Gateway if …

- You want a hosted gateway with dashboard, logs and analytics, reached by pointing an OpenAI SDK at `https://api.portkey.ai/v1` or an Anthropic SDK at `https://api.portkey.ai` ([universal API](https://portkey.ai/docs/product/ai-gateway/universal-api)). Kelvran has no hosted offering.
- You need the Anthropic Messages API: `POST /v1/messages` is present in the MIT codebase and documented on all plans ([Messages API](https://portkey.ai/docs/product/ai-gateway/messages-api)). Kelvran does not register the route and does not read `x-api-key`, so the `anthropic` SDK and Claude Code cannot use it for chat ([compatibility](../../reference/compatibility.md)).
- You need providers beyond OpenAI, Anthropic, Gemini, Bedrock and OpenAI-compatible servers: Portkey's integration index lists 49 ([integrations](https://portkey.ai/docs/integrations/llms)). Kelvran has exactly five adapters.
- You want paraphrase-tolerant semantic caching: embedding cosine over Milvus or Pinecone; the cache docs say "select Enterprise plans" while the pricing page lists "Simple & Semantic Caching" under the $49 Production plan ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic), [pricing](https://portkey.ai/pricing)). Kelvran's L3 is lexical MinHash and misses genuine paraphrases by design ([cache gate](../cache-gate.md)).
- You need nested fallback/loadbalance/conditional configs, automatic retries with exponential backoff, configurable request timeouts and a passive circuit breaker on all plans ([configs](https://portkey.ai/docs/product/ai-gateway/configs), [retries](https://portkey.ai/docs/product/ai-gateway/automatic-retries), [circuit breaker](https://portkey.ai/docs/product/ai-gateway/circuit-breaker)). Kelvran has no same-deployment retry, compiled-in timeouts and no traffic-derived circuit breaker ([routing and failover](../../how-to/routing-and-failover.md)).
- You need organisation and workspace hierarchy, SSO, audit logs, or SOC 2 / ISO 27001 / HIPAA claims: Portkey's enterprise offering documents them ([enterprise offering](https://portkey.ai/docs/product/enterprise-offering)). Kelvran has flat per-key budgets, one maintainer and no compliance attestations ([security model](../security-model.md)).
- You want a project with releases going back to January 2024 (last open-source release January 2026) and a 13,153-star community rather than a five-week-old repository with 0 stars ([repository API](https://api.github.com/repos/Portkey-AI/gateway)).

## Cache semantics

| Aspect | Kelvran | Portkey AI Gateway |
|---|---|---|
| Layers and modes | Three in-process layers, always on, no off switch, empty after restart, each partitioned per virtual key with its own LRU cap: L1 exact, L2 normalised (trim, Unicode NFC, strip one trailing `.` `!` `?`), L3 lexical MinHash/Jaccard over 3-word shingles ([caching](../../how-to/caching.md)) | Hosted/enterprise: "simple" (exact) and "semantic" (embedding cosine; exact checked first). OSS `main`: an in-memory middleware handling mode `simple` only, keyed on SHA-256 of body+URL, off by default, skipping streams; semantic constants exist but no semantic lookup is implemented ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic), [cache/index.ts](https://raw.githubusercontent.com/Portkey-AI/gateway/main/src/middlewares/cache/index.ts), [conf.json](https://raw.githubusercontent.com/Portkey-AI/gateway/main/conf.json)) |
| What gates a near-match hit | Volatile-query bypass when a user message matches `weather\|price\|stock\|score\|today\|current\|currently\|now\|latest`; entity/number/date fingerprint set equality; negation-particle set equality; age at most 24 h, Jaccard at least 0.9, same model id; exact equality on policy version, `response_format`, prompt, reasoning, thinking-binding and tools/tool_choice fingerprints (tools gate since `gateway/v0.18.0`); any rejection or search error goes upstream; no config knob ([cache gate](../cache-gate.md), [caching](../../how-to/caching.md)) | Cosine similarity above the threshold (default 0.95) plus exact match on model, temperature, max_tokens and all other body parameters; the system prompt is ignored; needs at least one user message, under 8,191 tokens, at most 4 messages; `/chat/completions` and `/completions` only; no entity, negation, freshness or staleness gate beyond `max_age` is documented ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic)) |
| TTL and capacity | Defaults L1 300 s, L2 75 s, L3 300 s; 10,000 entries per key per layer; jitter fraction 0.10 cannot be disabled; L3 has a 24 h staleness ceiling no TTL can lift; cache section read at startup only ([config](../../reference/config.md), [caching](../../how-to/caching.md)) | `max_age` in seconds: minimum 60 s, maximum 90 days, default 7 days; an org default caps the request value; enterprise advertises "unlimited" TTL; the OSS middleware defaults to 24 h ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic), [enterprise offering](https://portkey.ai/docs/product/enterprise-offering), [cache/index.ts](https://raw.githubusercontent.com/Portkey-AI/gateway/main/src/middlewares/cache/index.ts)) |
| Invalidation | Bump `guardrails.policy_version` and restart; `POST /admin/cache/erase` removes one request's L1 and L2 entries on one replica, L3 is never erased (`l3_skipped: true`, interface has no `Delete`); no client no-cache header, no per-key opt-out ([caching](../../how-to/caching.md), [admin API](../../reference/admin-api.md)) | Per-request `x-portkey-cache-force-refresh` (for semantic hits, refreshes all matching entries); `x-portkey-debug: false` disables caching; no bulk purge documented on the cache page ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic)) |
| Partitioning and sharing | Per virtual key, optional end-user scope via `X-Kelvran-End-User-Id`; in-process per replica; no Redis or shared cache; streaming served from and written to cache; `finish_reason: length` never written ([caching](../../how-to/caching.md)) | Partitioned by all request headers by default; `x-portkey-cache-namespace` overrides; enterprise self-hosted uses a Redis-compatible store; semantic requires Milvus or Pinecone and "select Enterprise plans" ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic), [cache behavior](https://portkey.ai/docs/aigw/self-hosting/cache-behavior)) |

## FAQ

**Can I point the `anthropic` SDK or Claude Code at either gateway?** At Portkey, yes: `POST /v1/messages` is in the MIT repo and documented on all plans. At Kelvran, no: the route is not registered and `x-api-key` is not read; the OpenAI SDK `base_url` override is the only client path ([compatibility](../../reference/compatibility.md), [why no SDK](../why-no-sdk.md)).

**Which Portkey features work in the open-source build without the hosted control plane?** Portkey's docs route Model Catalog, budgets, rate limits and the dashboard through `app.portkey.ai`; the pricing page lists the open-source tier as Universal API, Retries & Timeouts, Routing, Guardrails, Automatic Fallbacks, Load Balancing, Community Support and a "Basic Dashboard"; the OSS `main` cache middleware is simple-mode and off by default, and `src/apm/index.ts` is a console alias. Whether budgets, semantic cache or Prometheus function in the MIT build alone is not established from primary sources on 2026-10-09 ([pricing](https://portkey.ai/pricing), [cache/index.ts](https://raw.githubusercontent.com/Portkey-AI/gateway/main/src/middlewares/cache/index.ts)).

**Which one runs with no vendor connection at all?** Kelvran: a binary, a mounted `config.yaml`, and optional Redis; there is no control plane ([config](../../reference/config.md)). Portkey OSS `start-server.ts` calls `serve({ fetch, port })` with no `hostname`, so it listens on all interfaces (the deployment doc's `docker run -p 8787:8787` relies on that) and merely prints `http://localhost:<port>`; the server, handler, log and cache files read contain no outbound Portkey calls, but not every source file was audited; the enterprise hybrid mode requires outbound HTTPS to Portkey's control plane and sends usage counters back ([start-server.ts](https://raw.githubusercontent.com/Portkey-AI/gateway/main/src/start-server.ts), [deployment doc](https://raw.githubusercontent.com/Portkey-AI/gateway/main/docs/installation-deployments.md), [cache behavior](https://portkey.ai/docs/aigw/self-hosting/cache-behavior), [architecture](https://portkey.ai/docs/product/enterprise-offering/private-cloud-deployments/architecture)).

**How does each cache decide a near-match is safe?** Kelvran asks yes/no questions and serves only if every answer is yes: same entities, numbers and dates, same negation particles, under 24 h, at or above 0.9 Jaccard, same model, same policy and prompt provenance; a paraphrase is a miss, a one-synonym swap is a hit ([cache gate](../cache-gate.md)). Portkey's semantic cache serves on cosine similarity above 0.95 with exact parameter match and ignores the system prompt ([cache docs](https://portkey.ai/docs/product/ai-gateway/cache-simple-and-semantic)).

**Are the published artifacts signed?** Kelvran's container image has carried a cosign signature, SBOM and SLSA L2 provenance since 2026-09-13; no GitHub Release before `gateway/v0.18.0` has assets, so `gateway/v0.18.0` carries the first signed binaries ([release artifacts](../../reference/release-artifacts.md)). Portkey's releases have no assets, the npm package has no provenance attestation and the open-source image has no cosign signature or SBOM, only BuildKit's default SLSA v0.2 provenance (the enterprise image is Cosign-signed per its changelog) ([npm 1.15.2](https://registry.npmjs.org/@portkey-ai/gateway/1.15.2), [manifest](https://registry-1.docker.io/v2/portkeyai/gateway/manifests/latest)).

**What does each project say about its own production status?** Kelvran lists "Live pilot traffic" for Bedrock, untested Kubernetes manifests and five open v0.17.0 defects ([README](../../../README.md)). Portkey recommends its hosted cloud, has not cut an OSS release since 2026-01-12 or a commit since 2026-05-25, and now presents itself as PRISMA AIRS AI Gateway; the reasons are not stated in any primary source fetched ([commits](https://api.github.com/repos/Portkey-AI/gateway/commits?per_page=5), [portkey.ai](https://portkey.ai/)).
