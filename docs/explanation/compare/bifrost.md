# Kelvran vs Bifrost

Kelvran is a self-hosted, Apache-2.0 LLM gateway: one static Go binary that exposes an OpenAI-shaped `/v1` surface over five provider adapters, with per-virtual-key budgets and rate limits, a three-layer in-process cache and OpenTelemetry export, plus a separate Python evals CLI. Bifrost ([maximhq/bifrost](https://github.com/maximhq/bifrost)) is an Apache-2.0 Go AI gateway by Maxim AI that fronts 23+ providers behind OpenAI-compatible and provider-native endpoints, ships a web UI and a management API, and has a separately licensed Enterprise build. This page compares the two as of 2026-10-09. Kelvran cells cite the repository at HEAD 0863cb09 (26 commits past the `gateway/v0.17.0` tag) and say when something is on `main` only, because it is then in no release; facts about Bifrost come from its own documentation and repository on that date; verify before relying on them. A cell that neither side's primary sources settle says so instead of guessing. Every source is listed at the end.

## TL;DR

- Both are self-hosted Go gateways under Apache-2.0. Bifrost adds a commercial Enterprise build (clustering, adaptive load balancing, circuit breaker, guardrails, OIDC/SCIM, RBAC, audit logs) and a built-in web UI; Kelvran has one tier, no UI and no hosted offering ([README](../../../README.md); [enterprise/overview](https://docs.getbifrost.ai/enterprise/overview.md); [user-provisioning](https://docs.getbifrost.ai/enterprise/user-provisioning.md)).
- Kelvran's container image is signed and attested; its release assets are not yet. The image has carried a cosign keyless signature, an attested CycloneDX SBOM and SLSA Build Level 2 provenance on every push since 2026-09-13, so the `:v0.17.0` image (a single `linux/amd64` manifest, signed with plain `cosign sign`) is verifiable today; a linux/amd64+arm64 index signed with `cosign sign --recursive`, and a release-asset pipeline (syft SBOM per asset, `cosign sign-blob` over `checksums.txt`, provenance over every asset), are on `main` since 2026-10-08 and first run at the next `gateway/v*` tag; all 31 existing GitHub Releases carry zero assets ([release-artifacts](../../reference/release-artifacts.md)). Bifrost's release workflow uploads binaries to Cloudflare R2 and pushes images with no cosign, SBOM or attestation step, its GitHub attestations page lists none, and its npm packages do carry npm provenance ([release-pipeline.yml](https://raw.githubusercontent.com/maximhq/bifrost/dev/.github/workflows/release-pipeline.yml); [attestations](https://github.com/maximhq/bifrost/attestations); [npx-publish.yml](https://raw.githubusercontent.com/maximhq/bifrost/dev/.github/workflows/npx-publish.yml)).
- Surface: Bifrost mounts OpenAI `/v1/*` (chat, responses, embeddings, audio, images, rerank, ocr) and provider-native prefixes including `POST /anthropic/v1/messages`; Kelvran registers five routes (chat completions, embeddings, models on `main`, healthz, readyz) and no Anthropic Messages route ([data-plane-api](../../reference/data-plane-api.md); [openapi.json](https://docs.getbifrost.ai/openapi/openapi.json)).
- Cache: Kelvran's third layer is lexical MinHash behind entity, number, date and negation equality gates, always on, in-process and without a knob; Bifrost's semantic cache is embedding cosine similarity (default 0.8), opt-in per request, backed by an external vector store, with management-API invalidation ([cache-gate](../cache-gate.md); [semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)).
- Governance and maturity: Bifrost has Customer > Team > Virtual Key budgets, CEL routing rules, a Prometheus `/metrics` endpoint, about 8.7k stars and gateway releases since 2025-07-17; Kelvran has flat per-key budgets, weighted round-robin with fallback chains, OTel-only export with `agent_run_id` attribution, 0 stars, a single maintainer and a first commit on 2026-09-02 ([VERSIONING](../../VERSIONING.md); [GitHub API](https://api.github.com/repos/maximhq/bifrost)).

## Choose Kelvran if …

- You want a static gateway binary (with its companion CLI beside it) in a `FROM scratch` image with no datastore for a single replica: caches are in-process and Redis is optional, needed only for multi-replica budgets, identity, rate limits and config propagation ([container-image](../../reference/container-image.md), [virtual-keys-and-budgets](../../how-to/virtual-keys-and-budgets.md)).
- You want cache reuse decided by equality gates (entities, numbers, dates, negation, model, policy version) plus a 24 h freshness bound rather than by a similarity threshold, and you accept that there is no knob to loosen it ([cache-gate](../cache-gate.md)).
- You attribute spend per agent run: the W3C `baggage` member `agent_run_id` lands on the span and on the per-request decision event next to `cost_usd` ([metrics-and-logs](../../reference/metrics-and-logs.md)).
- Your telemetry already flows through an OpenTelemetry collector and you do not need a scrape endpoint ([metrics-and-logs](../../reference/metrics-and-logs.md)).
- You want a verifiable image signature, SBOM attestation and SLSA provenance on the image today and signed release assets from the next tag, with every workflow on `permissions: {}` and SHA-pinned actions ([release-artifacts](../../reference/release-artifacts.md)).
- You can live with a five-week-old pre-1.0 project with one maintainer, zero stars, five documented open defects in `gateway/v0.17.0` and production evidence limited to a Bedrock pilot ([README](../../../README.md)).

## Choose Bifrost if …

- You need Anthropic Messages ingress (the Anthropic SDK, Claude Code), the Responses API, audio, image, rerank or OCR routes: Kelvran serves none of these ([api.md](https://docs.getbifrost.ai/_llms/api.md); [claude-code](https://docs.getbifrost.ai/cli-agents/claude-code); [compatibility](../../reference/compatibility.md)).
- You need more than five providers; Bifrost's matrix lists 31 ([supported-providers](https://docs.getbifrost.ai/providers/supported-providers/overview)).
- You need hierarchical budgets (Customer > Team > Virtual Key > provider config), calendar-aligned resets, temporary budget overrides or model-level limits; Kelvran's budgets are flat per key ([budget-and-limits](https://docs.getbifrost.ai/features/governance/budget-and-limits)).
- You want a web UI, a management API, a request log store with content and retry trails, a Helm chart and deployment guides for the major clouds ([setting-up](https://docs.getbifrost.ai/quickstart/gateway/setting-up); [deployment-guides](https://docs.getbifrost.ai/deployment-guides/overview.md)).
- You need Prometheus to scrape the gateway directly, expression-based (CEL) routing, complexity routing or session affinity ([prometheus](https://docs.getbifrost.ai/features/observability/prometheus); [routing-rules](https://docs.getbifrost.ai/providers/routing-rules.md)).
- You want a project with about 8.7k stars, releases since 2025-06, a commercial vendor behind it, and, under an Enterprise licence, HA clustering with replicated governance counters, adaptive load balancing and a circuit breaker; Kelvran has none of these ([GitHub API](https://api.github.com/repos/maximhq/bifrost); [enterprise/overview](https://docs.getbifrost.ai/enterprise/overview.md)).

## Cache semantics

| Aspect | Kelvran | Bifrost |
|---|---|---|
| Layers | Three in-process layers, always on, no off switch, empty after every restart: L1 exact, L2 normalized (hit promoted to L1), L3-lite lexical near-duplicate, then upstream; every layer partitioned per virtual key with its own LRU cap, so one tenant cannot evict another ([caching](../../how-to/caching.md)). | One plugin (`plugins/semanticcache`) with a direct mode (the request "is normalized and hashed" for exact-match replay) and a semantic mode (embedding similarity); direct runs first, semantic only on a direct miss ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)). |
| Normalization | Exactly three operations: outer whitespace trim, Unicode NFC, strip one trailing `.`, `!` or `?` from the last message; no case folding, no internal whitespace collapse ([caching](../../how-to/caching.md)). | Not established from primary sources on 2026-10-09 beyond "normalized and hashed" ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)). |
| Semantic match | L3 is lexical MinHash/Jaccard: 3-word shingles hashed with FNV-64a, 128-value signature, top-5 candidates, similarity floor 0.9, 24 h staleness budget; all Go constants with no config knob; no embeddings ([cache-gate](../cache-gate.md)). | Cosine similarity on embeddings, default threshold 0.8; needs an embedding provider and model with a matching `dimension`; a per-request `x-bf-cache-threshold` can only raise the configured threshold, capped at 1.0 ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching), [v2.2.6 notes](https://github.com/maximhq/bifrost/releases/tag/transports%2Fv2.2.6)). |
| What gates a hit | A volatile-query bypass when any user message matches a fixed word list (weather, price, stock, score, today, current, currently, now, latest); entity/number/date fingerprint set equality; negation-particle set equality; age at most 24 h, similarity at least 0.9 and the same model id; exact equality on guardrail policy version, `response_format`, prompt, reasoning blocks, `thinking_binding_mode` and (on `main`) tools and `tool_choice`; any rejection or search error falls through to a real upstream call ([cache-gate](../cache-gate.md), [caching](../../how-to/caching.md)). | The only documented content gate is `conversation_history_threshold` (default 3: skip caching past that many messages); no entity, freshness or temperature gate is described and no tool-call exclusion is documented ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)). |
| TTL and capacity | L1 300 s, L2 75 s, L3 300 s; `max_entries` 10,000 per virtual key per layer; `jitter_fraction` 0.10 (up to 10% of the TTL added as random extra lifetime on every write) that cannot be disabled; the cache section is read at startup only ([config](../../reference/config.md), [caching](../../how-to/caching.md)). | Default TTL 5m; per-request `x-bf-cache-ttl`, `x-bf-cache-type` (direct or semantic) and `x-bf-cache-no-store`; entries persist across restarts ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)). |
| Opt-in and scope | Always on for every request; no client no-cache header, no per-key opt-out; optional end-user scoping via `X-Kelvran-End-User-Id` when `cache_scope_to_end_user` is set ([caching](../../how-to/caching.md), [config](../../reference/config.md)). | Opt-in: a request needs `x-bf-cache-key` or a configured `default_cache_key`, otherwise it bypasses the cache; entries partitioned per virtual key since HTTP v2.2.6 (pre-upgrade entries not reused); `cache_by_model` and `cache_by_provider` default true, `exclude_system_prompt` default false ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching), [v2.2.6 notes](https://github.com/maximhq/bifrost/releases/tag/transports%2Fv2.2.6)). |
| Invalidation | Bump `guardrails.policy_version` (folded into every L1/L2 key and an L3 equality gate) and restart; `POST /admin/cache/erase` removes one request's L1 and L2 entries on one replica given the exact original fields; L3 is never erased (`LexicalCache` has `Search` and `Put`, no `Delete`); get-then-delete is not atomic ([caching](../../how-to/caching.md), [admin-api](../../reference/admin-api.md)). | `DELETE /api/cache/clear/{cache_id}` and `DELETE /api/cache/clear-by-key/{key}`; `cache_debug` in `extra_fields` exposes `cache_hit`, `cache_id`, `hit_type` and `similarity` ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)). |
| Storage | In-process per replica; no Redis-backed or shared response cache (design RFC only) ([caching](../../how-to/caching.md)). | An external vector store is required for both modes: Redis/Valkey, Weaviate, Qdrant or Pinecone; Qdrant, Pinecone and Weaviate are documented as unsuitable for direct-only mode ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)). |
| Streaming and billing | Streaming is served from and written to the cache; responses with `finish_reason: length` or a post-call guardrail block are never written; concurrent buffered misses are coalesced (singleflight), streaming misses are not; a hit is never billed and records `kelvran.cache.savings_usd` ([caching](../../how-to/caching.md), [metrics-and-logs](../../reference/metrics-and-logs.md)). | Streamed responses are cached and replayed chunk-by-chunk across chat, Responses, embeddings, transcriptions, speech and image generation; direct hits cost zero and semantic matches are charged the embedding call only ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching), [model-catalog](https://docs.getbifrost.ai/architecture/framework/model-catalog.md)). |

| Aspect | Kelvran | Bifrost |
|---|---|---|
| Key format and auth | Operator-generated bearer secret; `config.yaml` stores only `key_hash` (hex SHA-256) and the presented secret is hashed and compared; `Authorization: Bearer <secret>` is the only accepted header; no server-side secret generation ([virtual-keys-and-budgets](../../how-to/virtual-keys-and-budgets.md), [admin-api](../../reference/admin-api.md)). | `sk-bf-*` token via `x-bf-vk`, or `Authorization: Bearer`, `x-api-key`, `x-goog-api-key` or `api-key` for SDK compatibility; legacy keys without the prefix work only in `x-bf-vk`; the value is auto-generated if omitted from `config.json`; hashing at rest not established from primary sources on 2026-10-09 ([virtual-keys](https://docs.getbifrost.ai/features/governance/virtual-keys), [config-json governance](https://docs.getbifrost.ai/deployment-guides/config-json/governance.md)). |

## Failover and routing

| Aspect | Kelvran | Bifrost |
|---|---|---|
| Load balancing | Deployments sharing one `model` form a pool; smooth weighted round-robin over members sorted by name; `weight` (0 resolves to 1, negative is a load error), opt-in `cost_tier`, `sticky: true` canary side (virtual key hash-bucketed, never moved back); weight is the only field changeable live (`POST /admin/deployments/{name}/weight`, in-memory, reverts on restart) ([routing-and-failover](../../how-to/routing-and-failover.md), [admin-api](../../reference/admin-api.md)). | Several provider API keys balanced by weighted random selection, with per-key model filters (deny-by-default since v1.5.0) and per-request pinning via `x-bf-api-key-id`; per-virtual-key provider weights normalized to 1.0; cross-provider routing is never implicit; when no fallbacks are given the other weighted providers are appended as fallbacks sorted by weight ([keys-management](https://docs.getbifrost.ai/features/keys-management), [governance/routing](https://docs.getbifrost.ai/features/governance/routing)). |
| Rules engine | Selection inputs are weight, `cost_tier` and `sticky`; cross-model movement happens only through `fallback_chains` targets; no live add or remove of deployments, no cross-model model groups ([routing-and-failover](../../how-to/routing-and-failover.md)). | Routing Rules are CEL expressions evaluated before governance selection, with weighted targets summing to 1, an ordered fallback chain, scopes (global, customer, team, virtual_key) and variables including `budget_used` and `complexity_tier`; an embedding-based Complexity Router; session affinity keyed by `x-bf-session-id` with a default 1 h TTL; all listed in the OSS feature index ([routing-rules](https://docs.getbifrost.ai/providers/routing-rules.md), [complexity-router](https://docs.getbifrost.ai/features/governance/complexity-router.md), [session-affinity](https://docs.getbifrost.ai/providers/session-affinity.md), [oss.md](https://docs.getbifrost.ai/_llms/oss.md)). |
| Health checks | Synthetic probes only, off unless `health_probe.interval_seconds > 0`: one probe per deployment per tick with a 5 s timeout: a 1-token chat completion, or on `main` a one-string embedding for `kind: embedding` deployments; defaults unhealthy 3, healthy 2, 4 ramp steps from 20%; probe gap doubles up to 8x while unhealthy; a real upstream 503 de-weights to the 10% floor; if every member is unhealthy selection fails open; no traffic-derived circuit breaker; in `gateway/v0.17.0` embedding deployments are mis-probed and `/readyz` returns 503 (fixed on `main`) ([routing-and-failover](../../how-to/routing-and-failover.md), [config](../../reference/config.md), [README](../../../README.md)). | OSS key health is per-request: 429 keys rotate within the request, 401/402/403 keys are dead for that request only, nothing persists across requests; all keys dead returns 502 `upstream_credentials_exhausted`. | Fallback | Default: one same-pool re-pick excluding the failed deployment. `fallback_chains` per error class (`content_policy`, `context_window_exceeded`, `generic`), classified by a keyword heuristic over the upstream body; a hop is skipped if the target is unhealthy, rate-limited for the key, at capacity, unable to honor `response_format` or outside `allowed_regions`/`allowed_models`; jittered pause 25 ms base, 400 ms cap; three consecutive real failures stop the walk; streaming falls back only before the first chunk; embeddings have no fallback ([routing-and-failover](../../how-to/routing-and-failover.md), [config](../../reference/config.md)). | A per-request `fallbacks` array of `provider/model` strings tried in order after the primary exhausts its retries; triggered by network errors, 5xx, 429 and 401/402/403, not by 400/404/422, plugin blocks or cancellation; each fallback is a new request (cache, governance, logging and plugins rerun) and a governance `budget_exceeded` on the primary cascades into the chain ([fallbacks](https://docs.getbifrost.ai/features/fallbacks)). |
| Retries and timeouts | No automatic same-deployment retry; non-streaming upstream call bounded to 60 s, streaming to a 60 s idle gap, both compiled-in constants; `ReadHeaderTimeout` 10 s; client `Retry-After` on 429 (rate and concurrency), 502 and 503 is a per-key equal-jitter exponential backoff (500 ms base, 30 s cap) floored by the upstream's own `Retry-After` capped at 60 s; never on budget 429 or `/v1/embeddings` ([data-plane-api](../../reference/data-plane-api.md)). | Per-provider `network_config`: `max_retries` default 0, `retry_backoff_initial` 500 ms, `retry_backoff_max` 5000 ms, exponential with 0.8-1.2 jitter; each fallback gets its own full retry budget ([fallbacks](https://docs.getbifrost.ai/features/fallbacks)). |
| Capacity ceilings | Per-deployment `rate_limit`: RPM, TPM (enforced since `gateway/v0.17.0`, parsed but silently ignored before), provider-weighted `tpm_accounting`, `max_concurrent_requests`; aggregated across all keys and fallback hops; in-memory per replica even with Redis; rejection is 503 `deployment_capacity_exceeded` with `Retry-After` ([config](../../reference/config.md), [routing-and-failover](../../how-to/routing-and-failover.md)). | `client.drop_excess_requests` (default false) returns 429 when the provider queue is full instead of waiting; per-provider-key TPM/RPM tracking in OSS not established from primary sources on 2026-10-09 ([client.md](https://docs.getbifrost.ai/deployment-guides/config-json/client.md)). |

## FAQ

**Can I point the Anthropic SDK or Claude Code at either gateway?** At Bifrost, yes: `/anthropic/v1/messages` and `count_tokens` are mounted, the Anthropic SDK targets `http://<host>:8080/anthropic` and Claude Code is configured with `ANTHROPIC_BASE_URL=http://<host>:8080/anthropic` and `ANTHROPIC_AUTH_TOKEN=<virtual key>` ([anthropic-sdk](https://docs.getbifrost.ai/integrations/anthropic-sdk/overview), [claude-code](https://docs.getbifrost.ai/cli-agents/claude-code)). At Kelvran, no: there is no `/v1/messages` route and `x-api-key` is not read ([compatibility](../../reference/compatibility.md)).

**What does each need besides the binary?** Kelvran for one replica: a `config.yaml` and provider credentials in environment variables or files; no database and no Redis, because caches are in-process and Redis is optional, serving multi-replica budgets, identity, rate limits and config propagation ([config](../../reference/config.md), [virtual-keys-and-budgets](../../how-to/virtual-keys-and-budgets.md)). Bifrost: `config.db` and `logs.db` (SQLite) or PostgreSQL, network access to `getbifrost.ai` for the pricing datasheet at startup (or a `file://` mirror), and an external vector store if caching is enabled ([setting-up](https://docs.getbifrost.ai/quickstart/gateway/setting-up), [airgapped](https://docs.getbifrost.ai/deployment-guides/how-to/airgapped.md), [semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)).

**Which one has teams?** Bifrost: Customer > Team > Virtual Key with cumulative budget checks ([budget-and-limits](https://docs.getbifrost.ai/features/governance/budget-and-limits)). Kelvran: flat per-key budgets; one key per team, agent or run ([virtual-keys-and-budgets](../../how-to/virtual-keys-and-budgets.md)).

**What can I cryptographically verify today?** Kelvran: the `:v0.17.0` container image's cosign signature, CycloneDX SBOM attestation and SLSA provenance; no release binary yet, because no GitHub Release has assets until the first tag pushed after 2026-10-08 ([release-artifacts](../../reference/release-artifacts.md)). Bifrost: npm provenance on `@maximhq/bifrost`; the binaries on R2 and the container images have no signing or attestation step in the release workflow and the GitHub attestations page lists none ([npx-publish.yml](https://raw.githubusercontent.com/maximhq/bifrost/dev/.github/workflows/npx-publish.yml), [release-pipeline.yml](https://raw.githubusercontent.com/maximhq/bifrost/dev/.github/workflows/release-pipeline.yml), [attestations](https://github.com/maximhq/bifrost/attestations)).

**Are the two "semantic" caches comparable?** No. Kelvran's L3 is lexical MinHash with equality gates and no embedding, always on, in-process, never erased ([cache-gate](../cache-gate.md)). Bifrost's semantic mode is embedding cosine similarity at a configurable threshold, opt-in per request, held in an external vector store, with API invalidation ([semantic-caching](https://docs.getbifrost.ai/features/semantic-caching)).

**Is there a hosted version of either?** No. Neither project describes a hosted or managed service; Bifrost Enterprise is a commercial in-VPC build and Kelvran has no commercial tier ([enterprise page](https://www.getmaxim.ai/bifrost/enterprise), [README](../../../README.md)).
