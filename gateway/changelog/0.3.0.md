## Added

- Added an Admin API viewer-role credential tier: `admin.Handler` now takes a `Credentials{Admin, Viewer}` struct instead of a single bearer token. An optional, separately-configured viewer credential (`admin.viewer_token_env`) can authenticate `GET /admin/config` but is structurally rejected by `POST`/`DELETE /admin/virtual_keys/{name}` (per-route middleware wrapping, not an in-handler role check) — omitting it reproduces the pre-existing single-credential behavior exactly. Every successful virtual-key create/delete now writes a structured audit-log entry (key name and `authorized_by` only, never the credential or key hash) — previously zero logging existed anywhere in the package. Also added the first-ever test coverage for the pre-existing admin-token startup guard.

## Security

- Fixed a real Guardrails post-call scanning gap: `serializeResponse` (shared by the buffered post-call check and the streaming audit-only check) only ever read `Message.Content`, never `Message.ToolCalls[].ArgumentsJSON` — unlike the pre-call check, whose full JSON marshal already covered tool calls. A model emitting PII/secrets/exfiltrated content inside a tool call's arguments (typically with `Content` empty) previously bypassed post-call Guardrails entirely. Fixed by extending `serializeResponse` to also scan each choice's tool-call arguments — no signature change, no new detectors, closes on both the buffered and streaming-audit-only paths in one change.
- Added a `SharedAcrossTenants` deployment flag closing a newly-discovered cross-tenant provider-side cache-leakage risk: a `Deployment` has exactly one upstream credential (never per tenant), and since provider-side prompt-caching went default-ON, two virtual keys sharing one deployment's credential (a normal, already-documented config shape) share provider cache-hit timing too — structurally identical to a 2026 finding measured live against a comparable multi-tenant LLM gateway. `SharedAcrossTenants: true` forces `cache_control`/`cachePoint` markers off for that deployment via a new centralized `effectiveCacheControlAutoDisabled()` method, composing with the existing `DisableCacheControlAutoPopulate` flag rather than replacing it.
