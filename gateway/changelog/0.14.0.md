# gateway v0.14.0 — 2026-09-21

Entries below are frozen as of this release — see `unreleased.md` for anything added since. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories; [SemVer](https://semver.org/) — load-bearing for the Go module path/tag.

## Added

- Redis-backed budget enforcement (`budget.redis_addr`) and identity/virtual-key persistence (`admin.redis_addr`), plus live cross-instance propagation of virtual-key upsert/delete/rotate over the existing config-propagation Redis pub/sub channel — the real unblock for running more than one gateway replica: `deploy/k8s/base/deployment.yaml` now ships `replicas: 2` with a rolling-update strategy instead of `replicas: 1`.
- Redis-backed TPM (tokens-per-minute) rate limiting via GCRA, alongside the existing RPM token bucket, so per-key token throughput is now enforced correctly across replicas too.
- Optional Redis AUTH/TLS (`redis_password_env`/`redis_username`/`redis_tls`) for every Redis-backed subsystem — budget, rate limiting, identity, and config propagation.
- An embedding-similarity prompt-injection detector (`guardrails.embed_sim`), complementing the existing regex-based detector.
- A fourth admin credential tier, `Operator` (`admin.operator_token_env`) — authenticates only the reversible, single-named-resource write routes (virtual-key rotate, deployment reweight, cache erase); every other admin write route stays Admin-only.
- `GET /admin/virtual_keys` lists every configured virtual key (never exposes `key_hash`).
- `dimensions` on the canonical embeddings request, threaded through both the OpenAI and Bedrock Titan embedding adapters.
- `finish_reason` on `GatewayDecisionEvent` (additive, non-breaking `api/` change).
- A real `PodDisruptionBudget` (`minAvailable: 1`) and preferred pod anti-affinity for the gateway Deployment, plus a real `Namespace` resource `deploy/k8s/base/` was previously missing entirely.

## Changed

- The pre-call guardrail scan (`guardrailScanMessages`) now extracts plain message text instead of JSON-marshaling the whole message slice, mirroring the post-call scan's existing extraction shape — JSON structural noise was measurably degrading both the embedding-similarity and the always-on regex-based prompt-injection detector.
- `RotateVirtualKey` now reads back and republishes its own currently-registered rate-limit config to other replicas, instead of publishing `nil`.
- `terminationGracePeriodSeconds` raised to 60s with a `preStop` hook, so the K8s manifest's own grace period comfortably covers the gateway's documented graceful-shutdown budget.

## Fixed

- A prompt label could resolve against an inconsistent snapshot under concurrent label/version mutation (a TOCTOU race in `ResolveLabel`), and sticky canary routing's within-side pick could lose its stickiness guarantee under real concurrent traffic (a shared-WRR-cursor race) — both closed with real concurrency regression tests.
- `HandleEmbeddings` had no completion logging or spend metric at all, unlike every other request path.
- Cache-entry erasure (`POST /admin/cache/erase`) silently reported success for a virtual-key ID that matched no real configured key, rather than 404ing like every other virtual-key-scoped admin route.
- The embeddings endpoint rejected a bare-string `input` (only accepting an array), despite already documenting OpenAI's real `string | string[]` contract; and nothing validated that two deployments sharing one canonical embedding model name actually produced comparably-shaped output.
- Two OTel GenAI semantic-convention drifts: an already-renamed-upstream attribute name (`cache_creation` → `cache_write`), and a `gen_ai.request.stream` attribute that was declared but never actually set on any span.
- The hidden-Unicode guardrail scan was missing two real, OWASP-cited smuggling ranges (U+2060 WORD JOINER, the U+FE00–FE0F variation-selector block).
- A same-model fallback attempt could leak a concurrency-limiter slot when a later capability/region check rejected the same candidate.
- The admin and client-facing HTTP servers shut down sequentially rather than concurrently on SIGTERM, and a shutdown-timeout error didn't name which server actually failed to drain.
- An admin config update landing mid-flight during an outstanding TPM rate-limit reservation could corrupt that key's accounting two different ways; both closed via a per-bucket epoch.
- Sticky canary routing's health-recovery ramp could be double-charged by an unrelated cost-tier filter re-offering an already-admission-checked candidate.
- Anthropic's streaming decoder had no guard against a duplicate/replayed `message_start`/`message_delta` event corrupting captured token usage; a duplicate chunk index arriving after a choice's finish reason was set was silently folded in rather than flagged as an anomaly.
- A corrupted-or-unreadable persist store in `on_corrupt_store: reset` mode was always treated as genuine bbolt corruption, even for a plain permissions/disk-full error — now classified against bbolt's own documented corruption sentinels.
- The webhook alerting sender retried a permanent 4xx response identically to a transient failure.
- The YAML config parser silently accepted a tab-indented line and a duplicate key at any nesting level with no error, and its colon search wasn't quote-aware (`"my:deployment":` split inside the quotes); a non-canonical boolean spelling silently collided with "field absent" instead of erroring.
- `LexicalCache.Search` panicked on a negative `k`; `MinHashSignature`'s permutation coefficient wasn't forced odd, a latent break of MinHash's own Jaccard-approximation guarantee.
- A live deployment-weight mutation from one gateway instance could be applied out of order on another sharing the same Redis, if two mutations for the same deployment raced; closed with a wall-clock ordering token.
- Bedrock's structured-output request silently dropped `response_format` for a non-whitelisted model instead of erroring; a URL-based image/document content part returned a generic, unwrapped error instead of a distinguishable sentinel.
- A Redis-mode virtual-key rotation published `rateLimit=nil`, silently deny-alling every request from that key on a replica that never independently learned about it.
- Two Redis Lua correctness bugs in the budget/rate-limit backends: a scientific-notation-formatting bug that silently disabled budget enforcement for any cap ≥ $100,000, and a missing per-window epoch that let a stale reservation corrupt an unrelated later window's ledger.
- Two Redis key-namespace collisions (budget's spend/alert-bucket keys, rate limiting's RPM/TPM composition) from unescaped virtual-key-ID concatenation.
- `deploy/k8s/base/` had no real `Namespace` object (`kustomization.yaml`'s own `namespace:` field only stamps the name onto other resources, never creates it) — `kubectl apply -k base/` failed outright against a genuinely fresh cluster.
- `deploy/k8s/README.md`'s Usage steps never showed the command to turn a local `.env` into the real `gateway-upstream-credentials` Secret before applying — and re-applying `kubectl apply -k base/` after that Secret exists silently wipes it back to the placeholder's empty `stringData`, documented as a standing operational gotcha rather than solved.

## Security

- Closed a full, unauthenticated admin-API bypass: the config-propagation Redis pub/sub channel had no authentication at all, so any process with Redis network access could forge a virtual-key mutation and have every subscribed replica apply it. Every mutation event is now HMAC-signed; an unsigned or misconfigured channel refuses to start rather than running open.
- A post-call-guardrail-blocked chat completion was never billed, letting a tenant drive unbounded real upstream spend with `BudgetUSD` never engaging (the completion was already paid for upstream before the block decision).
- L1/L2 response cache eviction had no per-tenant boundary, letting one tenant's traffic evict every other tenant's warm cache entries; deleting and recreating a virtual key under the same ID could silently inherit the deleted key's old spend history.
- Three real evasion gaps in the always-on regex guardrail detectors: verb-conjugation and whitespace/punctuation-variant bypasses of the prompt-injection phrase matcher, and a missing hidden-Unicode strip before matching (prompt-injection phrases and email-address PII could both be split with a zero-width character to evade detection).
- No Redis-backed subsystem (budget, rate limiting, identity, config propagation) supported AUTH or TLS at all — Redis network access alone was sufficient to read or corrupt state, with no way to mitigate it even at the network layer.
