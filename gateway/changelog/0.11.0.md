# gateway v0.11.0 — 2026-09-16

Entries below are frozen as of this release — see `unreleased.md` for anything added since. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories; [SemVer](https://semver.org/) — load-bearing for the Go module path/tag.

## Added

- Client-facing `Idempotency-Key` request deduplication (`internal/idempotency`): block-and-replay for a concurrent in-flight request, verbatim replay for a completed one, rejection on a body-fingerprint mismatch — no second real upstream call. Claimed right after auth, before rate-limit/budget checks.
- Live deployment-weight mutation via a new admin-only `POST /admin/deployments/{name}/weight` — in-memory only, `config.yaml` stays the source of truth on restart.
- A `-validate` flag: load and validate `config.yaml`, exit 0/1, with no listener/store/telemetry started.
- `kelvran.persistence.failed` OTel counter (`store_kind` attribute), paired at every existing budget/identity persist-failure log site.
- Live bbolt backup for the identity/budget/prompt durable stores via a new admin-only `POST /admin/backup`, gated on a new `admin.backup_dir` config field.
- Budget-data erasure folded into the existing `DELETE /admin/virtual_keys/{name}` route as a side effect — a deleted key's spend history no longer survives indefinitely under its old ID.
- Outbound `Idempotency-Key` header on Kelvran's own calls to OpenAI upstream deployments (hex-sha256 of the request body).
- A startup log line (`startup_virtual_key_overridden_by_persisted_store`) when a persisted virtual key silently overrides a config-declared one with the same ID.
- `identity.VirtualKey.AllowedRegions`, enforced at both the first deployment pick and every same-model fallback hop — a same-model fallback can no longer silently cross a region boundary.
- MWMB (multiwindow multi-burn-rate) SLO alert rules for Prometheus — page/warn severities, overall and per-provider.
- A standalone Alertmanager Compose service, wired to the SLO alert rules above (`grafana/otel-lgtm` bundles Prometheus/Tempo/Grafana but no Alertmanager).
- Two Terraform root modules: `terraform/bedrock-judge-panel` (scoped IAM role/policy for evals' Bedrock judge panel) and `terraform/vector-s3-shipper` (S3 bucket + write-only IAM user for the `vector-s3` log-shipping Compose profile).
- A narrow `CostViewer` admin credential tier, authenticating only a new `GET /admin/virtual_keys/{name}/spend` route.
- Grace-period virtual-key rotation via a new admin-only `POST /admin/virtual_keys/{name}/rotate` — an in-flight caller using the old secret keeps working until the grace period elapses.
- Admin-created/rotated virtual keys and admin-managed prompt templates now persist via bbolt and survive a restart (previously reverted to `config.yaml`'s own declared state).
- A fixed budget-alert threshold ladder (50/75/90/100% of cap) alongside the existing warn log, plus a `kelvran.budget.threshold_crossed` OTel counter.
- `X-Kelvran-Overhead-Duration-Ms` response header (buffered path) isolating Kelvran's own added latency from total end-to-end latency.
- A per-agent-run `kelvran.savings.usd` span attribute (set only on a real cache hit), plus an example Grafana panel.
- Real Kubernetes Kustomize manifests (`deploy/k8s/base/`) and cgroup-aware `GOMEMLIMIT`.
- Pre-flight rejection of Bedrock-unsupported structured-output schema features (recursive schemas, external `$ref`, numeric/string-length constraints) before sending, instead of an opaque upstream 400.
- Cross-provider `tool_choice` normalization (`auto`/`required`/`none`/`tool`) across all five adapters.
- A standalone CUSUM spend-velocity anomaly detector (`internal/telemetry/spendvelocity`) — not yet wired into the live request pipeline.
- An opt-in `pprof` endpoint under the existing admin server (`admin.enable_pprof`, default false), gated behind the admin credential.
- `cache.Cache.Delete`, closing part of a GDPR/CCPA erasure gap (finding every cached entry for a given data subject is still not built).
- A real OTLP observability backend for the pilot (OTel Collector/Prometheus/Tempo/Grafana via Compose, profile-gated), with a provisioned dashboard (cache hit rate by layer, budget burn, guardrail verdict rate).
- `evals`: judge/panel scores are now stamped with a judge-prompt version tag, so a prompt change no longer silently invalidates comparability of historical scores.

## Fixed

- A restart silently reset every virtual key's rolling-window budget-reset clock to the restart moment; rolling-window bookkeeping (period start, epoch, billed count) is now persisted, with an automatic, non-breaking migration from the legacy bare-decimal-string format.
- A request still in flight when graceful shutdown's own bounded wait expired never ran its deferred billing/telemetry/audit logic at all (`os.Exit` never runs deferred functions) — in-flight requests are now drained with a bounded grace period first.
- A mid-stream safety guard (runaway-completion ceiling or reservation-topup exhaustion) that ended a stream before the provider's own usage frame arrived billed an explicit $0 for real, already-delivered content instead of an estimated real cost.
- A client disconnect mid-stream discarded billing for content already delivered to the client, instead of billing the real, partial content.
- A same-model WRR fallback could re-select the exact deployment that had just failed for a different, concurrent request, due to a shared WRR cursor with no exclusion of the failed name — confirmed via a real concurrent-burst production dry run producing raw 502s with no fallback attempted.
- 3 related correctness bugs in the idempotency-key store, all one root cause (no ownership check on `Complete`/`Fail`): an abandoned claim could orphan a concurrent waiter indefinitely; a second `Complete` call on the same claim could panic; a stale caller could resolve a completely different, newer claim for the same key.
- `Verifier.Keys()` double-counted a virtual key mid-rotation (two hash-table entries pointing at the same key), which the very next admin write then rejected as a duplicate ID.
- `CacheControl.TTL` was silently dropped on every Bedrock call — every cache point used the hardcoded 5-minute default regardless of what the caller actually requested.
- The first deployment pick (not just fallback hops) now also reroutes to a capability-compatible deployment when one exists in the same pool, instead of silently sending an unsupported request format.
- Neither upstream HTTP client customized its transport, so every provider host ran on the stdlib default of 2 idle connections — raised the per-host idle-connection cap to reduce real connection churn under a concurrent burst.

## Security

- Added CodeQL SAST scanning (Go + Python) and a real OpenSSF Scorecard workflow.
- Enabled `gosec`+`bodyclose` (gateway) and ruff's native bandit ruleset (evals); fixed 2 real Slowloris gaps (missing `ReadHeaderTimeout` on both HTTP servers).
- The container image now runs as a real non-root user (UID 65532) instead of root.
- Added `.github/dependabot.yml` (gomod/pip/github-actions ecosystems).
- Added `make config-safe`, redacting secret-shaped env vars (and embedded `user:pass@host` connection strings) out of `docker compose config` output — closes the exact incident class that leaked a real AWS access key into a transcript twice.
- Added missing, explicit `permissions:` blocks to 2 CI jobs and 1 scheduled workflow that had none at all, inheriting the repo default instead of declaring the minimal `contents: read` they actually need.
- Enabled required status checks (the 3 core CI jobs) on `main` branch protection, previously completely unset.
