## Fixed

- Concurrent admin operations on the same virtual key (e.g. rotate + delete) could leave the on-disk bbolt store inconsistent with the final in-memory state — a divergence invisible until a restart resurrected the stale persisted record. Each virtual key's mutate-then-persist sequence is now serialized against the other admin operations on that key.
- Fixed several cross-provider response-translation bugs: Anthropic responses now hardcode the assistant role instead of trusting a field that could arrive empty; OpenAI/openaicompat now reject an empty `choices` array instead of silently returning a zero-value response; a `nil` tool-call arguments map (Anthropic, Bedrock, Gemini) now marshals to a valid empty object `{}` instead of the invalid JSON literal `null`.
- A panicking guardrail detector previously aborted its own request as a bare, ungraceful 500; panics are now recovered and handled through the same fail-open-with-logging path used for an ordinary detector error.
- The virtual-key and prompt admin upsert routes accepted `budget_usd`, `budget_reset_interval_seconds`, and `budget_warn_percent` with no validation (a negative reset interval could force a permanent budget reset on every check), and no length bound on virtual-key names or prompt ids. All four are now validated on upsert.
- A rate-limit pair with both burst/refill values negative was silently accepted as valid — previously checked at the deployment level only, not at all at the virtual-key level. An out-of-range numeric config value could also silently parse into a large nonzero integer instead of failing, because 16 call sites discarded the parser's own error flag.
- A Bedrock stream cut off mid-frame was indistinguishable from a clean end-of-stream and billed the partial, already-delivered content as if the response were complete; it is now detected as a real truncation via the absence of the stream's own terminal `messageStop` event.
- Closed two defensive gaps not reachable via any caller today but left as landmines for a future one: the router's `newModelState` no longer panics on an empty deployment slice, and idempotency `Claim` now rejects a non-positive TTL instead of silently defeating deduplication.

## Security

- A crafted client `model` value containing a JSON-escaped NUL byte could make two genuinely different `(model, messages)` request pairs collide onto byte-identical cache and idempotency keys — the exact cross-tenant `KeyPooling` collision class `THREAT_MODEL.md` warns about. `cache.Key`/`NormalizedKey` and the idempotency store key now length-prefix every hashed field to close it, invalidating all existing cache entries once as a side effect.
- Capped a single Bedrock stream's total decoded bytes, closing an unbounded-memory path where a pathological upstream frame could otherwise be buffered fully into memory with no ceiling.
- Added per-request caps on chat message count (2,000), tool-definition count (256, plus parameter-schema complexity limits), and a single message's `Content`/`ContentPart.Data` field size (8MiB) — previously bounded only by the 32MiB whole-body limit, and reachable before authentication, budget, or rate-limit checks ever run.
- Bounded the unauthenticated, client-controlled `model` field everywhere it reaches telemetry: its length is now capped in OTel span names and log lines, and the GenAI metrics attribute is pinned to a fixed sentinel whenever no real deployment was resolved for the request — closing both a log/span size blowup and a Prometheus/OTel metric-cardinality-exhaustion denial of service.
