# gateway v0.13.0 — 2026-09-19

Entries below are frozen as of this release — see `unreleased.md` for anything added since. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories; [SemVer](https://semver.org/) — load-bearing for the Go module path/tag.

## Added

- A new `POST /v1/embeddings` endpoint for OpenAI and Bedrock Titan, via a new `EmbeddingAdapter` interface kept separate from the existing chat `Adapter` interface so Anthropic (no native embeddings model) never needs a dummy implementation. Reuses the existing budget/rate-limit/guardrail enforcement pipeline.
- Sticky hash-bucketing canary routing (`Sticky: true` on a deployment): the same caller-supplied key deterministically prefers the same side of a canary split on every request, and ramping the canary's own weight up only ever adds newly-bucketed keys, never bounces an already-canary key back to stable.
- Mutable prompt-version labels: `PUT`/`DELETE /admin/prompts/{id}/labels/{label}` let an operator point a label (e.g. `production`) at a specific version and move it back — rollback is just re-pointing to an older version, no new upload needed.
- Push-based cross-instance config propagation over Redis pub/sub: a live deployment-weight mutation via the admin API now propagates to every other gateway instance sharing the same Redis address, not just the instance that received the admin call.
- `identity.VirtualKey.BillingSubjectID` (config key `billing_subject_id`): an opaque, operator-supplied external billing identifier, threaded through to `GatewayDecisionEvent.billing_subject_id` for a future billing-platform export consumer. Purely metadata — never read by any budget/rate-limit enforcement path.
- A new `POST /admin/cache/erase` endpoint gives an operator a real way to erase a cached entry across the L1/L2 cache layers (a data-subject erasure request, per `SECURITY.md`'s Data Retention section) — disclosed limitation: does not prevent an identical follow-up request from still hitting the L3 semantic cache.
- `admin.on_corrupt_store: fail|reset` config knob controlling whether a corrupted bbolt store is renamed aside and recreated empty, or the process refuses to start — previously always reset with no way to opt out.
- Direct-from-Go webhook push for budget-threshold alerts (`internal/alerting`), a from-scratch Standard Webhooks implementation (HMAC-SHA256, `whsec_`-prefixed secret) — fire-and-forget, never blocks the request that triggered the alert.
- `admin.enable_audit_log` config toggle (default `true`, preserving today's always-on behavior) for the existing admin audit-log trail.

## Fixed

- The YAML config parser silently accepted tab-indented lines (miscounted as zero-width indentation, producing wrong, undetectable structure) and silently let a duplicate key at any nesting level win by last-value-wins with no error at all. Both now reject loudly with a line-numbered error. Also added an explicit 64-level max-nesting-depth guard (defense-in-depth; the parser was never actually at stack-overflow risk).
- A same-model fallback attempt could acquire a candidate deployment's concurrency-limiter slot and then leak it — never releasing — when a subsequent capability or region check rejected that same candidate, a slow, silent capacity leak under sustained traffic with fallback chains configured.
- The admin and client-facing HTTP servers shut down sequentially on SIGTERM, so a slow admin-server drain could delay the client server's own shutdown (or vice versa) for no reason; they now shut down concurrently against one shared deadline. A shutdown-timeout error now also names which server(s) actually failed to drain, rather than two indistinguishable "context deadline exceeded" lines.
- An admin config update (`Register`) landing while a request's TPM (tokens-per-minute) rate-limit reservation was still outstanding could corrupt that key's rate-limit accounting two ways: crediting the reservation back to a brand-new bucket object while the real, already-debited one was silently discarded and never reconciled; and, once that was fixed, still re-crediting a now-stale reservation amount onto the freshly-reset bucket, silently granting free extra capacity that a later refill's own capacity clamp then ate — un-billing the real token usage underneath it. Both are now closed via a per-bucket epoch that detects a reset happening mid-reservation.
- Sticky canary routing's own health-recovery ramp could be double-charged: a ramping candidate selected via the sticky path, then rejected by an unrelated cost-tier filter, could be re-offered and re-admission-checked a second time by the normal health-aware fallback scan — letting a just-recovered canary ramp to full traffic faster than its configured recovery-ramp schedule intended.
- Anthropic's streaming decoder had no guard against a duplicate or replayed `message_start`/`message_delta` event corrupting already-captured token usage — mirrors the equivalent guard Bedrock's own decoder already had for the identical hazard.
- A duplicate chunk index arriving in a stream after that choice's own finish reason was already set was silently folded into the existing content instead of being detected and logged as a stream anomaly.
- A corrupted or unreadable persist store was previously always treated as genuine bbolt corruption in `on_corrupt_store: reset` mode; a permissions misconfiguration or a disk-full error during an earlier write would have been silently renamed aside and recreated empty — real, avoidable data loss unrelated to actual corruption. Now classified against bbolt's own three documented corruption sentinels specifically.
- The webhook alerting sender retried a permanent 4xx response identically to a transient failure, burning its full retry/backoff schedule pointlessly on a request that could never succeed.

## Security

- Patched a HIGH-severity `google.golang.org/grpc` index-out-of-bounds panic (CVE-2026-84445, flagged by a real Trivy scan against the published image) — pulled in indirectly via `aws-sdk-go-v2`'s own STS/Bedrock clients. Also bumped `aws-sdk-go-v2` and `golang.org/x/text` to their latest available versions.
- Added a top-level default-deny `permissions: {}` block to every CI workflow file, and pinned the Dockerfile's `golang` base image to a fully-qualified digest — closing two real OpenSSF Scorecard findings (`TokenPermissionsID`, `PinnedDependenciesID`) confirmed via the live code-scanning API before acting.
