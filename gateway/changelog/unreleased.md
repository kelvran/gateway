## Added
- An OpenAPI 3.1 document for both listeners, `gateway/openapi/kelvran-gateway.openapi.yaml` (plan item 14, owner gate G5): the eight data-plane routes and the 31 admin patterns over 26 paths (18 always registered, `GET /admin/audit` with `admin.audit_log_path`, the twelve pprof patterns with `admin.enable_pprof`, each marked `x-kelvran-conditional`), the OpenAI, Anthropic and plain-text error bodies with the `type` and `code` vocabularies, the virtual-key and the four admin credential tiers as security schemes, `Retry-After` and `X-Kelvran-Overhead-Duration-Ms`, and examples that name their source in `x-kelvran-example-source` (a committed fixture compared byte for byte, a `[]` suffix marking a golden object wrapped into a list response's one-element array; or `hand-authored` for the six the fixtures cannot supply). The 26 admin path items carry every status their handlers answer (plain text, per the admin reference's Errors column; net/http/pprof's own statuses under the pinned toolchain on the twelve profile routes), their query parameters, the 256-byte bound on the write-route identifiers, a summary each, and request and response examples from the admin wire golden. The request headers the data-plane handlers read (`Idempotency-Key`, `X-Kelvran-End-User-Id`, `anthropic-version`, `anthropic-beta`) are reusable header parameters on the routes that read them. `POST /v1/messages` and `POST /v1/messages/count_tokens` are documented as permissive by construction (RFC-1 Option C): unknown members pass through to an `anthropic` deployment. Every request-side schema is open (`additionalProperties: true`): the gateway's decoders ignore unknown members at every depth, and a test forbids a strict decoder. Seventeen contract tests in `gateway/cmd/gateway` pin the document to the code in both directions — paths and methods against the two route tables, security requirements against the credential rules, every status and `code` against the error writers, the Schema-keyword vocabulary (the OpenAPI 3.1 meta-schema leaves Schema Objects open, so `nullable`, a singular `example` or a typo passes it), every schema's properties against the Go wire types' JSON tags, the executed `405` shape of every data-plane route, the `Retry-After` rule, the open request schemas against the absence of `DisallowUnknownFields`, every admin operation's response set against a table transcribed from the handlers, the Markdown route tables of the two reference pages against the Go route tables (a check, not a generator), and the ServeMux behaviours the vocabulary cannot carry. The compatibility matrix (`gateway/compat`, its own module) adds the conformance tests: the document passes the OpenAPI 3.1 meta-schema (libopenapi-validator), every fixture the document names as an example source validates against its component (the admin wire golden among them, so every typed admin JSON body is covered without an admin listener), and the started gateway's data-plane answers — buffered, both streaming routes frame by frame, the probes, `401`s and `400`s — validate against the document, with the observed `(operationId, status)` pairs pinned to `gateway/compat/testdata/openapi_live_coverage.txt`. Public surface under `docs/VERSIONING.md` §2 from this release (the row added in the same release; [reference page](../../docs/reference/openapi.md)); hosting of a rendered page waits for owner gate G7.
- An optional Prometheus pull endpoint (plan item 13c, owner gates G24–G26; `docs/rfcs/2026-10-09-gateway-fallback-rescued-and-prometheus-pull.md`): `telemetry.prometheus.enabled: true` adds a reader on the same MeterProvider as the push exporter — or alone under `exporter: "none"` — and a third, unauthenticated listener serving `GET /metrics` (and `HEAD`; other methods `405`, other paths `404`) on `telemetry.prometheus.listen_addr`, `127.0.0.1:9464` by default, shut down with the other two inside the existing stop budget. The exposition is pinned to the `UnderscoreEscapingWithSuffixes` translation (`kelvran_llm_spend_usd_total`, `kelvran_cache_lookup_total`, `kelvran_fallback_rescued_total`, `gen_ai_client_operation_duration_seconds_{count,sum,bucket}`), carries `service_name` and `service_instance_id` on every OTel-exported series (`kelvran_*`, `gen_ai_*`, `target_info`; the Go and process collectors' own series carry neither resource label, so per-replica queries on them use the scrape job's `instance`), and omits the `otel_scope_*` labels; the constant-label set is the resource's own two keys, so an attribute added through `OTEL_RESOURCE_ATTRIBUTES` reaches the pull path only through `target_info`; the handler admits 4 scrapes in flight with a 10 s timeout. `TestPrometheusEndpointExposesEveryDashboardMetricName` reads the overview dashboard and the SLO recording rules and asserts every metric and label name they use appears in a real scrape after a rescued fallback, a cache hit and an upstream failure. A present-but-empty or non-string `listen_addr`, a non-boolean `enabled` or a non-mapping `prometheus` fails startup; a non-loopback bind logs a warning at startup, and the server carries read, write and idle timeouts. Dependencies in the binary: `go.opentelemetry.io/otel/exporters/prometheus` v0.68.0, `github.com/prometheus/client_golang` v1.24.1 and `github.com/prometheus/otlptranslator` v1.0.0, pinned (v0.69.0 would force the OTel SDK to v1.47.0), with `prometheus/common` v0.70.1 (also a direct test import, for `expfmt`), `client_model` v0.6.2, `procfs` v0.21.1, `beorn7/perks` and `munnerz/goautoneg` indirect and `klauspost/compress` 1.18.7 → 1.19.1.
- The pull endpoint's registry carries the Go runtime and process collectors (`go_*`, `process_*`) by default with no switch (G26); `metric_relabel_configs` on the scrape job is the opt-out. They exist on the pull path only: the push exporters are unchanged.
- The spend ledger leaf of plan item 13d (RFC-2 §13d, owner gates G27–G29; `docs/rfcs/2026-10-09-gateway-attribution-and-spend-ledger.md`), slice 1 of six: `internal/spendledger` keeps hourly UTC buckets per (virtual key, served model, client tool, session) of nano-USD spend and request counts, with two caps per key — 2,000 named sessions and 50,000 named cells by default, a cell being one row inside one hour bucket — whose overflow is written to the `other` session of the hour bucket while keeping model and tool (sessionless and `other` cells take no slot: they are bounded by hour buckets × the model and tool vocabularies, not by traffic), and a 168 h retention swept by whole hour buckets. Two backends behind one `Ledger` interface run one contract suite (`spendledger/ledgertest`): `Memory` and the bbolt-backed `spendledger/boltstore` (a nested bucket per hour; the per-key session sets and row counts are derived state rebuilt by every `Sweep`, which also removes undecodable rows and undated buckets so retention never stalls on corruption; read errors name hours and keys, never a row). `Record` refuses a session outside the 13a identifier grammar, the reserved name `other`, an entry without a request and a key, model or tool over 256 bytes; `DeleteSession` refuses `""` and `other`. `budget` exports `USDToNanoUSD` and `NanoUSDToUSD`. `kelvran.persistence.failed`'s description and documented `store_kind` values name `ledger` (visible as the HELP text today; the first emission is slice 3). Nothing records into the ledger and no route reads it yet: the `ledger:` config section and write hook, the `GET /admin/spend` and `POST /admin/spend/erase` routes with their OpenAPI operations, and `kelvran spend --by` follow in the next slices.
- The spend ledger's Redis backend, `internal/spendledger/redisledger` (item 13d slice 2 of six; used once slice 3 wires `budget.redis_addr` to it): one hash per hour and virtual key, `ledger:<hourUnix>:<QueryEscape(key)>`, with a field pair per cell (`<model>|<tool>|<session>` in nano-USD and `…#n` requests), the same escaping as the leaf's cell keys. Both caps are applied inside Redis by one Lua script — is the session live, is there room, does the cell exist — so every replica writing a key shares one view and no interleaving admits a slot beyond either cap (pinned by a sixteen-writer test). Retention is `Sweep` by the caller's clock like the other backends; every hash also carries a TTL of retention + 1 h from its first write as a backstop for a sweeper that never runs. The per-key `ledger:sessions:<key>` set and `ledger:cells:<key>` count are derived state rebuilt by every `Sweep` and `DeleteSession` from the hashes they have just read and removed with the key by `DeleteKey` (a key whose hashes are all gone loses its state at the next `Sweep`); `Sweep` also removes field pairs that do not decode, carry a non-integer value or lack their spend partner, on which reads fail closed without quoting them. Reads skip a foreign key under the prefix; HGETALLs and DELs go to Redis in bounded chunks. `Open` never fails on an unreachable address. The suite runs the shared contract plus reopen, two-client, concurrency, TTL, garbage and unreachable-address cases under testcontainers, as the other Redis suites do.

## Changed
- `internal/admin` registers its routes from one table (`admin.Routes`, `gateway/internal/admin/routes.go`: 31 patterns over 26 paths, each with its method, auth tier and registration condition) instead of one `mux.Handle` call per route (31 registrations over 26 call sites); `Handler` refuses to start when the table and its handler map disagree. No request or response changes — every wrapper, status and error text is the same, pinned by the unchanged admin test suite — and the table is the source the item 14 OpenAPI document (slice S3, owner gate G5) will be checked against.
- `go.yaml.in/yaml/v3` (already an indirect dependency) is a direct test dependency of the gateway module, read by the OpenAPI contract tests; no `go.sum` change.
- The data-plane route table (`gateway/cmd/gateway/mux.go`) now carries each route's accepted method, credential rule (none; `Authorization` alone; `Authorization` or its `x-api-key` alias) and the envelope of its own `405`, each pinned against the handlers (the credential rule over a live server); the patterns stay method-less on purpose, so every wrong method is still the route's own envelope rather than net/http's plain text.

## Fixed
- `docs/reference/admin-api.md` lists the twelve pprof patterns one per row in the route index and the pprof table (the route index's two rows and the pprof table's two combined rows had abbreviated them), states the `/admin/debug/pprof/` subtree and the `307` redirect of the slash-less path, gives each pprof route its own Errors cell (the index, `cmdline` and `symbol` never fail; `profile` and `trace` answer `500`; the six named profiles `400`, `408` and `500` around a delta profile), gains the request-body, JSON-response and method conventions, and lists on the nine JSON-answering routes that lacked it the encode-failure `500` they share with `GET /admin/config`. `docs/reference/data-plane-api.md`'s header table names `/v1/messages/count_tokens` among the routes that forward `anthropic-*` headers (it has since gateway/v0.19.0). `TestReferenceDocsRouteTablesMatchTheCode` now keeps both pages' route tables equal to the Go route tables.
- `400` `system_parts_unsupported`, `400` `lossy_ingress_rejected` and `400` `invalid_prompt_reference` (every cause: `prompt_id` with `messages`, `prompt_label` with `prompt_version`, an unknown prompt, a stored prompt whose content fails validation) no longer carry `Retry-After`, no longer bump the key's retry backoff, and their decision event records `OUTCOME_INVALID_REQUEST` instead of `OUTCOME_UPSTREAM_ERROR`. All are decided before any byte reaches an upstream — the rule that plan gate G16 set for `response_format_unsupported` and `idempotency_key_reused` in `gateway/v0.19.0` — but the three codes were still classified as upstream errors (the system-parts and lossy codes were added after G16; the prompt-reference code existed before it), so a client that honoured the header waited for nothing and the key's next real rejection started from a longer backoff. Found by item 14's design review against the route inventory and the review of this fix.
