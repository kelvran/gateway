## Added
- An OpenAPI 3.1 document for both listeners, `gateway/openapi/kelvran-gateway.openapi.yaml` (plan item 14, owner gate G5): the eight data-plane routes and the 31 admin patterns over 26 paths (18 always registered, `GET /admin/audit` with `admin.audit_log_path`, the twelve pprof patterns with `admin.enable_pprof`, each marked `x-kelvran-conditional`), the OpenAI, Anthropic and plain-text error bodies with the `type` and `code` vocabularies, the virtual-key and the four admin credential tiers as security schemes, `Retry-After` and `X-Kelvran-Overhead-Duration-Ms`, and examples copied from the test fixtures (each naming its source in `x-kelvran-example-source`, a `[]` suffix marking a golden object wrapped into a list response's one-element array). The 26 admin path items carry every status their handlers answer (plain text, per the admin reference's Errors column; net/http/pprof's own statuses under the pinned toolchain on the twelve profile routes), their query parameters, the 256-byte bound on the write-route identifiers, a summary each, and request and response examples from the admin wire golden. The request headers the data-plane handlers read (`Idempotency-Key`, `X-Kelvran-End-User-Id`, `anthropic-version`, `anthropic-beta`) are reusable header parameters on the routes that read them. `POST /v1/messages` and `POST /v1/messages/count_tokens` are documented as permissive by construction (RFC-1 Option C): unknown members pass through to an `anthropic` deployment. Every request-side schema is open (`additionalProperties: true`): the gateway's decoders ignore unknown members at every depth, and a test forbids a strict decoder. Seventeen contract tests in `gateway/cmd/gateway` pin the document to the code in both directions — paths and methods against the two route tables, security requirements against the credential rules, every status and `code` against the error writers, the Schema-keyword vocabulary (the OpenAPI 3.1 meta-schema leaves Schema Objects open, so `nullable`, a singular `example` or a typo passes it), every schema's properties against the Go wire types' JSON tags, the executed `405` shape of every data-plane route, the `Retry-After` rule, the open request schemas against the absence of `DisallowUnknownFields`, every admin operation's response set against a table transcribed from the handlers, the Markdown route tables of the two reference pages against the Go route tables (a check, not a generator), and the ServeMux behaviours the vocabulary cannot carry. The compatibility matrix (`gateway/compat`, its own module) adds the conformance tests: the document passes the OpenAPI 3.1 meta-schema (libopenapi-validator), every fixture the document names as an example source validates against its component (the admin wire golden among them, so every typed admin JSON body is covered without an admin listener), and the started gateway's data-plane answers — buffered, both streaming routes frame by frame, the probes, `401`s and `400`s — validate against the document, with the observed `(operationId, status)` pairs pinned to `gateway/compat/testdata/openapi_live_coverage.txt`. Public surface to be entered in `docs/VERSIONING.md` §2 for the next release; hosting of a rendered page waits for owner gate G7.

## Changed
- `internal/admin` registers its routes from one table (`admin.Routes`, `gateway/internal/admin/routes.go`: 31 patterns over 26 paths, each with its method, auth tier and registration condition) instead of one `mux.Handle` call per route (31 registrations over 26 call sites); `Handler` refuses to start when the table and its handler map disagree. No request or response changes — every wrapper, status and error text is the same, pinned by the unchanged admin test suite — and the table is the source the item 14 OpenAPI document (slice S3, owner gate G5) will be checked against.
- `go.yaml.in/yaml/v3` (already an indirect dependency) is a direct test dependency of the gateway module, read by the OpenAPI contract tests; no `go.sum` change.
- The data-plane route table (`gateway/cmd/gateway/mux.go`) now carries each route's accepted method, credential rule (none; `Authorization` alone; `Authorization` or its `x-api-key` alias) and the envelope of its own `405`, each pinned against the handlers (the credential rule over a live server); the patterns stay method-less on purpose, so every wrong method is still the route's own envelope rather than net/http's plain text.

## Fixed
- `docs/reference/admin-api.md` lists the twelve pprof patterns one per row in the route index and the pprof table (the route index's two rows and the pprof table's two combined rows had abbreviated them), states the `/admin/debug/pprof/` subtree and the `307` redirect of the slash-less path, gives each pprof route its own Errors cell (the index, `cmdline` and `symbol` never fail; `profile` and `trace` answer `500`; the six named profiles `400`, `408` and `500` around a delta profile), gains the request-body, JSON-response and method conventions, and lists on the nine JSON-answering routes that lacked it the encode-failure `500` they share with `GET /admin/config`. `docs/reference/data-plane-api.md`'s header table names `/v1/messages/count_tokens` among the routes that forward `anthropic-*` headers (it has since gateway/v0.19.0). `TestReferenceDocsRouteTablesMatchTheCode` now keeps both pages' route tables equal to the Go route tables.
- `400` `system_parts_unsupported`, `400` `lossy_ingress_rejected` and `400` `invalid_prompt_reference` (every cause: `prompt_id` with `messages`, `prompt_label` with `prompt_version`, an unknown prompt, a stored prompt whose content fails validation) no longer carry `Retry-After`, no longer bump the key's retry backoff, and their decision event records `OUTCOME_INVALID_REQUEST` instead of `OUTCOME_UPSTREAM_ERROR`. All are decided before any byte reaches an upstream — the rule that plan gate G16 set for `response_format_unsupported` and `idempotency_key_reused` in `gateway/v0.19.0` — but the three codes were still classified as upstream errors (the system-parts and lossy codes were added after G16; the prompt-reference code existed before it), so a client that honoured the header waited for nothing and the key's next real rejection started from a longer backoff. Found by item 14's design review against the route inventory and the review of this fix.
