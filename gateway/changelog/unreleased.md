# Unreleased

Entries accumulate here under the six [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories until the next `gateway` release. At release time this file's content is moved into a new dated `<version>.md` file (e.g. `0.2.0.md`) in this same folder, and this file is reset to empty category headers.

Versioning: [SemVer](https://semver.org/) — load-bearing for the Go module path/tag (`v0.1.0`, `v0.2.0`, ...).

## Added

- `GET /admin/debug/pprof/goroutineleak`: Go 1.27's goroutine-leak profile joins the admin pprof set (`admin.enable_pprof`, Admin tier, the 60 s `seconds` cap — the thirteenth pprof route, 34 admin patterns over 29 paths). Each collection forces a leak-detecting garbage-collection cycle (two with `seconds`, whatever its value) and collections serialize on a package-level mutex in `runtime/pprof`, so it costs more than the six other named profiles; the cap and the write timeout bound the connection, not the GC work (`docs/reference/admin-api.md`, THREAT_MODEL's Denial of Service row). Additive on the OpenAPI document — a new path item and operation `pprofGoroutineleak` (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule). `TestPprofGoroutineleakProfileIsServed` asks for the profile itself, because `pprof.Handler` answers 404 `Unknown profile` for a name the running toolchain lacks while every route-table test stays green — the route is real only on the `go 1.27.3` toolchain this release line builds with.
- An OpenAPI breaking gate: `scripts/openapi-breaking.sh` runs oasdiff v1.33.0 `breaking --fail-on ERR` on `gateway/openapi/kelvran-gateway.openapi.yaml` against the document shipped at the newest `gateway/v*` tag, in CI's `proto` job on every push and pull request and in `release.yml`'s `build` job at the tag (against the previous release). `gateway/openapi/oasdiff-severity.txt` raises the `docs/VERSIONING.md` § 2 surfaces oasdiff rates INFO or WARN by default (a non-success status, an operationId, an optional response header, a response enum value, an optional response property, a request parameter or a request member removed; a security requirement added), and `gateway/openapi/oasdiff-err-ignore.txt` waives a sanctioned MINOR break — it must be empty otherwise (`TestOpenAPIBreakingGateWaiverIsEmptyUnlessABreakIsInFlight` on every push, preflight check 8 at the tag) and its lines leave in the post-tag follow-up commit (RELEASE.md gateway step 7). The contract tests pin the document to the code; this pins it to the previous release, so a route removed from both no longer passes unnoticed. Not public surface (CI and release tooling). The first base is `gateway/v0.20.0`, the first release to carry the document; against an older base the gate reports nothing to compare. oasdiff has no rule for the `x-kelvran-*` members (its extension-aware rules read only `x-extensible-enum`, `x-stability-level`, `x-sunset` and `x-since-date`), so those stay pinned to the code only (`docs/reference/openapi.md`). The base is always a release tag (`gateway/vX.Y.Z`; a pre-release is never a base), the script refuses a `.oasdiff.*` config file or `$OASDIFF_CONFIG` that would reconfigure the tool behind its flags, and release.yml runs it without an argument so a rebuild of an older tag compares against that tag's own predecessor.
- `virtual_keys.<name>.rate_limit.tokens_per_day`: a tokens-per-day dimension per virtual key (round-5 Tier S item 24; OWASP LLM06:2026's tokens-per-day limit) on the existing TPM reservation path — a third bucket of that capacity refilling at `tokens_per_day/86400` tokens per second, a rolling 24-hour allowance rather than a midnight reset, checked after RPM and TPM (`ratelimit.KeyLimiter.ReserveTPD`/`IncreaseReservationTPD`/`ReconcileTPD`; in Redis mode the same GCRA scripts under their own NUL-tagged key beside the TPM one, with their own 24 h usage history — since 2026-10-17 the one admission script and the one settlement script, see Changed). A day bucket with no usage history reserves at most one hour's share of the day (`tokens_per_day/24`), or the same request's minute reservation when that is smaller, so one request never claims the whole day; a refusal returned the minute reservation at once until 2026-10-17 (since phase 2b of item 10 a refusal reserves nothing, see Changed) and is the same `429` `rate_limit_exceeded`, with `Retry-After` floored on the bucket's own wait until a typical request fits again (whole seconds, capped at 24 h; the 1-30 s per-key backoff still applies when larger, and alone for a refusal decided before the key has usage history — the first time the limiter's own wait reaches a client), and the message `dataplane: rate limit exceeded (tokens_per_day)`; like TPM it counts chat and messages turns only (embeddings and `count_tokens` draw RPM alone; cache hits release their reservation); a backend error fails open like the other dimensions, counted once per request (`ratelimit_tpd_backend_unavailable` — until 2026-10-17, and still with `op=mid_stream_topup`; since phase 2b of item 10 a pre-call error is the gate's `ratelimit_backend_unavailable`, see Changed). A single scalar, 0 or absent for none; negative or non-numeric fails startup; key-level only — under `per_model` or on a deployment it is a load error, not a silent no-op. Carried by the admin upsert body (`rate_limit.tokens_per_day`, `400` when negative), the propagation payload and `kelvran keys` offline diff; like TPM, not restored for an admin-mutated key after a restart and not echoed by `GET /admin/virtual_keys`. Additive config and admin-body surface (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule); the OpenAPI document gains the `RateLimitRequest.tokens_per_day` member and the chat and messages `429` descriptions name the dimension. `docs/reference/config.md`, `admin-api.md`, `error-codes.md`, `glossary.md`, `metrics-and-logs.md`, `docs/how-to/virtual-keys-and-budgets.md`, `docs/operations/TELEMETRY.md`, `FAILURE-MODES.md`, THREAT_MODEL's LLM06 row. Proven by `TestHandleChatCompletionRejectsOnceTheDayBucketIsExhaustedWithTheDayWait`, `TestHandleChatCompletionDayRejectionReleasesTheMinuteReservation`, `TestIntegrationMessagesTokensPerDayRejectionCarriesTheDayWait` and, against a real Redis shared by two instances, `TestIntegrationTwoGatewayInstancesShareOneRedisTokensPerDay`.
- `guardrails.role_scopes.<category>`: role-scoped guardrail detectors (round-5 Tier S item 25; LiteLLM v1.97.0's per-guardrail `scan_only_tool_results` generalised to a role set per category) — a mapping of role → `true` over `system`, `user`, `assistant` and `tool` that runs a category's detectors only on those message roles; absent, every role is scanned exactly as before. The post-call response scan is the `assistant` role and an embeddings input the `user` role; `count_tokens` scans its messages by role like the chat routes; a message whose role is none of the four is recorded as `other` and scanned by every detector; a role is the caller's own label on the wire, so omitting one is a trust decision about that key's callers; findings carry their role (`finding_roles` on the `guardrail_blocked_*` and `guardrail_verdict_*` log lines). A scope is part of the policy fingerprint folded into cache keys, so changing one forces misses without a `policy_version` bump. The loader refuses an unknown role, a non-bool value, a string or list value, and a scope that admits no role; an unknown category is logged and skipped like `category_overrides`. Additive config surface (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule).
- A tamper-evident admin audit trail (round-5 Tier S item 26): every line `admin.audit_log_path` receives now carries `seq` and `prev_hash`, the SHA-256 of the previous line's bytes, and, when the new `admin.audit_signing_secret_env` names a variable holding a key, a `mac` (`v1,` plus the hex HMAC-SHA256 of the line without it). A file written before this change keeps its lines; the first chained line hashes the last of them, so the earlier legacy lines are not verifiable. `kelvran audit verify [--file PATH] [--config PATH] [--key-env NAME] [--allow-unsigned-prefix] [--json]` walks a file and reports an edited, removed, reordered or forged line, a truncated tail, a line that is not JSON, a line whose bytes are not the gateway's own encoding of its content, and a missing or invalid `mac` (exit 1; with a key every chained line must carry a `mac` and at least one line must be signed, and `--allow-unsigned-prefix` accepts only the lines chained before the key was introduced), or the counts, the `seq` range and the chain head (exit 0). Without a key the trail is chained but unsigned: the gateway logs `admin_audit_unsigned` once at startup and `kelvran doctor` warns; a key variable that is set but empty refuses startup like every other `*_env` secret. The durable append now runs before the slog audit line, which carries the chain head as `audit_seq` and `audit_hash` when the append succeeded (a failed append writes the line without them, then `admin_audit_durable_append_failed`). A keyed gateway that resumes a file with lines but not one `mac` warns `admin_audit_resumed_unsigned_history` at every start until the first signed line is appended: expected when the key is first introduced over an existing trail, otherwise the file was rewritten while the gateway was down. `GET /admin/audit` is unchanged: the integrity fields stay in the file. The decision event (`gatewayevents_v1`) is deliberately not hashed in this change. Additive config surface (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule).
- Redis round trips are counted (round-5 Tier C item 10, the measurement before any pipelining): `kelvran.redis.round_trips` and `kelvran.redis.commands` OTel counters, the first attributed by store (`ratelimit`, `budget`, `ledger`, or `shared` when the three share one client, see Changed) and kind (`command`, `pipeline`), the second by store and command name, from a go-redis hook on the three request-path Redis stores (the identity store and the config-propagation client are not counted); every chat span carries the request's own `kelvran.redis.round_trips` and `kelvran.redis.commands` (0 in memory mode). The benchmark harness gains the `S1r` preset — S1a's twin with the gateway in Redis mode — and `kelvran-bench run -metrics-url`, which scrapes a gateway's Prometheus endpoint at the warm-up boundary and the end and reports Redis round trips and commands per request (a `Redis RTT/req` column; `redis_round_trips_per_request` and `redis_commands_per_request` in `results.json`); the recipe's virtual key now carries TPM and tokens-per-day for every preset, so in-memory and Redis presets run the same code path. The first S1r run found that a capped key in Redis mode admitted one request at a time (`docs/operations/FAILURE-MODES.md` R19) — fixed the same day, see Fixed. Additive telemetry surface (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule).

## Changed

- One Go toolchain: `gateway/go.mod` and `gateway/compat/go.mod` declare `go 1.27.3` (`go 1.27.2` when the toolchains were unified on 2026-10-15; see Security), the version `gateway/Dockerfile`'s builder (`golang:1.27.3-alpine`) uses, so the `-race` suite, `golangci-lint`, CodeQL, `govulncheck` and the release binaries now run on the Go minor the container image ships (before, they ran on `go 1.26.9`). Every workflow's `actions/setup-go` step reads the version from `gateway/go.mod` (`go-version-file`, as `release.yml` already did) instead of a literal; `TestOneGoToolchain` (`gateway/cmd/gateway`) fails on every push, and `scripts/release-preflight.sh` check 7 at the tag, when the two `go.mod` files and the Dockerfile tag differ or a workflow pins a literal again. Not public surface (`docs/VERSIONING.md` § 2): the Go field of `-version` and the `build_info` log moves from `go1.26.9` to `go1.27.3` for the release packages (the `gateway/v0.20.0` image said `go1.27.2`); request handling is unchanged: Go 1.27 enables `GOEXPERIMENT=jsonv2` by default, so `encoding/json` is now implemented on `encoding/json/v2` with the v1 option set (duplicate members, invalid UTF-8 and case-insensitive field matching are accepted as before, per the package doc; only decoder error wording may differ) — the implementation the container image has shipped since `gateway/v0.13.0` (the first release whose image built on a Go 1.27 tag, `golang:1.27.1-alpine`) and that the `-race` suite now runs on too, while `gateway/v0.20.0` and earlier packages used the classic implementation. The `go` directive also moves the binaries to Go 1.27's `GODEBUG` defaults: `tracebacklabels` (a no-op here, the gateway sets no goroutine labels) and, for the darwin and windows packages only, `x509sslcertoverrideplatform` (`crypto/x509` honours `SSL_CERT_FILE`/`SSL_CERT_DIR` instead of the platform store); the linux packages and the image are unaffected.
- `POST /v1/chat/completions` and `POST /v1/embeddings` run the Anthropic ingress's body check before decoding: a member that appears twice in one object, nesting beyond 64 levels or invalid UTF-8 is now `400` `invalid_json` (`invalid request body: the body has a duplicate member "model"`, `/messages/0 has a duplicate member "content"`, `nests deeper than 64 levels`, `not valid UTF-8`) before any pipeline work, as `/v1/messages` has done since `gateway/v0.19.0` (`/v1/messages/count_tokens` reaches the same check only through an `anthropic` deployment's parse, after authentication). Before, `encoding/json` kept the last duplicate silently, put U+FFFD where the UTF-8 was invalid and nested up to its own 10,000-level limit; `tools[].function.parameters` and `response_format.json_schema.schema` are raw sub-documents the `openai` adapter re-emits as received (the `anthropic` adapter re-encodes them through `map[string]any`, collapsing the duplicate and substituting U+FFFD), so a duplicate or invalid UTF-8 inside them was never refused before, and is refused with the rest of the body now. No new code or status — `invalid_json` was declared on both routes — and a syntax error met by the pre-decode walk is now reported as the parser's bounded description rather than the decoder's own text (a body truncated between tokens is still named by the decoder, one cut inside a string, literal or number by the walk as `unexpected EOF`; `docs/reference/error-codes.md`). The walk no longer parses number literals (`UseNumber`), so an out-of-range literal such as `1e999` is the typed decoder's business on every route — accepted in an ignored member, refused with the decoder's message in a typed one — where `/v1/messages` had answered `invalid_json` `expected float64` for it anywhere in the body. `anthropicmsgs.CheckBody` and `BodyError` are exported for the purpose; the `/v1/messages` messages are otherwise unchanged. `docs/reference/error-codes.md`'s `invalid_request` row no longer lists duplicate members and deep nesting, which that route has always answered with `invalid_json`.
- Redis mode makes three fewer round trips per billable request (round-5 Tier C item 10, phase 2a; `docs/operations/BENCHMARKS.md`'s third 2026-10-16 record): the budget reserve script reports the spend the decision was made against, so the decision event's `budget_spent_usd` no longer needs its own `HGET` (every key), and the settlement script reports the spend after the settlement, so the warn-threshold and alert-ladder checks no longer re-read it (capped keys) — 9.0 → 8.0 uncapped, 11.0 → 8.0 capped below its warn and ladder thresholds (at or above them each billable request adds the one-round-trip mark scripts, as before). `budget.Tracker.ReserveWithSpend` and `Reconcile`'s returns carry the values; `budget.RedisBackend.Reserve` and `Adjust` report them (an internal interface, not public surface). A lost settlement (FAILURE-MODES R7) now also skips both threshold checks for that request and logs `budget_threshold_checks_skipped`. `budget_spent_usd` keeps its meaning, the spend before this request's own cost, now read in the same lock or script as the decision.
- The pre-call rate-limit checks are one Redis round trip and the two token settlements another (round-5 Tier C item 10, phase 2b; `docs/operations/BENCHMARKS.md`'s 2026-10-17 record): one gate script evaluates RPM, TPM and tokens-per-day in that order and reserves nothing unless all three admit (the RPM hash's refreshed state is still persisted on every call), so a refused request consumes no RPM token and leaves no reservation (until now a TPM or tokens-per-day refusal had consumed the RPM token, and a tokens-per-day refusal spent a fourth round trip releasing the TPM reservation), and one script settles both token dimensions after the call — 8.0 → 5.0 round trips per billable request on a key with all three dimensions. Two consequences: a Redis error fails the whole gate open at once — one `ratelimit_backend_unavailable` line, one `kelvran.ratelimit.fail_open` increment, nothing reserved — where the three checks failed open each on their own (`ratelimit_tpm_backend_unavailable` / `ratelimit_tpd_backend_unavailable` remain for the mid-stream top-ups); and in memory the refused request's RPM token is refunded, so both modes agree on what a refused request consumes. `ratelimit.KeyLimiter.Admit` / `SettleTokens` and the `ratelimit.RedisBackend` methods `Admit` / `SettleTokens` carry it (internal); the Redis keys, value shapes and TTLs are unchanged, so replicas on the previous release interoperate.
- With `rate_limit.redis_addr` and `budget.redis_addr` on the same Redis (same address, username, resolved password and TLS setting), the rate limiter, the budget and the spend ledger run over ONE go-redis client and connection pool instead of three (round-5 Tier C item 10, phase 2c-1; the groundwork for fusing their scripts into one round trip before the upstream call and one after it). The request path is unchanged: a billable request still costs 5.0 Redis round trips. Two visible effects: `kelvran.redis.store` reads `shared` instead of `ratelimit`, `budget` and `ledger` for those commands (the label values on separate clients are unchanged), and the three stores' connections now compete in one pool. Two spellings of one host (`127.0.0.1:6379` and `localhost:6379`) do not match and keep a client per store. Internally the Redis-backed stores gain `NewOn` constructors over a client somebody else owns, and the rate limiter, the budget tracker and the ledger expose the request builders and result mappers their Redis paths use (`KeyLimiter.PlanAdmit`/`PlanSettle` and `ratelimit.MapAdmission`, `budget.PlanReserve`/`MapReservation`/`PlanReconcile`, `redisledger.Store.PlanRecord`), none of it public surface.

## Fixed

- A capped virtual key in Redis budget mode (`budget_usd` with `budget.redis_addr`) no longer admits one in-flight request at a time (FAILURE-MODES R19, found 2026-10-16 by the first Redis-mode benchmark run: 15.7 % of requests refused `429 insufficient_quota` at 100 rps on one gateway, 84.3 % with two replicas against a 50 ms mock; present from `gateway/v0.14.0`, the release that shipped `budget.redis_addr`, through `v0.20.0`). The reserve script took the whole remaining headroom on every call because Redis mode kept no billing history. It now keeps a `billed_count` on the key's window hash — counted by the settlement script when the settlement carried a real cost, expired with the window — and reserves the window's mean billed cost (`spent / billed_count`, an integer nano-USD, clamped to the remaining headroom) once that count is positive; a window with no billed settlement yet still reserves the full headroom, the in-memory tracker's rule and the TOCTOU RFC's cold start. The mean counts the siblings' in-flight reservations, as in memory (FAILURE-MODES, known gaps). Replicas on the previous release interoperate but keep the old behaviour until upgraded. Not public surface: the Redis key layout is not among the covered items in `docs/VERSIONING.md` § 2. The benchmark recipe's key carries `budget_usd` again, so S1r measures the capped path.
- A mid-stream TPM top-up whose Redis call errored no longer skips the same chunk's budget (and tokens-per-day) top-up: the TPM branch of `checkMidStreamReservationTopup` fell through to `return true` on a backend error, leaving the other dimensions under-reserved for that chunk; it now falls through to them like the day branch does. The fail-open log line and `kelvran.ratelimit.fail_open` increment stay once per stream.

## Security

- Go toolchain `1.27.2` to `1.27.3` (`gateway/go.mod`, `gateway/compat/go.mod`, the digest-pinned builder `golang:1.27.3-alpine`): `govulncheck` reported GO-2026-6809 ("Distrust compromised intermediate certificates in `crypto/x509`", fixed in Go 1.27.3) reachable in the gateway through the upstream HTTP client's `x509.Certificate.Verify`. The `gateway/v0.18.0` through `gateway/v0.20.0` images were built with 1.27.2; earlier images and the release packages (Go 1.26.9 for `gateway/v0.20.0` and earlier) were not assessed against this advisory.
