## Added

- `GET /admin/debug/pprof/goroutineleak`: Go 1.27's goroutine-leak profile joins the admin pprof set (`admin.enable_pprof`, Admin tier, the 60 s `seconds` cap — the thirteenth pprof route, 34 admin patterns over 29 paths). Each collection forces a leak-detecting garbage-collection cycle (two with `seconds`, whatever its value) and collections serialize on a package-level mutex in `runtime/pprof`, so it costs more than the six other named profiles; the cap and the write timeout bound the connection, not the GC work (`docs/reference/admin-api.md`, THREAT_MODEL's Denial of Service row). Additive on the OpenAPI document — a new path item and operation `pprofGoroutineleak` (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule). `TestPprofGoroutineleakProfileIsServed` asks for the profile itself, because `pprof.Handler` answers 404 `Unknown profile` for a name the running toolchain lacks while every route-table test stays green — the route is real only on the `go 1.27.2` toolchain this release line builds with.
- An OpenAPI breaking gate: `scripts/openapi-breaking.sh` runs oasdiff v1.33.0 `breaking --fail-on ERR` on `gateway/openapi/kelvran-gateway.openapi.yaml` against the document shipped at the newest `gateway/v*` tag, in CI's `proto` job on every push and pull request and in `release.yml`'s `build` job at the tag (against the previous release). `gateway/openapi/oasdiff-severity.txt` raises the `docs/VERSIONING.md` § 2 surfaces oasdiff rates INFO or WARN by default (a non-success status, an operationId, an optional response header, a response enum value, an optional response property, a request parameter or a request member removed; a security requirement added), and `gateway/openapi/oasdiff-err-ignore.txt` waives a sanctioned MINOR break — it must be empty otherwise (`TestOpenAPIBreakingGateWaiverIsEmptyUnlessABreakIsInFlight` on every push, preflight check 8 at the tag) and its lines leave in the post-tag follow-up commit (RELEASE.md gateway step 7). The contract tests pin the document to the code; this pins it to the previous release, so a route removed from both no longer passes unnoticed. Not public surface (CI and release tooling). The first base is `gateway/v0.20.0`, the first release to carry the document; against an older base the gate reports nothing to compare. oasdiff has no rule for the `x-kelvran-*` members (its extension-aware rules read only `x-extensible-enum`, `x-stability-level`, `x-sunset` and `x-since-date`), so those stay pinned to the code only (`docs/reference/openapi.md`). The base is always a release tag (`gateway/vX.Y.Z`; a pre-release is never a base), the script refuses a `.oasdiff.*` config file or `$OASDIFF_CONFIG` that would reconfigure the tool behind its flags, and release.yml runs it without an argument so a rebuild of an older tag compares against that tag's own predecessor.
- `virtual_keys.<name>.rate_limit.tokens_per_day`: a tokens-per-day dimension per virtual key (round-5 Tier S item 24; OWASP LLM06:2026's tokens-per-day limit) on the existing TPM reservation path — a third bucket of that capacity refilling at `tokens_per_day/86400` tokens per second, a rolling 24-hour allowance rather than a midnight reset, checked after RPM and TPM (`ratelimit.KeyLimiter.ReserveTPD`/`IncreaseReservationTPD`/`ReconcileTPD`; in Redis mode the same GCRA scripts under their own NUL-tagged key beside the TPM one, with their own 24 h usage history). A day bucket with no usage history reserves at most one hour's share of the day (`tokens_per_day/24`), or the same request's minute reservation when that is smaller, so one request never claims the whole day; a refusal returns the minute reservation at once and is the same `429` `rate_limit_exceeded`, with `Retry-After` floored on the bucket's own wait until a typical request fits again (whole seconds, capped at 24 h; the 1-30 s per-key backoff still applies when larger, and alone for a refusal decided before the key has usage history — the first time the limiter's own wait reaches a client), and the message `dataplane: rate limit exceeded (tokens_per_day)`; like TPM it counts chat and messages turns only (embeddings and `count_tokens` draw RPM alone; cache hits release their reservation); a backend error fails open like the other dimensions, counted once per request (`ratelimit_tpd_backend_unavailable`, also with `op=mid_stream_topup`). A single scalar, 0 or absent for none; negative or non-numeric fails startup; key-level only — under `per_model` or on a deployment it is a load error, not a silent no-op. Carried by the admin upsert body (`rate_limit.tokens_per_day`, `400` when negative), the propagation payload and `kelvran keys` offline diff; like TPM, not restored for an admin-mutated key after a restart and not echoed by `GET /admin/virtual_keys`. Additive config and admin-body surface (`docs/VERSIONING.md` § 2 for the surface, § 3 for the additive rule); the OpenAPI document gains the `RateLimitRequest.tokens_per_day` member and the chat and messages `429` descriptions name the dimension. `docs/reference/config.md`, `admin-api.md`, `error-codes.md`, `glossary.md`, `metrics-and-logs.md`, `docs/how-to/virtual-keys-and-budgets.md`, `docs/operations/TELEMETRY.md`, `FAILURE-MODES.md`, THREAT_MODEL's LLM06 row. Proven by `TestHandleChatCompletionRejectsOnceTheDayBucketIsExhaustedWithTheDayWait`, `TestHandleChatCompletionDayRejectionReleasesTheMinuteReservation`, `TestIntegrationMessagesTokensPerDayRejectionCarriesTheDayWait` and, against a real Redis shared by two instances, `TestIntegrationTwoGatewayInstancesShareOneRedisTokensPerDay`.

## Changed

- One Go toolchain: `gateway/go.mod` and `gateway/compat/go.mod` declare `go 1.27.2`, the version `gateway/Dockerfile`'s builder (`golang:1.27.2-alpine`) has used since 2026-10-09, so the `-race` suite, `golangci-lint`, CodeQL, `govulncheck` and the release binaries now run on the Go minor the container image ships (before, they ran on `go 1.26.9`). Every workflow's `actions/setup-go` step reads the version from `gateway/go.mod` (`go-version-file`, as `release.yml` already did) instead of a literal; `TestOneGoToolchain` (`gateway/cmd/gateway`) fails on every push, and `scripts/release-preflight.sh` check 7 at the tag, when the two `go.mod` files and the Dockerfile tag differ or a workflow pins a literal again. Not public surface (`docs/VERSIONING.md` § 2): the Go field of `-version` and the `build_info` log moves from `go1.26.9` to `go1.27.2` for the release packages (the image already said `go1.27.2`); request handling is unchanged: Go 1.27 enables `GOEXPERIMENT=jsonv2` by default, so `encoding/json` is now implemented on `encoding/json/v2` with the v1 option set (duplicate members, invalid UTF-8 and case-insensitive field matching are accepted as before, per the package doc; only decoder error wording may differ) — the implementation the container image has shipped since `gateway/v0.13.0` (the first release whose image built on a Go 1.27 tag, `golang:1.27.1-alpine`) and that the `-race` suite now runs on too, while `gateway/v0.20.0` and earlier packages used the classic implementation. The `go` directive also moves the binaries to Go 1.27's `GODEBUG` defaults: `tracebacklabels` (a no-op here, the gateway sets no goroutine labels) and, for the darwin and windows packages only, `x509sslcertoverrideplatform` (`crypto/x509` honours `SSL_CERT_FILE`/`SSL_CERT_DIR` instead of the platform store); the linux packages and the image are unaffected.
- `POST /v1/chat/completions` and `POST /v1/embeddings` run the Anthropic ingress's body check before decoding: a member that appears twice in one object, nesting beyond 64 levels or invalid UTF-8 is now `400` `invalid_json` (`invalid request body: the body has a duplicate member "model"`, `/messages/0 has a duplicate member "content"`, `nests deeper than 64 levels`, `not valid UTF-8`) before any pipeline work, as `/v1/messages` has done since `gateway/v0.19.0` (`/v1/messages/count_tokens` reaches the same check only through an `anthropic` deployment's parse, after authentication). Before, `encoding/json` kept the last duplicate silently, put U+FFFD where the UTF-8 was invalid and nested up to its own 10,000-level limit; `tools[].function.parameters` and `response_format.json_schema.schema` are raw sub-documents the `openai` adapter re-emits as received (the `anthropic` adapter re-encodes them through `map[string]any`, collapsing the duplicate and substituting U+FFFD), so a duplicate or invalid UTF-8 inside them was never refused before, and is refused with the rest of the body now. No new code or status — `invalid_json` was declared on both routes — and a syntax error met by the pre-decode walk is now reported as the parser's bounded description rather than the decoder's own text (a body truncated between tokens is still named by the decoder, one cut inside a string, literal or number by the walk as `unexpected EOF`; `docs/reference/error-codes.md`). The walk no longer parses number literals (`UseNumber`), so an out-of-range literal such as `1e999` is the typed decoder's business on every route — accepted in an ignored member, refused with the decoder's message in a typed one — where `/v1/messages` had answered `invalid_json` `expected float64` for it anywhere in the body. `anthropicmsgs.CheckBody` and `BodyError` are exported for the purpose; the `/v1/messages` messages are otherwise unchanged. `docs/reference/error-codes.md`'s `invalid_request` row no longer lists duplicate members and deep nesting, which that route has always answered with `invalid_json`.

## Fixed

- A mid-stream TPM top-up whose Redis call errored no longer skips the same chunk's budget (and tokens-per-day) top-up: the TPM branch of `checkMidStreamReservationTopup` fell through to `return true` on a backend error, leaving the other dimensions under-reserved for that chunk; it now falls through to them like the day branch does.
