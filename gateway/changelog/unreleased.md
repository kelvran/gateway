# Unreleased

Entries accumulate here under the six [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories until the next `gateway` release. At release time this file's content is moved into a new dated `<version>.md` file (e.g. `0.1.0.md`) in this same folder, and this file is reset to empty category headers.

Versioning: [SemVer](https://semver.org/) — load-bearing for the Go module path/tag (`v0.1.0`, `v0.2.0`, ...).

- Initial code skeleton per `docs/plans/2026-09-02-initial-code-scaffolding.md`: canonical request/response types; real OpenAI and Anthropic provider adapters with round-trip tests; stubbed Gemini/Bedrock/OpenAI-compat adapters (typed "not implemented" errors); the `cache.Cache` interface with a working in-process L1 exact-match implementation and dormant `grpcserver`/`grpcclient` extraction seams; a single static virtual-key auth check (constant-time comparison); an in-memory token-bucket rate limiter; a non-streaming dataplane pipeline wiring auth → rate-limit → cache → routing (round-robin + single fallback) → adapter → cost accounting → structured JSON logging; a stdlib-only YAML config loader; a multi-stage Dockerfile. Streaming, distributed rate limiting, Decimal-precision cost accounting, MCP/A2A, and guardrails are explicitly deferred — see `docs/rfcs/2026-09-02-initial-code-scaffolding.md`.
- Test/lint infrastructure: a real end-to-end HTTP integration test suite (`cmd/gateway/integration_test.go`) driving the full pipeline through a real `httptest` server and client against a mock upstream; byte-for-field regression fixtures (`internal/adapter/{openai,anthropic}/testdata/`) pinning both adapters' wire formats independently of the existing round-trip unit tests; `go test -fuzz` targets for the cache-key fabricator and the hand-rolled YAML config parser; `go test -bench` baselines for the in-process cache and the token-bucket rate limiter; and a tuned `.golangci.yml` (v2 schema: errcheck, govet, staticcheck, unused, ineffassign, errorlint, gofmt/goimports) with zero outstanding findings.
- Real SSE streaming (`stream: true`) for `/v1/chat/completions`, per `docs/rfcs/2026-09-02-streaming-support.md`: a new provider-agnostic `internal/streaming` package (canonical `ChatCompletionChunk` types, an SSE `Reader`/`Writer`, and the `StreamDecoder`/`StreamingAdapter` interfaces); real stateful `StreamDecoder`s for the OpenAI (near-passthrough, multi-chunk tool-call argument accumulation) and Anthropic (typed event sequence — `message_start`/`content_block_start`/`content_block_delta`/`content_block_stop`/`message_delta`/`message_stop` — with per-block-index state tracking) adapters; dataplane wiring for both the cache-hit path (a complete cached response is synthesized into a fake stream) and the cache-miss path (a real upstream stream is simultaneously written to the client and accumulated back into a canonical `ChatResponse` for cache write-back and cost accounting); the existing pre-first-byte fallback rule now applies to streaming too. Gemini/Bedrock/openaicompat remain unsupported for streaming — a request to one of them returns a typed `ErrStreamingNotSupported` (HTTP 400), never a silent fallback to buffering. Test coverage brought to full parity with the initial scaffolding's own bar across every category: 8 real end-to-end HTTP integration tests (both providers, cache-hit, unsupported-provider), unit tests for every new component, a `go test -fuzz` target (`FuzzReaderNeverPanics`) on the SSE reader parsing untrusted upstream bytes (20s local run, 580K+ execs, no crash found), `go test -bench` baselines for the reader/writer hot path, and byte-exact golden tests pinning the outbound SSE wire format — plus a clean `go test ./... -race` across the whole module.
- Real multi-tenant virtual keys with per-key budgets, per-key rate limits, and optional per-key allowed-model lists, per `docs/rfcs/2026-09-02-virtual-keys-budgets.md`: `identity.VirtualKey` (hash-matched, O(1) lookup by the presented token's own SHA-256 digest — never a raw secret in config), a new `internal/budget.Tracker` (in-memory cumulative-spend tracking against an optional USD cap), and one `ratelimit.TokenBucket` per configured key (replacing the single global bucket). Requests are checked in order: allowed-models → per-key rate limit → per-key budget → cache lookup. 12 new/updated tests across `internal/identity`, `internal/budget`, `internal/cache`, `internal/gateway/dataplane`, and 3 new real end-to-end HTTP integration tests (model-not-allowed → 403, budget-exceeded → 429 distinguishable from rate-limit by message, and the load-bearing cross-tenant cache-isolation proof).
- Real OTel tracing for every dataplane request (buffered and streaming), per `docs/rfcs/2026-09-02-otel-tracing-agent-run-id.md`: a new `internal/telemetry` package (the gateway's first external Go dependency — `go.opentelemetry.io/otel` + SDK + stdout/OTLP exporters) starts one span per request carrying GenAI semantic-convention attributes (`gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`/`id`/`finish_reasons`, `gen_ai.usage.{input,output}_tokens`) plus Kelvran-custom attributes (`kelvran.virtual_key.id`, `kelvran.cache.hit`, `kelvran.cost.usd`, `kelvran.deployment.name`) and, the headline feature, `kelvran.agent_run_id` — propagated in from the caller via the standard W3C `baggage` HTTP header, never fabricated when absent. New `telemetry:` config section (`exporter: "stdout" | "otlp" | "none"`, default `"stdout"`). Never adds prompt/completion content to a span — no opt-in mechanism for that exists in this pass at all. `api/otel/`'s versioned cross-language contract remains deliberately deferred; this ships the gateway-emits-spans half only.
- Decimal-precision cost/budget arithmetic, per `docs/rfcs/2026-09-02-decimal-cost-accounting.md`: `internal/costaccounting.ModelPrice`/`Calculate`, `internal/budget.Tracker`'s cumulative spend, and `identity.VirtualKey.BudgetUSD` all switched from `float64` to `github.com/shopspring/decimal` (the gateway's second external Go dependency; zero transitive dependencies). The hand-rolled YAML config parser (`controlplane.parseYAMLScalar`) no longer eagerly converts numeric scalars to `float64` before any caller sees them — money values now parse directly from their original decimal source text via a new `getDecimal` helper, never round-tripped through binary floating point first. `cost_usd` in structured JSON logs and the `kelvran.cost.usd` OTel span attribute are now exact decimal strings, not `float64`/JSON numbers — a deliberate, documented format change.
- Restart-durable budget-spend persistence, per `docs/rfcs/2026-09-03-budget-persistence.md`: a new `internal/budget/boltstore` package (the gateway's third external Go dependency, `go.etcd.io/bbolt` — near-zero *new* transitive weight, its one real dependency is already pulled in via OTel) backs `budget.Tracker` when a new `budget.persist_path` config field is set. Spend is persisted synchronously on every `Record` call (no async-flush data-loss window) and stored as the exact decimal string, never a numeric encoding. Single-instance only — a deliberate, bounded stepping stone ahead of the already-planned Postgres control-plane store, not a replacement for it. `dataplane.Pipeline` gains a `Close` method; `cmd/gateway`'s `run()` now defers it. Behavior is unchanged (pure in-memory, resets on restart) when `persist_path` is omitted.
- Distributed (Redis-backed) rate limiting, per `docs/rfcs/2026-09-03-distributed-rate-limiting.md`: a new `internal/ratelimit.KeyLimiter` sits above the existing per-key `TokenBucket`, backed by either in-memory buckets (default, unchanged) or a new `internal/ratelimit/redislimiter` package (the gateway's fourth external Go dependency, `github.com/redis/go-redis/v9`) when a new `rate_limit.redis_addr` config field is set. The Redis backend runs the exact same continuous-refill token-bucket math atomically via a single Lua script (EVALSHA, with go-redis's built-in EVAL fallback) so a virtual key's burst cap is enforced correctly across any number of gateway instances, not just per-process. A Redis backend error fails open (logged as `ratelimit_backend_unavailable`, request allowed) rather than rejecting — `internal/budget.Tracker`'s independent per-key USD cap is what makes that safe to default to. `dataplane.Pipeline` gains a `checkRateLimit` helper implementing this policy at both the buffered and streaming call sites; `Config.VirtualKeys` was removed (no longer needed — `Config.Limiter` is now a pre-built dependency, exactly like `Config.Budget`).

## Fixed

- A real, latent config-parsing bug, found while researching the Decimal-precision pass above: the YAML parser's boolean detection used `strconv.ParseBool`, which also accepts `"0"`/`"1"` as valid booleans — a config line like `budget_usd: 1` (intending a $1.00 cap) would silently parse as the boolean `true`, fail the numeric-field type switch, and fall back to a zero value, which `internal/budget.Tracker`'s own convention treats as **unlimited**. A one-digit budget cap could silently disable the cap entirely. Fixed by matching only the literal words `true`/`false` (with common casing), not `strconv.ParseBool`'s full permissive grammar.

## Security

- Closed a latent cross-tenant cache-leakage gap in the same pass that introduced multi-tenancy: `cache.Key()` gained a leading `tenantID` parameter (see the Added entry above), so two different virtual keys asking a byte-for-byte identical question can never collide on the same cache entry — the exact attack class (KeyPooling) `THREAT_MODEL.md`'s Cache STRIDE table already named. Never shipped exploitable, since only one implicit tenant existed before this pass.
