# gateway v0.15.0 — 2026-09-23

Entries below are frozen as of this release — see `unreleased.md` for anything added since. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories; [SemVer](https://semver.org/) — load-bearing for the Go module path/tag.

## Added

- `ToolDef.Strict` is now forwarded to OpenAI/openaicompat's native per-function `strict` field, and to Bedrock Converse's real `toolSpec.strict` field (live-confirmed against 3 independent AWS primary sources) -- previously silently dropped on all three.
- `AllowedSourceCIDRs` on virtual keys: an opt-in source-IP allowlist enforced once at request-auth resolution, resolved from the real TCP peer only, never a client-supplied header by default.
- Deployment `base_url` must now be `https` unless a deployment explicitly sets `allow_insecure_http` -- closes a gap where a self-hosted backend could silently be pointed at a plaintext endpoint.
- Optional per-deployment TLS transport (custom CA / client certificate) for self-hosted backends behind mTLS or an internal CA.
- A rolling-window finish-reason/fallback-rate anomaly detector (`internal/anomaly`), wired to signals `GatewayDecisionEvent` already carries today.
- Staged/canary rollout for `configpropagation` mutations: an optional `CanaryPercent` field, folded into the existing HMAC signature, with deterministic per-instance cohort assignment.
- Latency-aware soft de-weighting for self-hosted backends: the router now applies a soft, multiplicative de-weighting factor derived from real probe-call latency -- never a hard exclusion, so a slow-but-healthy deployment still receives some traffic.
- A durable, queryable audit trail (`internal/admin/auditstore`, `GET /admin/audit`) -- the previously write-only `slog`-based admin audit log now also persists to an append-only JSONL file with real filtering by action/field/time-range, governed by the same `EnableAuditLog` switch.
- `BudgetWarnPercent`'s threshold-crossing now also delivers a real webhook via the existing `alerting.Notifier` mechanism, deduped to at most once per rolling-window epoch per virtual key, in its own Redis key namespace independent of the sibling alert-ladder mechanism. The existing log-only line is unchanged and still re-fires on every over-threshold request.

## Security

- Opt-in, per-virtual-key end-user response-cache scoping (`CacheScopeToEndUser`, via a new caller-supplied `X-Kelvran-End-User-Id` header) -- closes the highest-severity finding in this round's own research: a cross-tenant response-cache leakage vector (2026 research cites an 86% cross-tenant cache-hit attack rate against comparable gateways). Fails closed (never shared-cached) when enabled but the header is absent. Default off -- no existing tenant's cache economics change without an explicit opt-in.
