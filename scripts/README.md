# Dev Scripts

Index of the dev scripts this project uses. As of the test-expansion pass (see `docs/agents/LOGS.md`), all `Makefile` targets below are real and run against real toolchains (`golangci-lint` v2.14.0 — the version `.github/workflows/ci.yml` pins since 2026-10-14; `ruff`, which neither `ci.yml` (`uvx ruff`) nor the `Makefile` pins to a version); `lint`/`test`/`verify` map onto `.github/workflows/ci.yml`'s jobs, and `bench`/`bench-ci` onto `.github/workflows/bench-nightly.yml` (same `scripts/bench-ci.sh`). **Corrected 2026-10-08**: the promise this file made when the targets were placeholders ("`make verify` will run exactly what CI runs, in the same order") was never exactly kept — at that pass CI already ran `go test ./... -race` and `make verify` did not (the original `make verify` row disclosed it) — and CI has since added more steps with no local equivalent; see the `make verify` row below and `AGENTS.md`'s Testing section (**Corrected 2026-09-14**).

| Script | `Makefile` target | Status | Notes |
|---|---|---|---|
| Bootstrap both toolchains | `make setup` | **Real** | `go mod download` (gateway) + `uv sync` (evals) |
| Lint `gateway/` + `evals/` + `api/` | `make lint` (or `lint-gateway`/`lint-evals` individually) | **Real** | `go vet` + `golangci-lint run ./...` (config `gateway/.golangci.yml`) + `go-arch-lint`; `ruff check .` + `ruff format --check .` (config `evals/pyproject.toml`'s `[tool.ruff]`) + `lint-imports`; `buf lint` + `buf breaking` via `lint-proto` (see below) |
| Run all tests | `make test` (or `test-gateway`/`test-evals` individually) | **Real** | `go build ./... && go test ./...`; `uv run pytest tests/` — includes unit, integration, regression/golden, fuzz, and property-based (Hypothesis) tests. Docker-requiring sandbox integration tests are skip-by-default (`RUN_DOCKER_TESTS=1` to opt in), per `docs/testing/TESTING.md`. The SDK compatibility matrix (`gateway/compat/`, its own Go module, CI job `compat`) is outside `make test`: `cd gateway/compat && go test ./...` builds the gateway from the tree and runs the official OpenAI and Anthropic SDKs against it. |
| Release preflight (`scripts/release-preflight.sh <gateway\|evals> <version>`) | — | **Real** (2026-10-08) | Checks the dated changelog file exists, `unreleased.md` is empty, every `**BREAKING**` entry has an `UPGRADE.md` row, (evals) `pyproject.toml` matches, (gateway) `gateway/openapi/kelvran-gateway.openapi.yaml` exists with `info.version` equal to the release (a warning until 2026-10-12), and (gateway, added 2026-10-15) the Go toolchain is declared once (`gateway/go.mod`, `gateway/compat/go.mod` and the Dockerfile's `golang:` tag agree, no `toolchain` directive, no workflow pins a literal `go-version`, every `setup-go` step reads `gateway/go.mod`), and (gateway, added 2026-10-15) the OpenAPI breaking-gate waiver `gateway/openapi/oasdiff-err-ignore.txt` is empty unless the dated changelog has a `**BREAKING**` entry; warns when `docs/VERSIONING.md`'s support-window table does not name the release; `release.yml`/`release-evals.yml` run it at the tag before building. |
| OpenAPI breaking gate (`scripts/openapi-breaking.sh [base-ref]`) | — | **Real** (2026-10-15) | oasdiff v1.33.0 `breaking --fail-on ERR` of `gateway/openapi/kelvran-gateway.openapi.yaml` against the document at the newest `gateway/v*` tag that does not contain `HEAD` (or the given ref), with `gateway/openapi/oasdiff-severity.txt` raising the `docs/VERSIONING.md` § 2 surfaces oasdiff rates INFO or WARN by default and `gateway/openapi/oasdiff-err-ignore.txt` waiving a sanctioned break. Installs the pinned tool with `go install` (network; not part of `make verify`). CI's `proto` job runs it on every push and pull request, `release.yml`'s `build` job at the tag against the previous release. A base older than `gateway/v0.20.0` has no document and reports nothing to compare. |
| Benchmarks (`scripts/bench-ci.sh`) | `make bench` (quick local trend: 30 s windows, 5 s warm-up, 100 rps — the shape the nightly workflow runs), `make bench-ci` (the presets' full windows — the shape any published number must use) | **Real** (2026-10-08) | Builds `gateway` and `kelvran-bench`, starts the mock upstream and one gateway per scenario with a generated config and a random virtual key in a 0600 file, runs S1a S1b S2 S3 by default (`BENCH_SCENARIOS` for others), writes `bench-out/{results.json,bench.json,summary.md}`; `BENCH_REDIS_ADDR` adds S1r (one gateway in Redis mode, S1a's twin) and S4 (two replicas); only their gateways use Redis and are scraped for the Redis round-trip counters (since 2026-10-16); `BENCH_BASELINE=1` also runs each scenario straight at the mock. Methodology: `docs/operations/BENCHMARKS.md` |
| Local CI-equivalent | `make verify` | **Real** (**Corrected 2026-10-08**: no longer exactly matches CI) | `lint` + `test` + `check-proto` (`Makefile`), covering `gateway/`, `evals/` and `api/`. CI (`.github/workflows/ci.yml`) runs the same checks per-deployable in parallel jobs, plus steps `make verify` does not run — the eight `AGENTS.md`'s Testing section lists (**Corrected 2026-09-14**: `go test -race`, `govulncheck`/`pip-audit`, `mypy`, the two evals corpus-threshold gates and the two coverage gates), the evals test step's own `--cov-fail-under=93` flag (`ci.yml`, also 2026-09-14 but not in that list of eight; `make test-evals` runs `pytest` with no coverage flags) and, added 2026-10-08 (after `gateway/v0.17.0`), `scripts/check_versions.py` (also run by `scripts/release-preflight.sh`) and the `docs-links` job (`lychee` + `scripts/check-doc-paths.sh`) and, added 2026-10-11, the `compat` job (`cd gateway/compat && go test ./...`) and, added 2026-10-15, `scripts/openapi-breaking.sh` in the `proto` job (the row above); run `cd gateway && go test ./... -race`, or the step's own command from `ci.yml`, directly if you want any of them before pushing. |

**Real since 2026-09-03:** `buf breaking` — `api/gatewayevents/v1/gatewayevents.proto` has been a committed contract since that date (`bc4bd649`; see `api/README.md`), and `buf breaking` is wired exactly where this line once promised: `make lint-proto` (`cd api && buf lint && buf breaking --against '../.git#branch=main,subdir=api'`, `Makefile`) runs as part of `make lint` and therefore `make verify`, and CI's `proto` job (`api (buf lint, breaking, generated-code drift check)` in `.github/workflows/ci.yml`) runs `make lint-proto` and `make check-proto` on every pull request to and push on `main`.

**Not scripted at all, deliberately:** release/publish steps (`RELEASE.md` documents these as a manual runbook — automating them is a reasonable future step, but not before the runbook itself has been executed by hand at least once, so the steps are proven before they're encoded).
