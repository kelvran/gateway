# evals v0.10.0 — 2026-09-21

Entries below are frozen as of this release — see `unreleased.md` for anything added since. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories; [SemVer](https://semver.org/) by default.

## Added

- `--llm-judge-provider {bedrock,anthropic,openai}` on both `run` and `rollout`, defaulting to `bedrock` (zero behavior change when unset) — `make_anthropic_call_model`/`make_openai_call_model` had been fully implemented and unit-tested since this project's first judge-provider RFC, but the CLI only ever wired the Bedrock factory. `--llm-judge-panel` stays Bedrock-only; mixing providers in a panel needs its own per-panelist selector syntax, out of scope here.
- `pass_at_k`, `bootstrap_paired_pvalue`, and `beta_binomial_prob_a_beats_b` in `evals.stats` — the unbiased Chen et al. 2021 pass@k estimator, a correctly re-centered paired-bootstrap significance test, and a Beta-Binomial Monte Carlo model comparison, all implemented against the stdlib only (no numpy/scipy). Pure functions with full test coverage; CLI/report-surface wiring is a separate, later decision.
- `evals.online.sampler` — per-event sampling (`should_sample`, seedable) and rule-based filtering (`RuleFilter`/`passes_rule_filters`, mirroring `auto_flag.FlagRule`'s shape), wired into `evals ingest` via three new, additive flags (`--sample-rate`/`--sample-seed`/`--filter-rules`). Scoped down from the original online-eval-service design once `GatewayDecisionEvent`'s own lack of prompt/completion content made LLM-judge scoring against it impossible to build honestly — that half stays explicitly deferred and disclosed rather than faked.
- `finish_reason` on `GatewayDecisionEvent` (additive, non-breaking `api/` change shared with `gateway`).

## Fixed

- `evals ingest --source s3://...` / `evals cost-report --source s3://...` raised `NoRegionError` in a clean environment (e.g. CI) when only `AWS_REGION` was set, since the pinned `botocore` only honors `AWS_DEFAULT_REGION` for a bare `boto3.client(region_name=None)` call — the identical bug class a much earlier fix already closed for the Bedrock judge client specifically, now closed the same way (`AWS_REGION` then `AWS_DEFAULT_REGION` fallback) for the S3 object-store client too.
- `evals ingest`'s "runs" persistence call ran unconditionally even when `--results` was never given, printing a spurious `warning: failed to persist runs` line on the single most common `evals ingest --source ... --out ...` invocation shape.
- `run_in_sandbox`'s `TimeoutError`/cancellation cleanup could itself fail (a vanished `docker` binary, a transient `OSError` reading the cidfile) and silently replace the real timeout/cancellation signal the caller was unwinding with; the success path had the identical exposure for its own incidental cidfile read, turning an otherwise-complete, successful command run into a raised exception.
