## Fixed

- `parse_judge_response` matched the leftmost `VERDICT: PASS|FAIL` line instead of the final one — the judge prompt template's own instructions literally contain that phrase, so REASONING text discussing or quoting it could silently flip a real FAIL to a recorded PASS.
- Every single-judge call site (`run`, `rollout`) hardcoded `Score.scorer_id` — and the cache key derived from it — to the Bedrock model id regardless of `--llm-judge-provider`, falsely claiming Bedrock produced a verdict that anthropic/openai actually produced, and silently reusing a prior provider's cached verdict across a `--use-score-cache` run under a different provider.
- `botocore` (imported directly by `evals.judge.providers`) was declared only as a transitive dependency of `boto3`, not explicitly — now pinned in step with `boto3` (`>=1.35.0`), the same floor the two already ship in lockstep under.
