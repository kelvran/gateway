# evals v0.9.0 — 2026-09-19

Entries below are frozen as of this release — see `unreleased.md` for anything added since. [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) categories; [SemVer](https://semver.org/) by default.

## Added

- `evals trend alert`: static threshold+window checking over persisted `TrendSnapshot` history, with optional JSON output and a webhook notification hook. Wired into the nightly judge-accuracy workflow (which previously never accumulated any trend history for it to check).
- `evals cost-report --agent-run-id <id>`: a durable, cross-request answer to "why did this agent run cost $X," summing both real spend and cache savings for one agent run from ingested `GatewayDecisionEvent` history.
- `Score.judge_prompt_version`: every real `--llm-judge`/`--llm-judge-panel` score is now stamped with the judge-prompt version that produced it, so a later prompt change no longer silently invalidates comparability against historical scores. A `--use-score-cache` hit replays the original stored version rather than the current one — the entire point of tagging it at all.
- Judge-panel quorum-tie rate is now persisted as its own `TrendSnapshot` series (`judge_panel_tie_rate`), alongside the existing quote-grounding-rate and cost series `report`'s panel path already tracked.
- `--notify-webhook` deliveries are now signed (Standard Webhooks-shaped envelope, HMAC-SHA256, `whsec_`-prefixed secret via a new `--notify-webhook-secret` option) and retried with bounded exponential backoff on a transient failure — previously a single unsigned, no-retry request.

## Changed

- `report`/`trend show`/`trend alert` now disclose harness configuration on their output: a distinct line per `rubric_axis` when `--judge-axes` is used (previously silently pooled into one blended, misleading pass rate), and the judge/panel `scorer_id` on the main line. The existing blended line is unchanged for every non-multi-axis workflow.
- `trend alert`'s triggered output now carries a real Wilson confidence interval alongside its window rate, matching `report --fail-under`'s own existing disclosure — never a bare percentage.
- `run`/`ingest` now always attempt to persist whatever succeeded so far, even when a later case/key fails partway through, or when the persistence attempt itself fails (mirroring `rollout`/`audit-corpus`'s own existing behavior). One disclosed side effect: `--scores`/`--suite`/`--results` may now exist as an empty or partial file in a scenario where they previously wouldn't have been created at all.

## Removed

- A false `"disjoint_model_family_panel"` audit claim, previously attached unconditionally to every judge-panel `Score` even though the one real shipped panel (`--llm-judge-panel`) is same-vendor (two Bedrock Claude models) — removed rather than left misleading; `"independent_refutation"` stays, since the panel genuinely does perform independent refutation regardless of vendor composition.

## Fixed

- `quote_is_grounded` false-negatived when a judge wrapped its own verbatim quote in quote marks the prompt template never asked for, making the measured grounding rate an artifact of judge formatting habits rather than judge behavior.
- Bedrock judge/panel calls ignored `Converse`'s own `stopReason`, silently returning a `max_tokens`-truncated partial response instead of a clear error naming the real cause; all 6 judge/panel call sites also omitted `max_tokens` entirely, exposing them to the model spending its whole default token budget on internal reasoning before ever emitting visible text.
- `trend alert --window` accepted a non-positive integer with no validation, silently reinterpreted via Python's own negative-slice semantics as the exact opposite of the documented intent.
- `run_in_sandbox` only killed the sandboxed Docker container on a timeout; a Ctrl-C (`asyncio.CancelledError`) left an already-created container running unbounded.
- `audit-corpus` and `rollout` both discarded every already-computed finding/result on an operator's Ctrl-C mid-batch — the existing `except Exception` guard around each case cannot catch `KeyboardInterrupt`/`SystemExit`, both `BaseException`.
- 5 already-decoded `GatewayDecisionEvent` fields (`occurred_at`, `rate_limit_fail_open`, `fallback_happened`, `fallback_from_deployment`, `budget_spent_usd`) were silently discarded during ingestion instead of persisted onto the mapped `EvalCase`/`Run`.
- `run`/`ingest` lost every already-computed result on a later case/key's failure, and the fix for that could itself mask the real triggering error (or block an unrelated sibling persistence call) if the persistence attempt inside its own `finally` block failed — both closed with a shared `_try_persist` helper applied consistently across all four commands that share this pattern (`run`, `ingest`, `rollout`, `audit-corpus`).
- The `--notify-webhook` sender retried a permanent 4xx response identically to a transient failure, burning its full retry budget on a request that could never succeed, and silently signed with a malformed `whsec_` secret instead of failing loudly.

## Security

- Sandboxed command execution now applies CPU (1 core), memory (512MB, with `--memory-swap` matched to close the swap loophole), and process-count (128 pids) ceilings — previously unbounded, letting a single sandboxed command exhaust host resources.
- Enabled ruff's native bandit ruleset (`S`) and triaged all 20 findings individually rather than blanket-suppressing: 3 real production-code call sites reviewed and disclosed as benign (an operator-supplied webhook URL, an internal OTel SDK invariant assertion, a `git` subprocess call with internally-constructed arguments), the rest a genuine test-only false-positive class.
